## Public service and route contract

Add a small backend/services/bootcamp/sprintAccess.mjs for positive-safe-integer normalization, trusted actor validation and Sprint ownership lookup. Normalize numeric IDs and trimmed decimal digit strings; reject zero, negative, unsafe, fractional, NaN, Infinity, junk suffix, exponential and object/array input before query/job lookup. Retain valid normalized integer IDs across route/service/model comparisons. The actor is {userId, role}, with normalized positive userId and exact admin/trainer role. It comes from authenticated req.user only, never req.body or generated metadata.

Every callable public service in sprintService.mjs accepts and validates that actor: createSprint(actor, params), getSprintById(id, actor), listSprints(actor), updateSprint(id, actor, updates), archiveSprint(id, actor), updateWeek(sprintId, weekId, actor, updates), updateSlot(sprintId, slotId, actor, updates), confirmSlotUsed(sprintId, slotId, actor, body), getSprintExerciseMemoryKeys(sprintId, actor). Update the verified internal create -> get call. List remains scoped to the actor's own trainer identity under current behavior; do not add an unsolicited all-trainers admin listing. Object lookup permits explicit authenticated admin override and otherwise scopes by owner. Missing/foreign objects use the existing non-disclosing not-found outcome; bad actor/role is forbidden. Child week/slot queries must additionally include the authorized Sprint ID. No exported trusted-internal bypass or omitted-actor fallback.

Generator signatures become generateSprintClasses(sprintId, actor, onProgress) and regenerateSlot(sprintId, slotId, actor). Authorize before claim/update, profile/catalog access or memory read. Authorize previousSprintId under the same actor before reading its exclusions. For an admin operating an owned trainer Sprint, generation uses the Sprint's stored trainerId as data owner and the explicit requester role where profile policy needs it; never replace ownership with the admin's ID. Handle string-vs-number slot comparisons through the common normalizer.

All sprintRoutes.mjs callers pass an actor constructed solely from req.user. POST generation and GET reconnect must authorize the Sprint before reading sprintJobs, creating a job, flushing SSE headers, replaying events, or generation dispatch. Invalid IDs fail before any job/cache/model lookup. Route errors preserve the sanitized public envelope; do not echo ORM/provider exception messages. Access denial is an ordinary JSON error before SSE setup. Rate-limiter placement can stay consistent with existing policy.

No migration or provider activation is needed. The in-memory job map remains only progress storage at this stage; it is not authority and this slice does not claim distributed concurrency protection. Existing job cleanup/duplicate terminal behavior will be repaired with the durable claim/stream contract. Existing confirmation remains non-idempotent until the taught-log slice; record that boundary explicitly.
