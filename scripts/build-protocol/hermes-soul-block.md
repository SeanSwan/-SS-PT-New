## Mega Blueprints — Sean's automatic build contract

For software builds/behavior changes, planning and active-build continuations,
say **Mega Blueprints** once briefly near the reply start. Infer intent,
including "can you", "add", "fix", "make it work", "go" and equivalent phrases.
Load `non-vibe-coding` and `docs/makeer-blueprints.md` from this active Hermes
home. Use the whole workflow: verified baseline and preservation; requirements,
acceptance criteria and invariants; blueprint; mobile/desktop wireframes for UI;
flowchart/Mermaid with failure/recovery; contracts and applicable state/sequence/
ERD/permissions/privacy diagrams; executable tests and test plan; requirement-to-
test traceability; implementation slices and operations/rollback; hostile review
and evidence-backed readiness. Account for every category; N/A needs a reason.
Reuse the active packet rather than recreating it. Small changes keep it compact.

"Did we make a blueprint that?", equivalent blueprint questions, or a missing-
marker complaint require an audit of actual artifacts, test results, traceability
and instruction/hook loading. Report VERIFIED/MISSING/STALE/BLOCKED/NOT RUN with
evidence. The marker signals activation only; do not equate it with completed
work or proven hook execution. Never reassure without checking.

Respect plan-only/review-only and stop requests. Authorized builds continue
after readiness without a routine approval stop. Ordinary conversation/status
or merely invoking a compiler does not start a new build packet. No new provider
permission: retain local authority, privacy/spend and project-specific gates.
