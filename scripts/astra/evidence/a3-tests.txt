===============================================================================

`reject` IS in MUTATION_ROUTES, so the gate at server.mjs:146 runs BEFORE the handler.

would be a silent CSRF hole; these two were measured against each other, not assumed.

6. THE DEFECT THIS SLICE FOUND AND FIXED — T-M-03
===============================================================================
T-M-03: a compile record missing `lawChecks` must render as PARTIAL, and must NEVER
render as "0 checks passed".

BEFORE the fix, renderThink always emitted its count heading, so an empty `lawChecks`
rendered the literal text "0 run, 0 passed" — a finding the data cannot support. Zero
passes and five unrun checks are different findings, and only one is a problem with
the compile.

The fix is in the RENDERER (surface/panes.mjs), not the test: a count is a CLAIM ABOUT
COMPLETENESS, so it is only made when the record can support it. Measured across four
cases:

  partial + empty lawChecks   | LAW CHECKS  counts withheld — this record is PARTIAL
                              | contains "0 passed": false
  partial + 3 checks          | LAW CHECKS  counts withheld — this record is PARTIAL
                              | contains "0 passed": false
  complete + 2 checks         | LAW CHECKS  2 run, 2 passed
                              | contains "0 passed": false
  lawChecks never reported    | LAW CHECKS  not reported in this record
                              | contains "0 passed": false

The complete case still shows its real count, so the fix DISTINGUISHES rather than
blanket-suppressing. The fourth case is new: a record that never reported `lawChecks`
now states that fact in place of the table, because an empty <tbody> renders as
nothing and reads as "all clear".

THE RUNNER WAS THEN MUTATION-TESTED, because a check that cannot fail is not a check.

The two failures were exactly the two token-gate checks — `POST /api/compile (NO token)`
and `(WRONG token)`. server.mjs was then restored and verified BYTE-IDENTICAL to the
backup (`cmp` clean), and the runner returned to 26/26.

THE RUNNER'S OWN FIRST RUN FAILED 5 OF 24, AND THREE OF THOSE WERE ITS OWN BUGS:

 1. The overflow scan matched the stylesheet's own COMMENT reading "NO `overflow-x:
    hidden` ANYWHERE". The scan read a declaration as the thing declared — the D11/D20
    class, fourth appearance in this engagement. Fixed by stripping comments first.
 2. The traversal check used `fetch`, which normalises `..` away before the request is
    sent — so it tested the URL PARSER, not the server. The existing a3-surface test
    already documents this and uses a raw socket; the smoke runner now does too.
 3. The token sentinel was `undefined` for "no token", which was also the "not
    specified" value, so the check labelled "NO token" actually SENT a valid token and
    passed a 200. Now `'none'` is explicit.

The other two were a wrong expectation (`lawChecks` live on the `view`, not top-level)
and a correct behaviour tested with a bad id (`E_COMPILE_UNKNOWN` on an unknown compile).
