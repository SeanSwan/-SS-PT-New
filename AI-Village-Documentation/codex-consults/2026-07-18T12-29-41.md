## FINDING [HIGH]: `useCrystallizeTransition` can leave transition attrs/styles stuck if a flushed in-flight commit throws

**Evidence:** `frontend/src/adapters/style-lens-swan/motion/useCrystallizeTransition.ts:151-155`

```ts
if (pending.current && !pending.current.done) {
  clearTimers();
  runPending();
  clearHtmlAttrs();
}
```

**Why this is a bug:**  
[VERIFIED] `runPending()` marks `done = true` and then calls `p.commit()` at lines 116-121. If that commit throws during the busy-call flush path, `clearHtmlAttrs()` at line 154 is skipped. The old `data-lens-transition`, `data-lens-transition-variant`, and `--lens-crystallize-*` inline properties can remain on `<html>` indefinitely.

**Concrete reproduction:**

1. Use `useCrystallizeTransition` with an animated variant (`fade` or `sweep`).
2. Call `crystallizeTo(() => { throw new Error('boom'); })`.
3. Before `chargeMs` elapses, call `crystallizeTo(() => {})` again.
4. The second call enters the flush block at lines 151-155.
5. `runPending()` throws.
6. `clearHtmlAttrs()` is never reached.
7. Inspect `<html>`: transition attrs/styles can remain stuck.

**Impact:**  
[LIKELY] Any CSS keyed off `[data-lens-transition]` can remain active after the failed transition. This is not a live blocker until Lane A wires crystallize, but it is not safe “ready-to-wire” code.

**Fix direction:** wrap the flush in `try/finally`:

```ts
if (pending.current && !pending.current.done) {
  clearTimers();
  try {
    runPending();
  } finally {
    clearHtmlAttrs();
  }
}
```

Then decide whether the new commit should proceed or the old error should propagate.

**Impact:**  
[VERIFIED] The documented desk/lap root-scale portion of the sweep choreography is dead code. Not a live blocker unless Slice 2 is wired.

**Fix direction:**


## FINDING [MEDIUM]: `usePrefersReducedMotionFailClosed` crashes on MediaQueryList implementations without `addEventListener`

**Evidence:** `frontend/src/adapters/style-lens-swan/motion/useCrystallizeTransition.ts:64-65`

```ts
mql.addEventListener('change', onChange);
return () => mql.removeEventListener('change', onChange);
```

**Why this is a bug:**  
[LIKELY] Some browsers/test environments expose `MediaQueryList#addListener/removeListener` but not `addEventListener/removeEventListener`. This hook treats missing `matchMedia` as fail-closed, but does not treat missing MQL event APIs as fail-closed. It will throw `TypeError: mql.addEventListener is not a function`.

**Concrete reproduction:**

1. In a browser/test shim, define:

```ts
window.matchMedia = () => ({
  matches: false,
  addListener: () => {},
  removeListener: () => {},
}) as any;
```

2. Mount a component using `useCrystallizeTransition`.
3. The effect reaches line 64 and throws.

**Impact:**  
[LIKELY] This can crash the appearance settings surface once Slice 2 is wired in an environment with legacy MQL APIs.

**Fix direction:**

```ts
if (typeof mql.addEventListener === 'function') {
  mql.addEventListener('change', onChange);
  return () => mql.removeEventListener('change', onChange);
}
if (typeof mql.addListener === 'function') {
  mql.addListener(onChange);
  return () => mql.removeListener(onChange);
}
setReduced(true);
```
