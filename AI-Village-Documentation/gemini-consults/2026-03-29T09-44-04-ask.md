### PART 2: BACKEND SERVICES (Node.js / Express)

We will refactor the existing `GamificationEngine` into a modular service architecture.

**1. The Compulsion Loop Engine (`RewardService.ts`)**
This handles the *Cue -> Action -> Variable Reward -> Investment* loop.
*   **Action:** User logs a workout.
*   **Variable Reward:** RNG calculation based on workout intensity (NASM RPE) and current `SimsNeeds` state. High needs + High RPE = higher chance of "Pearlescent/Crystalline" loot drops.
*   **Investment:** User equips the dropped `CyberwareAugment` to boost tomorrow's XP yield.

**2. Needs Decay Cron (`NeedsService.ts`)**
Runs at 00:00 UTC. Subtracts points from `SimsNeeds` based on the user's logged data (or lack thereof). If Mobility drops below 30, the "Tamagotchi Companion" (Aegis Sprite) visually degrades (loses its `Ice Wing` #60C0F0 glow).

**3. Ghost Mode Streamer (`GhostService.ts`)**
When a user starts a workout, this service fetches their best `GhostRun` for that template and feeds it to the frontend via WebSockets or lightweight polling to drive the Gran Turismo UI.
