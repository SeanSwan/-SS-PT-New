### 1. Design Gaps (What You Missed)

*   **AI State Visualization:** You mentioned a "waveform visualizer," but AI interaction has four distinct states: *Idle, Listening, Processing (Thinking), and Responding*. Each requires a distinct visual signature so the trainer doesn't have to guess what the system is doing.
*   **Responsive Drawer Mechanics:** A "persistent drawer on the right" works on 1440px, but fails on 375px. We need a specific spatial strategy across our 10 breakpoints. How does it push content vs. overlay content?
*   **Typography & Markdown Styling:** AI outputs structured text (lists, bolding, tables). Default browser markdown rendering will break our Galaxy-Swan theme. We need custom styled-components for the AI's markdown output.
*   **Accessibility (a11y) & Focus Trapping:** When the drawer opens, focus must be trapped inside it for screen readers. The dictation mode needs `aria-live="polite"` to announce state changes without interrupting the trainer's flow.

---

### 2. Enhancement Opportunities (Elevating the UX)

*   **The "Swan Intelligence" Aura:** Instead of a standard chat interface, the AI should feel alive. When "Swan AI" is processing or speaking, the edges of the drawer or the FAB should pulse with a fluid, animated gradient of Swan Cyan (`#00FFFF`) and Cosmic Purple (`#7851A9`). Think Apple Intelligence's glowing screen edges, but localized to our components.
*   **Morphing FAB (Floating Action Button):** On mobile, the FAB shouldn't just be a static mic. When tapped, it should physically morph (using Framer Motion) from a 64x64px circle into a pill-shaped waveform visualizer at the bottom of the screen, anchoring the dictation experience.
*   **Premium Glassmorphism:** The drawer cannot be a solid color. It must use a deep, frosted glass effect over the `Galaxy Core` background, allowing the underlying dashboard charts and data to blur beautifully beneath it.
*   **Haptic Feedback:** For mobile (PWA), we must trigger `navigator.vibrate()` on dictation start/stop to give the trainer physical confirmation without needing to look at their screen during a session.

---

### 3. Architecture Recommendations

*   **Animation Engine:** We will use **Framer Motion** exclusively for the drawer, FAB morphing, and waveform animations. CSS transitions are too stiff. We need physics-based spring animations to achieve the Peloton/Apple Fitness+ level of polish.
*   **Styled-Components Pattern:** Use transient props (e.g., `$isOpen`, `$isRecording`) to prevent React from leaking styling props into the DOM. 
*   **Z-Index Scale:** We need a strict z-index token system to prevent the drawer from colliding with existing modals or tooltips.
    *   `z-index: 100` (Header/Nav)
    *   `z-index: 200` (Floating Action Buttons)
    *   `z-index: 300` (AI Drawer Backdrop)
    *   `z-index: 301` (AI Drawer Surface)
