### Highest Severity Finding (P1 - Potential UI Flicker)

*   **File:** `frontend/src/adapters/style-lens-swan/styles/activeLensStyles.tsx`
*   **Failure Scenario:** The keyed `<Fragment>` in `ActiveLensGlobalStyles` correctly triggers a remount when the set of active lenses changes. However, it remounts *everything* inside it, including `LensCoreGlobalStyles`. The core styles contain the critical `--console-*` skin for the Aurora Console.
    *   **Concrete Example:** A user has `aurora-console` as their active lens. They open a UI (like a style explorer) that renders a preview of the `quiet-meridian` lens inside a `ScopedLensFrame`.
    1.  `useStyleLensIds` now detects both `['aurora-console', 'quiet-meridian']`.
    2.  The `<Fragment>` key changes from `'aurora-console'` to `'aurora-console|quiet-meridian'`.
    3.  React unmounts the old fragment's children. For a frame, `styled-components` removes the `<style>` tags for both `AuroraConsoleLensStyles` and, critically, `LensCoreGlobalStyles` from the document head.
    4.  React mounts the new fragment's children, and `styled-components` re-injects the style tags for `AuroraConsoleLensStyles`, `QuietMeridianLensStyles`, and `LensCoreGlobalStyles`.
    *   **The Bug:** In the split-second between steps 3 and 4, the `--console-*` CSS variables defined in `lensCoreStyles.ts` are absent from the DOM. Any on-screen component consuming these variables will lose its skin, causing a visible flicker or re-layout. This compromises the "luxury vault" stability of our UI. The cascade order logic is sound, but the lifecycle of the core styles is not.
*   **Required Change:** The core styles must be permanent and stable, not subject to the dynamic remounting of the active lens set. Decouple `LensCoreGlobalStyles` from the keyed fragment.

    **Implementation:**
    Modify the `ActiveLensGlobalStyles` component to render the core styles unconditionally outside the fragment.

    ```typescript
    // In: frontend/src/adapters/style-lens-swan/styles/activeLensStyles.tsx
    
    export function ActiveLensGlobalStyles(): ReactElement {
      const ids = useStyleLensIds();
      const known = selectActiveLensIds(ids);
      if (process.env.NODE_ENV !== 'production') warnOncePerUnknownId(ids, known);
      
      return (
        <>
          {/* Core styles are now permanent, never unmounted on lens change. */}
          <LensCoreGlobalStyles />
    
          {/* This fragment now ONLY manages the dynamic, per-lens style components. */}
          <Fragment key={known.length ? known.join('|') : 'core-only'}>
            {known.map((id) => {
              const LensStyles = LENS_STYLE_ALLOWLIST[id];
              return <LensStyles key={id} />;
            })}
          </Fragment>
        </>
      );
    }
    ```
    This change ensures the core styles (including the console skin) are injected once and remain stable, while still allowing the per-lens styles to be dynamically managed. The cascade order is also preserved, as `styled-components` will still inject the dynamic lens styles *after* the core styles in the DOM head if they are rendered later in the tree, but the specificity of the lens selectors will ensure they win. *Correction:* `styled-components` injects based on render order. With this change, core will be injected first, then the dynamic lenses. This is the correct order for lens-specific rules to override core defaults.
