### 1. Design Gaps in the Current Plan

*   **The "Infinite Cylinder" Desktop Scaling Problem:** A vertical 3D cylinder rolodex is a brilliant mobile-first paradigm (mimicking a tactile combination lock). However, stretching this across a 1440px or 2560px display will result in massive, distorted touch targets and wasted negative space. We need a layout shift at the 1024px breakpoint.
*   **Visual Disambiguation of Groupings:** The plan mentions supersets, tri-sets, circuits, pyramids, and drop sets. If these all use the same visual bracket, cognitive load will skyrocket. We lack a tokenized visual language to instantly differentiate a Drop Set (intensity/fatigue) from a Circuit (endurance/pacing).
*   **Drag-and-Drop Ghosting:** `dnd-kit` defaults can feel clunky. The plan doesn't specify the visual state of the "drag overlay" (the item being held) versus the "drop target" (where it will land).
*   **Accessibility (a11y) in 3D Space:** A virtualized Framer Motion wheel is inherently hostile to screen readers. We are missing a hidden, standard `<select>` or `aria-live` region that announces the currently snapped exercise.
