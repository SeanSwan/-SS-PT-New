### TOPIC 1: ADMIN DASHBOARD THEME UNIFICATION
**The Problem:** Hardcoded static themes in a styled-components `ThemeProvider` create a walled garden, breaking our CSS custom property architecture.

**The Strategy: The "Variable Bridge" Migration (All-at-Once Layout, Phased Components)**
Do *not* do this component-by-component, or we will have a Frankenstein UI where half the dashboard shifts themes and the other half stays dark. We must do a **Top-Down Variable Mapping**.

1. **Retire `executiveCommandTheme` Hexes:** Instead of passing static hexes, update the `executiveCommandTheme` object to pass our global CSS variables. This instantly connects the legacy components to the `UniversalThemeContext` without rewriting every single styled-component file immediately.
2. **The Default Aesthetic:** To maintain the dark executive feel as the default, the `UniversalThemeContext` must initialize with the Crystalline Swan dark tokens for Admin roles.

**Implementation Directive:**
```typescript
// Legacy approach (BAD):
// const executiveCommandTheme = { bg: '#0A0A0F', card: '#141419' }

// New Bridge approach (GOOD):
const executiveCommandTheme = {
  bg: 'var(--bg-base, #0A0A0F)', // Fallback to Obsidian Black
  card: 'var(--surface-dark, #141419)', // Fallback to Carbon
  elevated: 'var(--surface-elevated, #1A1A24)', // Fallback to Graphite
  textPrimary: 'var(--text-primary, #E0ECF4)', // Frost White
  accent: 'var(--accent-primary, #002060)', // Midnight Sapphire
  glow: 'var(--accent-glow, #8B5CF6)' // Wing Purple
};
```

**Visual Risks & Mitigation:**
The biggest risk is **Contrast Collapse** when switching to a light theme (e.g., if a user selects a "Daylight" theme, white text on a suddenly white background).
*Fix:* Ensure your CSS custom properties define both `--text-primary` and `--text-inverse`. Any component using `Carbon` (`#141419`) as a hardcoded background *must* use `--text-inverse` if the global theme shifts to light, OR we strictly enforce that Admin themes are variations of Dark Mode only (which I strongly recommend for the "Command Center" aesthetic).

### TOPIC 2: AI PAYWALL FOR NON-PAID MEMBERS
**The Architecture: Dual-Layered (Frontend Glass + Backend Gate)**
A frontend-only gate is unacceptable for a premium SaaS. Tech-savvy users will bypass it via DevTools.
1. **Backend:** Express middleware (`verifyPremiumTier`) that checks the PostgreSQL subscription status. If free, return `403 Forbidden` with a specific payload: `{ error: 'upgrade_required', feature: 'ai_terminal' }`.
2. **Frontend UX Pattern: The "Interactive Teaser"**
Do not hide the AI Terminal. Visibility drives conversion. Use the **Strava/Hevy Pattern**: Show the interface, let them see the value, but blur the results.

**UX Flow:**
1. The free user sees the AI Terminal Panel. The chat history area is populated with 2-3 "dummy" placeholder insights (e.g., *"Analyzing your squat depth..."*).
2. Over this history area, apply a heavy glassmorphic overlay.
3. The user *can* type a prompt into the input field. When they hit "Send", the input clears, and the Paywall Modal triggers.

### TOPIC 3: WORKOUT LOGGER UX IMPROVEMENTS
To compete with Strong and Hevy, our Workout Logger must eliminate cognitive load during a workout. Sweaty hands and fatigue mean we need massive touch targets and zero-friction data entry.

**The Top 3 Highest-Impact Improvements:**

#### 1. "Ghost" Data (Inline Previous Workout Comparison)
*Why:* Users shouldn't have to click away to see what they lifted last week.
*UX:* Inside the Reps and Weight input fields, display the previous session's numbers as placeholder text.
*Design:* Use `Frost White (#E0ECF4)` at `30% opacity`. Font: `Fira Code` (Monospace aligns numbers perfectly).
```css
.ghost-placeholder {
  color: rgba(224, 236, 244, 0.3);
  font-family: 'Fira Code', monospace;
}
```

#### 2. Visual Superset/Circuit Grouping
*Why:* Hevy does this brilliantly. A visual bracket linking exercises prevents confusion during complex circuits.
*UX:* A left-aligned neon bracket connecting the grouped exercises.
*Design:* Use `Ice Wing (#60C0F0)` for the bracket line.
```css
.superset-bracket {
  position: absolute;
  left: -12px;
  top: 20px;
  bottom: 20px;
  width: 8px;
  border-left: 2px solid #60C0F0;
  border-top: 2px solid #60C0F0;
  border-bottom: 2px solid #60C0F0;
  border-radius: 4px 0 0 4px;
  box-shadow: -2px 0 8px rgba(96, 192, 240, 0.2);
}
```

#### 3. Global Picture-in-Picture (PiP) Rest Timer
*Why:* Users navigate away from the logger to check their history or change a song. If the timer is trapped in the logger component, it's useless.
*UX:* When a set is marked "Complete" (checked), automatically start the rest timer. The timer must live in a global React Context and render as a floating pill at the bottom center of the screen (above the mobile nav bar).
*Design:*
- Background: `Graphite (#1A1A24)`
- Border: 1px solid `Midnight Sapphire (#002060)`
- Font: `Fira Code` for the countdown.
- Tap to expand into a modal to add/subtract 30 seconds. Minimum touch target: `44px` height.
