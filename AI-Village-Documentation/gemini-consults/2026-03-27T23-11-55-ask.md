### 1. SSE Endpoint Architecture: New Route vs. Accept Header
**CTO Decision:** Create a **NEW** route (`/api/ai-chat/stream`). 

**Engineering & UX Justification:**
Do not overload the existing endpoint via an `Accept` header. SSE (`text/event-stream`) requires fundamentally different Express middleware, connection lifecycle management (handling client disconnects, keeping connections alive), and response formatting (`res.write()` vs `res.json()`). 

*Crucial CTO Warning on Streaming JSON:* Since we are forcing the AI to output a structured JSON schema (which includes the chat response *and* the report card), streaming it means the client will receive **partial JSON chunks**. 
*   **The Fix:** On the frontend, we must implement a partial JSON parser (or use a library like `partial-json`) to extract the `chatMessage` string as it streams to create the typing effect, while waiting for the stream to close before rendering the NASM Report Card UI.

### 3. Persistence Strategy: The `TrainerEvaluations` Table
**CTO Decision:** Create a **NEW** PostgreSQL table. Do *not* bury this in conversation metadata.

**Why?** Data visualization and gamification. In Q3, we will build a "Trainer Mastery Dashboard" using **Arctic Cyan #50A0F0** line charts to show a trainer's NASM adherence improving over time. We cannot efficiently query JSON blobs across thousands of messages to build a time-series chart.

**Schema Definition (`TrainerEvaluations`):**
*   `id` (UUID, Primary Key)
*   `trainerId` (UUID, Foreign Key)
*   `sessionId` (UUID, Foreign Key)
*   `messageId` (UUID, Foreign Key - links to the specific AI response)
*   `totalScore` (Int)
*   `tempoScore`, `repScore`, `exerciseScore`, `warmupScore`, `safetyScore` (Int)
*   `rawFeedback` (JSONB - stores the praise, corrections, and safety arrays)
*   `createdAt` (Timestamp)
