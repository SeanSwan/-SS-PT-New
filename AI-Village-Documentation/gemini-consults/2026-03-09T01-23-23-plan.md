### 1. Design Gaps

You have outlined a great technical foundation, but you are missing critical UX and architectural considerations:

*   **Cognitive & Visual Overload:** Point earns happen frequently (liking a post, finishing a set). If a swan flies across the screen with lasers every time a user taps "Like," it will become an abrasive annoyance within 3 minutes. We need strict visual hierarchy: **Micro-celebrations** (frequent) vs. **Macro-celebrations** (rare).
*   **Accessibility (a11y) & Photosensitivity:** Explosions and flashing lasers are massive WCAG liabilities. We *must* wrap all animations in a `prefers-reduced-motion` check. If true, fallback to elegant opacity fades and disable canvas particles.
*   **Z-Index & Stacking Context:** Full-screen overlays often get trapped inside `overflow: hidden` parent containers or under sticky navbars. The plan lacks a React Portal strategy.
*   **Responsive Canvas Scaling:** WebGL/Canvas particle systems look blurry on Retina/OLED screens if devicePixelRatio isn't calculated. A 3840px ultrawide monitor requires vastly different particle counts than a 375px iPhone to maintain 60fps.
*   **Screen Reader Context:** Visual explosions mean nothing to visually impaired users. We need `aria-live="polite"` for points and `aria-live="assertive"` for level-ups.

### 2. Enhancement Opportunities

To elevate this from a standard gamification system to a **SwanStudios Signature Experience**, we will implement the following:

The swan beats its wings once, emitting a cosmic shockwave (glassmorphic ring), and shatters into stardust.

*   **Premium Typography Masking:** The "slamming" level-up number shouldn't just be a solid color. It should use `background-clip: text` with an animated cosmic gradient flowing through it, giving it a liquid-glass/nebula feel.

### 3. Architecture Recommendations

Do not pollute individual components with complex animation logic. Use this architecture:

*   **Global Celebration Portal:** Create a `<CelebrationProvider>` at the root of the app. Expose a hook: `const { triggerPointEarn, triggerLevelUp } = useCelebration()`. This provider renders a React Portal attached to `document.body` with `z-index: 9999`.
*   **Hybrid Animation Strategy:**
    *   Use **Framer Motion** for DOM elements (the slamming text, the expanding rings, the floating XP numbers). It handles spring physics perfectly.
    *   Use a lightweight **Canvas API** (or `tsparticles` if strictly configured) for the Constellation Swan and stardust. Do *not* render 500 DOM nodes for particles; it will destroy mobile performance.
*   **Audio Sprite System:** Do not load 10 different `.mp3` files. Use `howler.js` to load a single audio sprite sheet. This guarantees zero-latency playback on mobile devices when a user earns a point.
*   **Styled-Components Transient Props:** Use transient props (e.g., `$isLevelingUp`) to conditionally style components without passing DOM attributes that cause React warnings.
