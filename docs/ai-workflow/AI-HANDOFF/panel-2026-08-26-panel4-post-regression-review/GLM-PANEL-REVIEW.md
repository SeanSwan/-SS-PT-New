## HIGHEST RISK
Merging 15 commits whose rewritten billing derivation has **never executed against a real database** into an auto-deploy-to-production pipeline, with no staging, no data-rollback plan, and a *writable* prod connection string sitting in local dev — while the only undo (git revert) cannot reverse any data the new code writes.

Cheapest de-risk, in gate order (each cheap; stop on failure):

- **G0 (10 min):** Create a read-only DB role for local dev, or strip the prod URL from local `.env`. Nobody holds writable prod creds during deploy/rollback. This is the 10-minute version of the next slice, not the slice itself.
- **G1 (5 min):** Prove zero migration files in `git diff main...branch --name-only`; read the Render build command and confirm it runs no migrations. (Blocker 1.)
- **G2 (hours):** **Advisory-only patch**: the derived rate never overrides the operator figure — surfaced, flagged, operator confirms. Small diff, unit-testable, and it deletes the entire wrong-money harm class of blockers 2–4 regardless of how the window/population debates resolve. For a single-trainer business where the owner *is* the operator, this is strictly better UX anyway.
- **G3 (1 hr):** Transactional prod smoke — since dev already resolves to prod, use it deliberately and safely: open a transaction, invoke `getClientPackagePricing` for a sample of real clientIds and the cancel-warning logic against real upcoming sessions, assert payload keys **exactly** match what `useSessionPackagePricing` reads (settles blocker 2), count the `isFallback` rate (if the dual-duration storm from blocker 4 is real, you'll see it here and can decide pre-merge), `ROLLBACK`. Zero writes commit.
- **G4 (30 min):** `pg_dump` prod to off-Render storage. Pre-write the reversing SQL for the new writes — `UPDATE sessions SET "cancellationDecision" = NULL WHERE "updatedAt" >= :deploy_ts AND "cancellationDecision" IS NOT NULL` (adjust columns to reality) — and dry-run it against the dump restored into a *local* container, never against the prod URL.
- **G5 (30 min):** First browser run of the prospect-facing pricing sheet (`vite build && vite preview`, mocked/recorded API): Victory not Recharts, styled-components only, `var(--token,#fallback)` palette, Dual-Button Glow, 44px targets, dark-first, 4.5:1 contrast, ≤300 lines/file, and credential copy is "26+ years / NASM-protocol" — **not** "NASM-certified" — with no "yoga/meditation" language. None of the house rules are verifiable from this brief; this is the gate that checks them.
- **G6:** Merge at low-traffic hour; watch the Render deploy; HTTP smoke: sheet shows real numbers, "$88" copy gone; cancel-warning on one real upcoming session shows the correct window; monitor 5xx on `/api/sessions` for 24h.

**Rollback ladder:** R1 — `git revert <merge commit>`, push `main`, Render redeploys in minutes (measure that duration *now*, not during the fire). R2 — R1 does not undo stamps: run the pre-written, pre-dry-run bounded UPDATE from G4; full-restore from the dump is last resort because it loses post-merge orders, and for this business one lost order is unacceptable. R3 — if G2 shipped, a misbehaving derivation is operator confusion, not wrong money, and can be fixed forward the next morning — which is the entire point of making it advisory.

**Position on deploy-first: yes, after G0–G5.** "$88 may apply" is a daily customer-facing lie and the pricing sheet is the acquisition work the owner says is priority one — waiting for full dev/prod severance trades a known live harm for an unbuilt infrastructure slice. But the gates above are hours, not days, and G0 plus G1 are non-negotiable.
