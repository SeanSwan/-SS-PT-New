## VERDICT

## BLOCKERS
1. **P0 — Telegram inbox may be an unauthenticated remote shell onto prod.** `telegram.allowed_chats: ''` with `platforms.telegram.enabled: true` and `platform_toolsets.telegram` including `swanstudios-operator`, `operator-workflows`, `supervised-browser-actions`, plus `command_allowlist: [execute_code, hermes update…]`, `hooks_auto_accept: true`, `memory.write_approval: false`. If empty means “no allowlist” (common in these agents), any user who can message the bot inherits shell, file I/O, memory persistence, and SwanStudios operator tools. If empty means “deny all,” Telegram is already dead and the primary channel is misconfigured. Either reading is a ship blocker; the config does not say which. Evidence: `telegram.allowed_chats`, `platform_toolsets.telegram`, `command_allowlist`, `mcp_servers.swanstudios-operator.enabled: true`.

2. **P0 — `fallback_providers: []` is not the real cloud boundary.** Every `auxiliary.*` block is `provider: auto` with empty `model`/`base_url`/`api_key` (compression, title_generation, curator, approval, profile_describer, background_review, vision, web_extract, skills_hub, monitor, …). Session titles, compression summaries, memory curation, and approval judgments can leave the box without a slash-command. That is silent cloud routing of medical/immigration/family + prod-credential context, and it violates the binding “zero PII to LLMs (IDs only)” rule. `codex_gpt55_autoraise: true` is a second hidden escalate. Evidence: `auxiliary:` tree; `compression.codex_gpt55_autoraise: true`; `fallback_providers: []`; `privacy.redact_pii: false`.

3. **P0 — Context-starvation 500 is not actually fixed; one trigger was moved.** Default was rebuilt to `qwen3.8-ctx131k:latest` / `num_ctx 131072`, but `local_private.default_model` is still `qwen3.8:27b-mtp-q4_K_M` (the 32k tag), and the catalog still lists `qwen3.8:27b-mtp-q8_0`, `hermes-fast:latest`, `hermes-fast-38:latest` with no measured `num_ctx`. Same inputs as §2.1 on the private lane or any alias → head truncation → user-less array → Qwen template HTTP 500 `no user query found` → `format_error` → poisoned session, every `/continue` dies. Evidence: §2.1 table A–D; `local_private.default_model`; `model.aliases` / `model_aliases`; `compression.threshold: 0.35`.

4. **P0 — No mechanical invariant that a `user` turn survives compression/truncation.** §2.1 explicitly left the template hard-reject in place. `protect_first_n: 3` did **not** save system + original user (“oversized-session truncation removed the head”), so there is a truncation path that ignores the protector. `abort_on_summary_failure: false` lets a bad summary proceed. `gateway_auto_continue_freshness: 3600` then auto-replays the corpse (matches the four dead continues). Evidence: §2.1 “Explicitly NOT fixed”; `compression.protect_first_n: 3`; `compression.abort_on_summary_failure: false`; `agent.gateway_auto_continue_freshness: 3600`.

## ATTACKS
- Correctness: Happy-path `num_ctx` rebuild does not query the *loaded* context; advertised 262144 × 0.35 ≈ 91750 only *happens* to sit under 131072 — swap the brain again and §2.1 repeats (already repeated once in six weeks). `protect_first_n` is either broken or does not apply to oversized-session truncation; the packet never distinguishes those code paths. `local_private.base_url` is `:11434` (native) while `providers.local-ollama.base_url` is `:11434/v1` (`api_mode: chat_completions`) — same host, two dialects; a private-lane call can mis-parse context metadata and retune the threshold against the wrong number. Aliases `fast`/`local`/`qwen`/`quinn` pin `hermes-fast*` with unknown ctx. `delegation.child_timeout_seconds: 0` + `max_concurrent_children: 5` + `inherit_mcp_toolsets: true` = un-reaped children holding MCP (including `swanstudios-operator`). `timezone: ''` + `session_reset.at_hour: 4` = reset at an undefined local hour. `approvals.timeout: 60` with unspecified timeout semantics (deny vs fail-open). `streaming.enabled: false` vs `display.streaming: true` / `display.platforms.telegram.streaming: true` — undefined which wins. ## HIGHEST RISK
Unauthenticated-or-ambiguous Telegram control plane sitting on `swanstudios-operator` + `execute_code` + fail-open Tirith + auto-accept hooks. Cheapest de-risk before anything else: set `telegram.allowed_chats` to the single operator chat id (mechanical, not a habit), disable live dashboard bind or set `basic_auth`, and pin every `auxiliary.*.provider` to `local-ollama` / the local Qwen tag — or `enabled: false` if the field does not support pin. That closes remote drive-by and silent cloud exfil in one config edit; no new service, no session ritual.

Settle with: one-line source/docs for empty allowlist and `auto`; `curl` to Ollama `/api/show` for every tag in `providers.local-ollama.models` printing loaded `num_ctx`; a unit test that compression/truncation **must** emit ≥1 `user` or refuse to send; packet capture or a stub showing whether `title_generation`/`auxiliary.compression` open an outbound TLS connection on a local-only session; `ss`/`netstat` for the dashboard bind. Uncertain settings I did **not** promote to blockers: B5 `execute_code` on the allowlist (reasonable for a one-operator coding agent **after** the Telegram/dashboard gate is real), B8 90-day retention (privacy hygiene, not a page), B10 loop ceiling (partially covered by `gateway_timeout: 1800` and `tool_loop_guardrails`). Durable fix for §2.1 is not another rebuild: on session start, measure loaded ctx and refuse the model if advertised drifts; after every compress/truncate, assert a `user` role or restore the pre-compress snapshot. Turn **off**: `bedrock.discovery`, `codex_gpt55_autoraise`, `allow_lazy_installs`, `trust_recent_files`, `model_catalog` hourly phone-home (or TTL to days), top-level `moa.enabled` until a slash command flips it, live `voice_assistant` capture, and the still-32k `local_private` default.
