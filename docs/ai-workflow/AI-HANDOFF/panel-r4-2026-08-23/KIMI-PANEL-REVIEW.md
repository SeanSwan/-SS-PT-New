## BLOCKERS

1. **P1 — Square-bracket glob classes bypass SHELL_META → phantom MISSING on a healthy hook.** Scenario: settings registers `node scripts/[h]ooks/drift-check-gate.mjs`. The file exists; the shell's `[h]` character-class glob expands to `hooks`; the hook runs fine. But `[` and `]` are not in `SHELL_META` (`/[;&|><\`$(){}*?~!#\n]|\\\s/` — "anything that changes word meaning" definition, snippet ~line 30 of the code block), so the command enters the ASSERT branch, the token ends in `.mjs` (SCRIPT_EXT matches), no whitespace, not a URL → `statSync(join(SS_PT, 'scripts/[h]ooks/…'))` on the *literal* brackets → ENOENT → pushed to `missing` as a file that "DO[es] NOT EXIST". This is a phantom on a healthy registration — the exact failure that, per the header, "trains the operator to ignore the gate, which restores the original outage."

2. **P1 — Blanket `\`→`/` replacement corrupts POSIX-escaped characters → phantom MISSING.** Scenario: `node drift\-check\-gate.mjs`. POSIX unescapes to `drift-check-gate.mjs` (exists). SHELL_META only treats backslash as complex when followed by whitespace (`\\\s`); `\-` passes through. Then in the token loop, `const tok = rawTok.replace(/\\/g, '/')` rewrites the escape to a separator: `drift/-check/-gate.mjs` → ENOENT → false MISSING. The blanket replace is correct for Windows-form registrations and wrong for POSIX-escaped ones, with no discriminator.

3. **P1 — Quoted subcommands still classify as NONE → silent clean, the original outage shape.** Scenario: `sh -c 'node scripts/missing-hook.mjs'` where the file is absent. Quotes are not in SHELL_META, so it goes to the ASSERT branch; tokenize glues the quoted run into one whitespace-bearing token `node scripts/missing-hook.mjs`; it passes SCRIPT_EXT (ends in `.mjs`) but is then dropped by `if (/\s/.test(tok)) continue;` → nothing reported → reads clean. The document's own case matrix lists "NONE: quoted subcommand," and the prose claims "zero phantoms and zero false clean. Both wrong answers are eliminated" — that claim is falsified by the matrix it ships with. A real missing hook can still report clean via `sh -c`, `bash -c`, `eval` strings, `npm run build` indirection, and `node -e`.

4. **P2 — Smaller reporting defects.** (a) In the complex branch, if the unanchored extension test fails the command is silently dropped rather than UNVERIFIED (e.g. `x.mjsx; echo` — `\b` fails after `mjs` inside `mjsx`) — asymmetric with the "complex ⇒ at least UNVERIFIED" story. (b) Complex commands are bounded (`cmd.slice(0, 90)`) but `missing` interpolates full `tok` unbounded — a pathological token bloats the report. (c) `seen` is declared inside the per-file loop, so the same hook in both `settings.json` and `settings.local.json` is reported twice.
