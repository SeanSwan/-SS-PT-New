## BLOCKERS

1. **P1 — `if (/\s/.test(tok)) continue;` silently discards unjudgeable tokens, violating the redesign's own invariant.** Scenario: `node "C:\Program Files\swan\hooks\x.mjs"` (healthy, file present, Windows path with a space — `tokenize`'s quote-gluing correctly produces one space-bearing token) → the guard `continue`s → **zero findings → reads clean, not UNVERIFIED**. Same hole: `sh -c "node scripts/x.mjs"` with `x.mjs` absent — no metacharacters, so it enters the ASSERT branch, the subcommand token is whitespace-skipped, and a genuinely missing hook reports NOTHING. The case matrix line "NONE: quoted subcommand" **codifies the violation** — the design text says "anything else → UNVERIFIED, never tokenised, never 'clean'", and a quoted subcommand is "anything else." The comment on the guard even admits "It is a command, not a path" — then it must be `unresolvable.push(...)`, not `continue`. This is the original outage shape (missing hook → byte-identical to clean) reopened inside the fix, and it's provable from the document.

2. **P1 (conditional) — `join(SS_PT, tok)` assumes SS_PT equals the harness's hook working directory, and absolute paths are asserted against whatever machine runs the gate.** Scenario A: if `SS_PT` is anything other than the CWD hooks execute from (e.g., the gate script's own dir in a monorepo), `scripts/hooks/x.mjs` resolves to `scripts/scripts/hooks/x.mjs` → stat fails → **every relative registration phantoms**, which the doc itself says "trains the operator to ignore the gate, which restores the original outage." Scenario B: `node C:/tools/hooks/x.mjs` committed for Windows targets, gate runs on Linux CI → `statSync('C:/tools/...')` fails → phantom on every non-Windows run. Same for `/opt/...` and the UNC `//host/share` form the code comment explicitly claims to support. Absolute/drive/UNC paths are machine-relative by definition and belong in UNVERIFIED unless the gate knows it's on the target machine. SS_PT's definition is not in the document, so severity is conditional on one fact — see CONFIDENCE.

3. **P2 — `SHELL_META` omits glob brackets `[` `]` (and cmd.exe's `^`): `node scripts/[ab].mjs` contains no listed metacharacter, so it's judged SIMPLE, the literal token `scripts/[ab].mjs` is stat'ed, the file doesn't exist under that literal name → MISSING reported on a healthy glob registration → phantom.** The "zero phantoms" claim is the redesign's entire justification; this breaks it. Evidence: `const SHELL_META = /[;&|><`$(){}*?~!#\n]|\\\s/;` — no `[`, `]`, `^`.

4. **P2 — the code asserts EVERY script-extension token, but the design licenses only `<interpreter> <plain-path> [plain args]`.** Scenario: `node scripts/gen.mjs --emit dist/preview.mjs` (SessionStart generator) — `dist/preview.mjs` is an output that legitimately doesn't exist pre-run, yet it passes `SCRIPT_EXT`, isn't a URL, has no whitespace → asserted → phantom. Design/code drift between the stated contract and the loop.

5. **P2 — complex commands containing no script extension are dropped silently, not marked UNVERIFIED.** The complex branch only emits when the unanchored extension regex matches: `node $HOOKS_HOME/guard` (extensionless, `$` meta) → the `if` fails → `continue` with **no finding** → reads clean. Same class: simple extensionless registrations (`node ./scripts/guard`) are never asserted by `SCRIPT_EXT` at all. Both are false negatives the matrix doesn't cover.

6. **P2 — errno conflation: `try { ok = statSync(abs).isFile(); } catch { ok = false; }` reports EACCES/EIO/EPERM/EROFS as "DO NOT EXIST."** Under a permissions or transient FS fault the finding text makes a false factual claim ("file(s) DO NOT EXIST") that will send an operator hunting for a deletion that never happened. Distinguish `ENOENT`/`ENOTDIR` from everything else.

7. **P2 — `cmd.slice(0, 90)` echoes raw command text into the findings channel.** A hook like `MY_TOKEN=sk-... ; node x.mjs` hits `;` → complex branch → the inline credential is reprinted into whatever surface consumes findings (console/log/report). The round-3 egress fix ("API key length no longer printed") does not cover this channel. Severity depends on where findings land — see CONFIDENCE.

8. **P2 — enumeration scope: only `.claude/settings.json` and `.claude/settings.local.json` under `SS_PT`.** If the harness merges any other layer — user-level `~/.claude/settings.json`, managed/enterprise settings, `--settings` flags — a missing hook registered there is invisible and reads clean.
