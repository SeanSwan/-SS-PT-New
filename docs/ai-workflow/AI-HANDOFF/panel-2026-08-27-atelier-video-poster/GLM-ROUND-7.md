## ATTACKS
- **Correctness:** (a) `{a.kind !== 'image' && <span> · {a.kind}</span>}` — if `kind` is ever `null`/`undefined` (a `MediaAsset` row from a future writer), the guard passes (`null !== 'image'`) and renders a dangling `" · "` separator; low likelihood given exactly two lowercase-literal writers, but the marker's falsy story is only half-thought. (b) `attempted += 1` inside the map is synchronous and correct; counter alignment with `previews[i]` is sound. (c) Mixed page, one purged poster + one genuinely broken signer → `failed === attempted === 2` → banner asserts a single cause for two different failures; the parity heuristic degrades silently as page heterogeneity grows. (d) `reportNoSigner` double-evaluates `previewKeyFor` (some + filter) — pure function, harmless today, worth noting only because the packet's own standard is "the rule exists once."
- **Security:** (a) The presign oracle is *narrowed*, not closed: the restriction lives in `previewKeyFor`, while `generateThumbnailUrl` remains a presign-anything primitive (`r2StorageService.mjs:177`) for every other injection site — capability checks belong at the capability, not at one caller (Blockers 2–3). (b) The ownership predicate checks a *convention* (segment membership) rather than a *fact* (prefix built from row data); conventions are exactly what an attacker with an unvalidated write path gets to violate — the threat model in the packet's own §3 header. (c) Content-spoofing residue: an agent whose planted keys *do* pass (Blocker 2 shape with own-tenant collision) controls what imagery renders in the operator's library — not exfiltration, but trusted-surface injection. (d) Authn/authz on the route itself is settled (Round 2: unconditional `ownerUserId`, `E_BAD_OWNER`); no IDOR introduced by this diff. (e) No rate-limit/DoS delta: ≤25 HMAC signatures per authenticated page.
- **Data-truth / schema drift:** (a) Round 3's settling query assumes snake_case columns (`a.poster_r2_key`, `j.poster_r2_key`) against camelCase model fields — correct only if the Sequelize models are `underscored: true`; that config is never shown, and a wrong assumption makes the *settling query itself* fail. (b) `jobId` exists on the asset row (writer defaults) but `previewKeyFor` reads only `kind`/`r2Key`/`posterR2Key`/`ownerUserId` — the field that would make the guard precise is already in the row and unused: model-vs-reader drift in the predicate's favor. (c) Frontend response-shape drift is genuinely closed (Round 1's backend assertion through real `assetView`, extended Round 3 to the whole view shape) — this is the slice's strongest property. (d) `keyBelongsTo`'s docstring vs. actual writers is documentation drift with security consequence (Blocker 1).

## HIGHEST RISK
Blocker 1+2 taken together: the shipped predicate is anchored to the wrong identifier, which simultaneously keeps the feature inert for real posters and admits foreign objects on ID collision — and its docstring canonizes the wrong convention for every future writer. Cheapest de-risk, no Postgres required: change the acceptance to prefixes built from data already on the row — `atelier/stills/${row.ownerUserId}/` for stills posters/originals, `jobs/${row.jobId}/` for video posters — plus two unit tests (`jobs/<otherJobId>/x` rejected; `jobs/<rowJobId>/poster.webp` accepted) and one production query when a database is reachable (`SELECT poster_r2_key FROM media_assets WHERE kind='video' AND poster_r2_key IS NOT NULL LIMIT 50` — the prefix of whatever comes back *is* the answer). Add the signer-side prefix allowlist (Blocker 3) in the same pass and the whole class closes in one file.
