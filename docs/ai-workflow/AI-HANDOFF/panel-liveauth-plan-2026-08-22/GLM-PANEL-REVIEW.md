## BLOCKERS

The Wave-1 disease was "Settings reported 'Saved' without writing" — the *inverse* failure (write fails, surface still says "Saved") is the same bug class and no journey forces it. The next agent does exactly what's written → an optimistic-toast implementation passes → the agent still doesn't know whether the fix works when the network is slow, the token is expired, or the field is rejected. The plan's own standard convicts it: "the bug class this entire workstream fixed was **surfaces that claim a capability they do not have**," while the only persistence check is "Save. **Hard-refresh.** Confirm the values persisted." Add a forced-failure step (offline toggle or logout-in-second-tab before Save) requiring an error state, not "Saved."

2. **P1 — The recommended route produces evidence the plan's own gates should reject.** "Ask Sean to do the click-through and report results. Cheapest, most reliable for anything behind auth" is listed first — but hearsay cannot satisfy "**Measure it** (devtools, or `getBoundingClientRect()`), and record the number," cannot measure Journey E contrast, and is a weak "PROOF: line with current-session evidence" for the P0 check. The plan also says "do not ask him to read code" and then routes Journey D through devtools. Specify per-journey which route is mandatory (Playwright-observed for A2/B/C/D; Sean for touch feel and legibility) and what artifact each journey must yield.
