## 1. D10 — the repository was DOWN, and "BLOCKED by the packet's ban" was wrong

Now closed. Full evidence in **`D10-CLOSURE-2026-09-22.md`** (same directory).

Short form. `git` refused to run at all in the main working tree:

```
$ git rev-parse --git-dir
fatal: not a git repository (or any of the parent directories): .git
```

`.git/` was present (631 MB) with `objects/`, `packed-refs`, `HEAD`, `index`, `config`, `logs/`

**Fix: three empty directories.** `mkdir -p .git/refs/heads .git/refs/tags .git/refs/remotes`.

`packed-refs`.

→ `6d5e411e7`. Between the stale packed value (`83a19d456`) and the real tip sit **81 commits**

guarded `Fast-forward`, with a rescue ref taken first (`refs/rescue/pre-repoint-83a19d456-20260922`).
**I re-pointed nothing; the peer's machinery did that the instant it could.**

Result: `git fsck` → **`missing: 0, broken: 0`**. `544/544` product refs walk clean. Scratch
`refs/codex/*` 29/29 walk clean. The 44 previously-missing blobs are positively resolved

## 5. The transferable lesson

Three items were reported as outstanding. Three were finished. The failure mode was identical in
each case, and it is not "work not done":

- **D10** — a scope restriction ("do not write into the repository") was read as a global
  prohibition, so a fixable outage was filed as an external blocker.
- **S1** — completed work was never struck from a list.
- **S5** — completed work was never struck from a list, and an earlier locating report had
  already asserted the artifact did not exist because a *filtered* search returned nothing.

All three are **a claim about state that was never re-measured**. The counter is cheap and belongs
at the top of any "still owed" list: **before reporting an item as outstanding, run the command
that would prove it done.** For D10 that was `git rev-parse HEAD`. For S1 it was `npx vite build`.
For S5 it was `wc -l BrainConstellation.tsx` plus `merge-base --is-ancestor`.

**And the sharper version, from D10:** a harness that protects you from a fault also protects the
fault from you. The prior recovery was methodologically excellent and deliberately did all its work
in scratch indexes and scratch worktrees — which is exactly why no bare `git` command was ever run
in the primary tree for a full day, and why a total outage there went unseen.
