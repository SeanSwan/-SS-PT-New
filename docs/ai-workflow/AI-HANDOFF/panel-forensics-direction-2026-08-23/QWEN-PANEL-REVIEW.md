### 1. What the Rule System SHOULD Be (Priority: CRITICAL)
**Current State:** A 1,177-line document of 83 numbered rules, 60% of which are "MANDATORY" prose.
**Evidence:**

- Q2: 38–47% of errors were "already written up" before recurring.
- Q6: "Rule existed and was simply ignored" is **not** the failure mode. The failure mode is "Rule existed, was read, and violated because it had no mechanical consequence."

**The Fix:**
The rule system must shift from **Declarative Prose** to **Imperative Hooks**.
1.  **Delete 80% of the prose.** Keep only the rules that map to a *mechanical action* (a script, a gate, a validation step).
2.  **Convert the rest to "Triggers."** A rule is not a sentence; it is a condition that fires a script.
    *   *Bad Rule:* "Always check exit codes."
    *   *Good Mechanism:* A wrapper script `safe-exec` that runs the command, captures `$?`, and if `$? != 0`, it **halts the agent** and prints the error. The agent *cannot* proceed without acknowledging the exit code.
3.  **The "Zero-Trust" Principle:** The agent should never be asked to "remember" to do something. The environment must make the "wrong" action impossible or immediately visible.

**Concrete Action:**
*   **Rule 80 (Second-Vantage Verification)** is currently prose. Convert it to a **mandatory pre-commit hook** that runs a diff-check against a "known-good" baseline or runs a specific mutation test. If the hook fails, the commit is blocked.
*   **Rule 74 (Proof-Before-Done)** is currently prose. Convert it to a **CI gate** that requires a specific artifact (e.g., a test report JSON) to exist in the workspace before the "Done" status can be set.

### 3. The Learning Loop Fix (Priority: CRITICAL)
**The Problem:** The corpus shows lessons are **WRITTEN** but never **READ**.
*   28/106 packets fail schema.
*   416 memos pending unread.
*   A self-improvement queue nothing drains.
*   A validator whose gate mode works but which **NO hook invokes**.

**The Fix:**
The learning loop is broken because it is **passive**. It relies on the agent to "remember" to read the lessons. The agent does not.

1.  **Invoke the Validator:** The `hermes-learning-validate.mjs` script exists. **Wire it into the `pre-commit` hook.** If a new learning packet is added, the hook runs the validator. If it fails schema, the commit is blocked. This forces the agent to fix the schema before it can "save" the lesson.
2.  **Drain the Queue:** The "self-improvement queue" is a dead letter. **Delete it.** Replace it with a **CI Job** that runs daily:
    *   Reads all `pending` memos.
    *   Runs a simple LLM prompt: "Summarize the mistake. Is it already in CLAUDE.md? If yes, mark as 'Redundant'. If no, propose a new rule."
    *   Outputs a PR to `CLAUDE.md` with the proposed rule.
    *   **Human (Sean) approves the PR.** This moves the burden from the agent (who forgets) to the CI (which runs) and the human (who decides).
3.  **Schema Enforcement:** The 28/106 schema failures indicate the agent is writing "freeform" lessons. **Enforce a strict JSON schema** for learning packets. The agent must fill in: `Mistake`, `Root_Cause`, `Mechanism_Fix`, `Test_Case`. If it can't fill in `Mechanism_Fix`, it's not a valid lesson.
