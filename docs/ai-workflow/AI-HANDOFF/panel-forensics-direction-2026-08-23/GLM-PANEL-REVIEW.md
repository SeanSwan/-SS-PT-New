## 1. What the rule system should actually be

The catch-verb evidence (ran/checked ~84+, read 26, hostile ~48, recall 0) plus Q4's tethered-vs-untethered finding plus Q8's zero-recall-catches converge on one answer: **a trigger-tethered system in four layers, replacing a boot-time prose block.**

- **Layer 0 — Kernel (boot, target <2k tokens, from today's ~54k):** identity, routing, and one meta-law in the corpus's own words: *"A rule without a command is not a control."* Nothing else survives in boot context. No hand-written counts anywhere; counts generated by hook at build.
- **Layer 1 — Mechanisms:** hooks, gates, tests. This is where converted rules live. Out of context entirely — they cost zero boot tokens and fire whether or not anyone remembers them.
- **Layer 2 — Act-cards:** 2–4 command checklists bound to the four verb-moments where the recorded failures happen: *claim-absent, claim-done, quote-cost, declare-fixed.* Built from what actually caught things: run it, read it, or attack it. Example card (claim-absent): (1) positive control — search a string you know is present with the same instrument/scope; (2) read exit status, not the pipe; (3) state scope before verdict.
- **Layer 3 — Archive:** the packets and memos, machine-readable, **retrieved by lookup at task start keyed to the task's file/rule surface** — never loaded wholesale.

Rule format becomes **TRIGGER → COMMAND → REFUSAL**. A rule that can't fill that template goes to the archive or (rarely, max ~10) the kernel as a principle. Additionally: **stop mirroring CLAUDE.md/AGENTS.md by hand** — one source, one generated mirror. The Stage-1 author was bit by exactly this (local checkout capped at Rule 70, main at 83); two hand-maintained copies are a Class D drift machine.

Internal dissent, ruled on: one seat says keep a fatter rulebook because Q8's zero is phrase-level and prevention is invisible (P3). Ruling: the kernel keeps routing principles; prose that guards *recorded-recurrent* classes is demonstrably failed and gets converted; prose for classes with no recorded recurrence gets a **staged cut with measurement** (see Q6), not silent deletion.

## 3. New mechanisms the evidence demands (priority order)

1. **Exit-status law** — `exit code` 44 hits, **zero rule coverage**; the validator bug is an instance, not an outlier. pipefail/PIPESTATUS discipline + lint hook + validator self-test.
2. **Positive control before negative claims** — one mechanism covering six-false-absences, false schema-absent, the PII leak, probe-negatives. *No absence claim without a known-present control on the same instrument, same scope.*
3. **RED-before-green artifact** — a fix is not done without a recorded failing run of its regression test against pre-fix source (tests-can't-fail 4×; 13 tests never observed RED; mutation testing "only when run").
4. **Gate self-test + marker-emitter contract** — every gate ships a known-bad fixture it must catch, in the same change as the gate; every string a gate greps for has a tested contractual emitter. This single mechanism retires the entire "the gate is the failure" meta-class (guard-refuses-caller, adjacent-properties, marker-nobody-emits) **and stops the Rules 79→80→81→82 generation loop.**
5. **Obligation ledger** — requested panels/syncs become open tokens at request time; closeout gate refuses on open tokens without explicit Sean waiver. Catches deferral *as it happens*, not at disclosure.
6. **Receipt ≠ evidence** — done-claims attach this-session exit status + output tail from re-execution.
7. **Session-start card** — branch-currency check (origin/main ~38–43 hits, unruled) + targeted lesson lookup + open obligations.
8. **Stop-the-line at second same-class error in-session** — "third time session" appears 13 times; by the third it's already twice too late. Second occurrence forces a mechanism switch before continuing.

## 4. Fixing the learning loop — yes, this outranks the rulebook

38–47% of recurrences were already written up, and the memo corpus independently reproduces the headline from different agents. The knowledge store is **write-only memory.** The fix, in order:

1. **Fix the validator first** (exit 0 on FAIL → nonzero), then **positive-control it** (feed it a known-bad packet, assert refusal) — per P4, wiring it before fixing it builds a fake gate.
2. **Invoke it at write time, not audit time:** pre-commit hook on packets, CI on both corpora. 28 failing packets should never have landed.
3. **Drain by instrument, not model:** script-extract the 416 pending memos into the JSON ledger (the Haiku 77%-accuracy caveat says don't delegate this to a model), mark consumed. Then **move consumption to session start** — a lookup against the task's file/rule surface — because end-of-session writing with no reading point is the current architecture's actual bug (P5).
4. **Dedupe the write path:** a new mistake in a known class increments a recurrence counter instead of producing new prose. **Recurrence ≥2 auto-opens a mechanism-conversion ticket; ≥3 without a mechanism escalates to Sean weekly.** The corpus already told us the law: "do not re-write the lesson harder — convert it into a mechanism." The loop's job is to make that conversion non-optional.
5. **Retire lessons superseded by mechanisms** (marked `retired-by-mechanism-X`) or the archive regrows into boot context.
6. **Measure the loop:** monthly per-class recurrence rate is the KPI. A class that stays flat after its mechanism ships means the mechanism is decorative — which the gate self-test (Q3.4) then catches.
