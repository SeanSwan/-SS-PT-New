## VERDICT
REVISE — the failure-isolation mechanics are genuinely sound and honestly tested, but the slice ships previews whose payload weight, URL lifecycle, and "opaque signer" claim are all unresolved, and any one of them can silently defeat the retrieval goal this exists to serve.

## BLOCKERS
1. **P1 — Previews sign the original object; no derivative, no lazy-loading anywhere in the packet.** Scenario: a page of 24 image rows at the packet's own documented asset size (1920×1080, §1) is tens of MB; an operator on a studio tablet over LTE watches the grid paint for 10–30s and scroll-janks thereafter. "Recognising rather than reading" fails at the network layer before it can fail anywhere else. Evidence: `assetLibrary.mjs:234` signs "one short-lived URL per image row" — no resized variant, no `loading="lazy"`, no `decoding="async"` is mentioned in §2 or §4, and §4 admits no real-URL measurement was done. The absence of evidence is the evidence.

2. **P1 — Expiry has no re-sign path, and "hides the image" is not "shows the placeholder."** Scenario: operator loads page 1, works pages 2–4 for longer than TTL, scrolls back → every card on page 1 fires `onError` → hidden images. If hide ≠ swap-to-dimensions-placeholder, the operator sees a wall of blank cells — reads it as data loss, which is precisely the misreading §2 says the design exists to prevent. Evidence: §2 "does not re-sign"; §3.2 poses the question but the shipped behavior is silent degradation. Silent is the wrong answer for the primary session case; it's acceptable only as a last-resort fallback after a re-sign attempt.

3. **P1 (conditional — must be settled pre-merge) — "opaque" is asserted, not shown.** If `generatePlaybackUrl` emits a SigV4-style presigned URL (the R2 default), the object key is in the URL path. That silently reverses the prior posture the packet itself quotes — "the storage key never leaves the server" (§3.1) — at 24 keys per page, into browser history, referrer headers, and error-tracker breadcrumbs (Sentry captures full URLs by default, signature included). If keys embed original filenames, that's user data leaving too. Evidence: §2 signer reuse; no sample URL in the packet. One printed URL settles it; until then the trade analysis in §3.1 is conducted against an unverified premise.

4. **P2 — The degradation stack makes every failure mode invisible, including systemic ones.** Scenario A: signer secret rotates misconfigured → every row rejects → catch fires 24 times → page of placeholders, exit 0, zero telemetry, no alert. Scenario B: DB row exists, R2 object deleted (orphan) → `onError` → same pixels as an expired URL. `onError` cannot distinguish 403-expired from 404-gone, and the design treats them identically. Failure isolation without a counter on the catch path is a production blind spot wearing a feature's clothing. Evidence: §2 wrap; no logging/metric mentioned.

5. **P2 — Isolation covers rejection, not suspension.** Scenario: the signer's "local HMAC" invariant (§2) is true today; someone later swaps `generatePlaybackUrl` for a remote token service without a timeout → one stalled request → the awaited page assembly never settles → the library hangs on a spinner forever. The wrap catches throws and rejections; it does nothing about a promise that never settles. Cheap fix: outer timeout or `Promise.allSettled` with a deadline.

6. **P2 — "Non-image rows are not signed at all" (§2) is only as good as the mime column.** Scenario: assets uploaded before mime capture carry `mimeType = NULL` or `application/octet-stream` → misclassified → the back catalog permanently renders as dimensions-only cards. Retrieval exists for new uploads and silently doesn't for the oldest work. Evidence: none supplied — the nullability/backfill status of the classification column is absent from the packet.

## ATTACKS
- **Correctness:** The `Promise.resolve().then(...)` sync-throw wrap is correct and correctly tested — no notes, which is rare. Real notes: (a) if `onError` sets per-row error state, any future re-sign/refetch that returns a fresh `previewUrl` will not clear the flag → permanent placeholder until remount; the state shape chosen now determines whether blocker #2's fix is one line or a rewrite. (b) if `onError` is implemented as a DOM mutation (`style.display='none'`), it desyncs from React re-renders. (c) server clock skew against R2's validation clock produces instant-403 on every card — and per blocker #4, invisibly. (d) `tsc` exit 0 "over the glob-generated include" proves only that the glob's contents typecheck; a glob that misses a file proves nothing about it — check the include actually covers the three named files.
- **Security:** (a) **Signing oracle:** the signer signs whatever key each row carries. If `listAssets`' filter is client-steerable (trainerId, ids[]) and tenant scoping lives only in the single-asset reference endpoint, the list path becomes a bulk cross-tenant signing service. No WHERE-clause evidence in the packet. (b) **Cache headers:** the list response now embeds auth-bearing URLs; it must be `private, no-store` (or max-age well under URL TTL). A shared edge-cache key on this route is a cross-tenant signed-URL leak. Not specified. (c) **Stored XSS via asset origin:** if the bucket is served from a custom domain on the app's site, an uploaded SVG navigated to directly (signed URL, `image/svg+xml`) executes script on your origin — non-image rows escape signing, but SVG *is* an image mime. Verify domain topology. (d) Replay within TTL is inherent; leak surface scales with paging — short TTL + refetch-on-focus is the mitigation, which loops back to blocker #2.
- **Data-truth / schema drift:** (a) **The casing contract is unverified by construction:** backend is `.mjs` (untyped), `tsc` sees only the frontend, and 119 green frontend tests prove nothing if they mock `previewUrl` in camelCase while the server emits `preview_url`. Only a contract test against a running server settles it. (b) **The fallback is drift-invisible:** if the storage-key column is renamed in a parallel migration, `readUrl` receives `undefined`, every row rejects, every card renders the designed fallback — the feature that isolates failures also launders schema drift into "working" output. This is the sharpest interaction in the whole packet: the safety mechanism and the blind spot are the same code (`assetLibrary.mjs:234`).

## HIGHEST RISK
**Blocker 1 — full-resolution originals as grid previews.** It's the only blocker that is near-certain rather than conditional (no derivative pipeline is mentioned anywhere), and it defeats the feature's stated purpose on real devices regardless of how clean the signing code is. Cheapest de-risk: open one real page with the network panel (or `curl -I` one signed URL for `Content-Length`) — ten minutes, and it converts my inference into a number. If a page exceeds ~5MB, ship `loading="lazy" decoding="async"` now and put a width-constrained derivative (or a Cloudflare image-resizing prefix in front of the signed URL) at the top of the next slice.
