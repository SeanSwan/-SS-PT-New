# Part A — defects

Ranked most severe first. `CONFIRMED` = mechanism identifiable now; `SUSPECTED` = needs the probe stated.

1. **`CreateShortcut()` mutates an existing foreign `.lnk` in place; leftovers leak through.** On an existing path, `WScript.Shell.CreateShortcut` binds the *existing* shortcut's properties, and `Save()` writes only the four fields you set. Trigger: `Swan Guard.lnk` already exists pointing at `game.exe` with `Arguments = "-fullscreen"` and a Hotkey. After the script: target is your `.cmd`, but `-fullscreen` rides along and the hotkey fires your batch file. Silent repointing of something you didn't own. Fix: `Test-Path` first; refuse without `-Force`; when overwriting, `Remove-Item` then recreate so the object is clean. `CONFIRMED` (documented COM behaviour). Also mechanically prove it: build against a hand-made lnk carrying `Arguments`, read back.
2. **Pillow discards almost all of your prepared frames.** In `IcoImagePlugin._save`, the loop over `sizes=` accepts a provided image **only if `provided_im.size == im.size`** — i.e. only the one you passed as the base (`frames[-1]`). Every other appended frame, being a different size, is skipped; all remaining entries are derived by `thumbnail(size, LANCZOS)` *from the base image alone*. Consequence: the entire per-size UnsharpMask programme lands in exactly one stored frame; every other size is a plain re-downscale of that frame. Worse, if `frames[-1]` happens to be the **16px** end of your list, `thumbnail()` never enlarges — larger entries degrade toward 16px content. Your stated pipeline therefore cannot deliver the claimed per-size tuning as written. Fix: stop fighting Pillow — write the ICO container yourself (~40 lines: ICONDIR + ICONDIRENTRY + per-frame bytes; PNG payloads are fine for all sizes on Win10/11, or BMP for ≤48 for belt-and-braces) — and keep frames at their exact target sizes. Prove it either way in five minutes: generate frames where each carries its own size rendered as giant text, save through the real pipeline, reopen with `Image.open`, iterate `ico.sizes()`, set `ico.size` and extract — whichever digits appear tells you whose pixels got stored. `CONFIRMED` as mechanism (source), probe confirms your instance.
3. **Silent icon-file clobbering via sanitisation collision.** Strip-non-alphanumerics is non-injective: `Swan Experiment 2 - Recurrence Clock` and `Swan Experiment 2 – Recurrence Clock` (hyphen vs en dash) both become `SwanExperiment2RecurrenceClock.ico`; the second build overwrites the first with no warning, retroactively changing the other launcher's icon. Additional edge: a fully non-A-Z name collapses to an empty stem producing `\<Swan-Icons>\.ico`. Fix: append a short stable hash of the unsanitised name; keep a JSON manifest mapping cmd→ico→lnk. `CONFIRMED` (trivial string check).
4. **Desktop may not be the folder you're writing to.** With OneDrive Known Folder Move (default on new Windows 11 setups), the Desktop the user sees is under OneDrive; if the script resolves Desktop via `%USERPROFILE%\Desktop` or `$env:` instead of `[Environment]::GetFolderPath('Desktop')` / the Shell `Desktop` known-folder API, icons land in a folder nobody sees while "success" prints. `SUSPECTED` — probe: echo both resolutions on the owner's machine; compare with `(New-Object -ComObject Shell.Application).Namespace(0x0).Self.Path`.
5. **Frost-on-gold spine segment fails non-text contrast (tie-in, see Part B #4)** — noted here only so the icon work and console work share one contrast story. Arithmetic: `#E0ECF4` on `#C6A84B` ≈ **1.9:1**, far below WCAG 1.4.11's 3:1 for the active-section chip. `CONFIRMED` by computation.
6. **PNG-framed ICO entries at small sizes.** By default Pillow encodes ICO frames as PNG; Microsoft's format reserves PNG payloads for the 256px entry. Win11 Explorer copes, but you depend on leniency for 16–48px entries. `SUSPECTED` — probe: hexdump the .ico, check each directory entry's payload for the `\x89PNG` signature vs BI_HEADER; if small frames are PNG and any renderer mishandles them, that's your "generic glyph came back" heisenbug. Fix lives in the manual packer from #2.
7. **Halos at 16px and a contact sheet that hides them.** `UnsharpMask(radius=0.7, percent=140–190, threshold=1)` with threshold=1 sharpens essentially every pixel including the alpha-boundary neighbourhood; at 16px that produces over/undershoot ringing that reads as a light fringe on pale wallpapers. The grey contact-sheet ground cannot reveal a white fringe — that verification method is blind to the exact defect class it exists to catch. Fix: render the sheet on black, white, *and* a checkerboard; inspect corners at 1600% zoom; cap percent≈120 at 16px or exclude the outer 1px from sharpening. `CONFIRMED` mechanism, magnitude `SUSPECTED`.
8. **`ie4uinit.exe -show` is weak sauce and your messaging overpromises.** On Win11 it flushes only parts of the icon cache; stale frames persist especially when only `IconLocation` index/path changed, and the command gives no reliable success signal. When it no-ops, "done" is a lie and the owner wastes minutes rebooting Explorer by trial. Side effect to warn about: none harmful, but the *absence* of effect is the problem. Fix: print honest guidance ("if still stale: restart explorer.exe"), or offer `-RefreshExplorer` doing it properly (taskkill /f /im explorer.exe & start explorer — with confirmation). `SUSPECTED` per build — probe: flip IconLocation between two distinct icons, run -show, screenshot Explorer without restart on the owner's actual machine.
9. **`convert` upscales then trusts ground colour.** 700×900 → 1024 square means interpolating *up* AI art (never a win) and then your whole ladder downscales from invented pixels. Trigger: any sub-square source. Fix: pad to max dimension (square 900 here), keep the ladder downscale-only; assert source ≥ target with a loud warning otherwise. Also confirm the pad colour is transparent — an opaque pad letterboxes visibly at 16px. Half-verified already; the corner-pixel check remains. `CONFIRMED` as a quality issue.
10. **Comma in an explicit `-Icon` path.** `IconLocation="path,index"` is positional string parsing; a comma in the path (legal in folders/files, and in usernames — `Doe, John` profiles exist) makes resolution ambiguous. Your sanitised default paths are safe; the hazard arrives only via `-Icon`. Fix: reject commas in `-Icon`, or copy/rename the asset into `Swan-Icons\` under your own safe name first. `SUSPECTED` — probe: create `a,b.ico`, set, `Save()`, reopen, resolve; record what index the parser decided you meant.
11. **Half-written states.** `$ErrorActionPreference='Stop'` guarantees termination, not atomicity: die between "copy icon" and "Save()" and you've left a previous-good `.lnk` overwritten or an orphaned `.ico`. Fix: stage icon into place, then snapshot old `.lnk` to a backup name, then Save, then delete backup on success. Cheap, deterministic. `CONFIRMED` sequencing hazard.
12. **Missing declarations.** No `#requires -Version 5.1`, no `Set-StrictMode`. Relevant deltas: `Start-Process -WindowStyle Hidden` and `WScript.Shell` behave identically across 5.1/7, but **execution policies are stored per-edition** (5.1 vs PowerShellCore registry hives) — a machine unlocked for one edition is locked for the other, and the failure message will look like the script is broken, not the policy. Add `#requires`, and state in the header which edition was tested. `CONFIRMED` gap by omission.
13. **`-List` swallows everything, so partial blindness reads as completeness.** Malformed files (many tools emit non-shortcut junk named `.lnk`), and `.url` Internet shortcuts both throw or misparse; the catch merges "verified no-link" with "unreadable" — on a busy Desktop that's several silent unknowns. Also: reading `TargetPath` of a target-less network-share lnk returns the stale UNC path harmlessly (IShellLink doesn't resolve), so the real risk is misreporting, not hangs. Fix: distinguish exit states — HasLink / NoLink / Unreadable(reason) — and print counts. `SUSPECTED` composition; probe: plant a corrupted binary-named `.lnk` and a `.url`, observe classification.
14. **Rewriting a `.lnk` while the `.cmd` runs:** benign for the running process (it holds the `.cmd`, not the `.lnk`; the pin follows the path, so pins survive overwrite). Residual risk is a sharing-violation race if Save() lands during an Explorer-initiated read — under `Stop` you abort mid-sequence (see #11). Non-blocking; fold into #11's backup dance. `CONFIRMED` reasoning, negligible severity.
15. **Mark geometry at ÷64 (1024→16):** beak wedge spans ≈88×46 → **1.4×0.7px**: sub-pixel; it either vanishes into the head silhouette or aliases to a stray speck depending on hue. Waterline ellipse (24px tall band) ≈ **0.4px**: merges with plate-bottom vignette into an indefinite smear. Neck ribbon trailing half-width 19 → **~0.3px**: antialiased alpha may fall below perceptibility, breaking the ribbon into dots. Defects only if fidelity matters at 16px today — it's declared placeholder art, so log, don't redesign. `CONFIRMED` by scaling arithmetic.
