## FINDINGS

**1. BLOCKER | `SwanChart.tsx` (`events: Object.freeze([])`, `container()` stub) + absent files** — The interactive half of the frame does not exist, and the slice ladder says it should. v2 §C10/§C6 and the T0.4 slice specify `swanChartEvents.ts` with `parseDatumIndex` (string indices, grouped `"1-2"`) and per-kind `container(kind)`; §D specifies `swanChartEvents.test.ts`; T0.5 specifies `swanChart.guards.test.ts` in **blocking** mode. None of these files are in the packet. `events` is hard-frozen empty and `container` returns `undefined` unconditionally. Failure scenario: the first migrator in T1 spreads `ctx.events` onto a `VictoryLine`, gets nothing, writes their own `onClick` + index parsing (exactly the `CanonicalProgressChartsGrid.primaryCards.tsx:64-72` pattern B7 condemned), and drift is relocated, not prevented — with no blocking guard to stop them, which is v1's B11 failure repeating at slice zero. Minimal fix: land `swanChartEvents.ts` + `parseDatumIndex` + the guards test scoped to `Charts/swan/**` before T1 opens; until then the frame's claim "the one chart frame" is false advertising.

**2. HIGH | `swanChartColor.ts` (`resolveTokenColor` Path 1) and `swanChartColor.test.ts`** — The jsdom path masks a real browser failure, and the production path has zero coverage in this packet. Every positive assertion in the suite resolves through `dereferenceManually` (Path 2), because jsdom never evaluates the var(). In a real browser Path 1 runs, and it has different failure semantics: a custom property holding a syntactically-substituted-but-invalid color (a typo'd hex like `#C6A84`, or `10px`) makes `color` **invalid at computed-value time**, and an inherited property computes to its *inherited* value — so the probe returns the host's text color (~Frost White on the dark card), `parseColor` accepts it, `enforceSeriesContrast` passes it at ~15:1, and every series slot paints in body-text white instead of failing closed to Arctic Cyan. Concrete scenario: lens author typos the accent; `swanChartColor.test.ts` "falls back… when the token holds garbage" stays green (jsdom Path 2 falls back correctly) while production renders wrong. The blueprint's promised Playwright coverage of the browser path is also absent. Minimal fix: in the browser path, also read the authored stream via `getPropertyValue` and refuse it when it is neither a color nor a `var()` chain (syntax gate before trusting the computed read), and add the Playwright assertion this file's own header admits is missing.

**3. HIGH | `SwanChart.tsx` (`assertIdentityContract`)** — The mitigation gate is vacuously satisfiable. The legend check is `!legend || legend.length === 0`. `legend=[{one entry}]` passes for `seriesCount: 5`; a two-entry legend with both `hidden: true` passes; a legend whose slots don't cover the series passes; duplicated slots pass (`visibleSlots` becomes `[1, 1]`). `directLabels` is a boolean nobody verifies is honored by the body. This is the *only enforcement* of the lightness-band deviation (v2 §C2) — the "rule that cannot fail" fails silently. Scenario: a migrator under time pressure passes one legend entry to stop the dev throw; five series render with no identity mitigation and no test goes red. Minimal fix: require `legend.filter(l => !l.hidden).length >= seriesCount` (or slot coverage ⊇ `{1..n}` with uniqueness), and document that `directLabels` is a promise, not a check.

**4. HIGH | `SwanChartDataTable.tsx` (drillable row branch)** — A `<table>` (and `<td>`s) nested inside `<button>` is invalid HTML (button permits phrasing content only), and it wrecks the semantics the component exists to provide: the drillable rows collapse to one `colSpan` cell, so the outer table's "Point / Value / Detail" headers no longer describe those rows' cells, header association is lost, and screen-reader table navigation (ctrl+alt+arrows) walks into an unheadered nested table inside a button. Different SRs will flatten or announce it unpredictably. Scenario: an NVDA user opens the table on a drillable chart and hears column headers for a grid whose rows have no columns. Minimal fix: render the button's content as spans (visually styled to align), keep `<td>`s only for the non-drillable plain-row path.

**5. HIGH | `swanChartColor.ts` (`parseColor` + `enforceSeriesContrast`)** — Contrast is computed on the wrong color for anything with an alpha. `parseColor` silently discards the alpha channel, so `rgba(255,255,255,0.05)` grades as opaque white (~15:1 vs carbon) and **passes** the series guard while compositing to near-invisibility; conversely `ctx.fade()` then re-alphas the parsed channels, silently discarding a lens-authored translucency. WCAG contrast of raw channels is not contrast of the composited result. Additionally, the demotion surface is hardcoded to `SWAN_CHROME.surface` (`#141419`) while the card background is token-driven (`SwanCard`'s `color-mix` over `--surface-primary`); today that matches, but the moment a lens restyles surface tokens — the direction this whole system is heading — the guard validates against a surface the user isn't looking at. Minimal fix: composite the candidate over the surface before `contrastRatio` (or reject alpha-bearing candidates), and probe the card's actual computed background for the reference surface.

**6. MEDIUM | `swanChartTheme.types.ts` (`brandPalette`, `brandTheme`)** — The fence is one import away from defeat because the forging functions are exported. `import { brandTheme } from './swanChartTheme.types'` + one call yields a fully-branded hand-built theme; the "compiler, which is always on" guards nothing against a dev who finds the pretty constructor. The comment concedes "module-private by convention" — that's the same prose enforcement B12 was supposed to replace. Minimal fix: stop exporting the brand functions (build themes only inside `swanChartTheme.ts`, export the built objects), or accept and document that the brand only stops *accidental* fabrication and add the G-guard that catches imports of `brand*` outside the module.

**7. MEDIUM | `SwanChartDrillSheet.test.tsx` (`describe('portal')`) and the unused palette context** — The portal test is vacuous: `expect(dialog.closest('[data-swan-chart]')).toBeNull()` holds for *any* placement, because the test renders the sheet standalone where no `[data-swan-chart]` ancestor exists in the first place. It would pass if the sheet rendered inline. Meanwhile `SwanChartPaletteProvider` is wired in `SwanChart.tsx` and `useSwanChartPalette()` is exported, but **nothing in the portal consumes the palette** — the sheet's styles read raw CSS tokens. So the §C4 mechanism ("palette passed into the portal… portal content never re-resolves") is unproven and consumer-less, and the blueprint's `swanChartPortal.test.tsx` ("palette passed as a prop is used inside the portal") is absent. **8. MEDIUM | `useSwanChartTheme.ts` (`useLayoutEffect` deps)** — Re-resolution is keyed on `committedLensId` alone. A user (or recipe) that changes the committed accent *within* the same lens never triggers re-resolve: the grid keeps the old series color until a lens switch or reload. Scenario: user tunes the world accent in the lens editor; every chart on the dashboard silently disagrees with the accent everywhere else. [UNSURE — whether `appearance.state.committed` can change the accent without changing `styleLensId`; if the accent is only settable per-lens-id, this is moot. **9. MEDIUM | `SwanChartDrillSheet.tsx` (focus-return cleanup)** — When the opener has been removed, focus return silently does nothing and focus drops to `<body>`. Real flow: sheet open → parent re-renders with shorter `rows` (refresh completes) or the grid remounts → the row button that opened the sheet unmounts → Escape closes → keyboard user is dumped at the document top with `aria-modal` background. The guard `document.contains(opener)` makes the failure *quiet* rather than safe. Minimal fix: on unmount, if the opener is detached, fall back to a live container (the chart card's root via a passed ref, else `document.body`'s first tabbable) — never nowhere.

**10. MEDIUM | `SwanChart.tsx` (SwanPlot `role="img"`)** — `role="img"` forbids descendants in the accessibility tree. T0 gets away with it because there is no interactive Victory content (see finding 1), but the moment T1 wires voronoi targets, focusable marks, or portals tooltips inside the plot, screen readers will skip all of it — and the migrator will "fix" it locally, nine different ways. Minimal fix: `role="group"` with `aria-label` plus `aria-describedby` to a summary, or `img` on the inner SVG only, decided now while there are zero consumers.

## WHAT THE CODE GETS RIGHT

- **The drill race is genuinely closed**: the monotonic request-token in `useSwanDrill` correctly handles close-then-resolve, rapid re-open, and out-of-order responses, and the test drives the real interleavings rather than mocking time; unmount-during-flight is state-safe.
- **Honesty is enforced end to end**: shape-failure (`drill-shape-unrecognised`) is distinguished from empty (`entries: []`), which is distinguished from transport error, in the source, the sheet, and the frame — with tests that would each fail if the distinction collapsed.
- **The test instruments are themselves tested, with negative controls**: `swanChartTestKit.test.ts` proves jsdom lacks RO/matchMedia before mocking them, and the color suite proves `getPropertyValue` cannot answer the question the probe answers. This is the right discipline, applied consistently.
- **The D1 fix and the tier-parity change are both pinned by negative controls** ("still counts every real failure", "leaves the performance charts gated") — the tests fail loud if the fix overshoots, which is exactly how an entitlement change should be locked.
- **The WCAG math itself is correct**: luminance coefficients, the 0.03928 knee, the (L1+0.05)/(L2+0.05) ratio, and the 3:1 graphics threshold for `MIN_SERIES_CONTRAST` are all right — the defect is *which color* gets graded (finding 5), not the arithmetic. Reduced-motion is also fixed at the only layer that matters: synchronous first-render initialization with a render-trace test that specifically defeats the `act()` masking trap.
