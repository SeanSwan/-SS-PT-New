## VERDICT
REVISE — the ladder's architecture and its honesty mechanisms (tri-state lanes, frozen provenance, withheld embeds) are genuinely sound, but licence enforcement is currently disconnected from reality and published embeds self-destruct in four hours, so merging today ships silent legal exposure and deterministic site breakage that roughly a week of targeted fixes removes.

## BLOCKERS
(The packet supplies module/section references, not line numbers; citations below are the strongest the document offers.)

1. **P0 — Published embeds expire by design.** `GET /asset/:id/reference` hands out `<img>/<video>` snippets built on a signed read URL with a 4h default lifetime (§2.1 Publish; §3 Q2). Scenario: Sean publishes an asset Monday, pastes the snippet into a client site; Tuesday every image 404s with zero telemetry anywhere in the pipeline. The sha256 content-addressed key makes the fix cheap and safe: an unsigned, immutable-cache, status-gated public route (`/asset/:id/public/:hash.ext`, 404 unless `published`), with signed URLs reserved for draft previews. This also violates the packet's own §1 principle — the UI promises an embed the server will break.
2. **P0 — Policy gates are wired to nothing.** "Nothing in the pipeline sets a flag yet, so today the consent gate never trips" (§2.2). Under the doc's own reading this is **fail-open**: grant/consent required-ness is never populated, so H3 (explicitly non-commercial-until-grant, weights sitting on `Z:`) can be run and published commercially with no refusal — a direct violation of the binding fail-closed licence-gate rule. The alternative reading (false flags → everything refused) is a total publish outage. Whichever is true, enforcement is decorative until a setter exists, and no test can currently distinguish them.
3. **P1 — The Still rung's execution contract.** A 4-up batch on a 27s/frame model is ~2 min inside one HTTP request (§3 Q3): nginx's default 60s `proxy_read_timeout` and Cloudflare's 100s cut the connection while GPU work continues; there's no cancel; and because single-flight/coalescing is in-process, a backend restart mid-batch strands the reservation — a client retry then either double-spends GPU or hangs on dead state depending on where the idempotency key lives. Motion already solved this with the queue; stills should be `202 + jobId` on the same queue, not a special case.
4. **P1 — Cross-lane VRAM race.** Motion jobs go through the video queue; stills run inline with a single live-VRAM snapshot at admission (§2.1, §3 Q3). A video job loading while a still batch is in flight (or starting after the snapshot) oversubscribes the 5090 → ComfyUI OOM → both lanes die mid-run, plus a half-failed bind. Admission and the queue scheduler need a shared lock, not a point-in-time read.
5. **P1 — `initImage` filename TOCTOU.** Agent re-hashes, uploads to ComfyUI input, "then the graph sees a filename" (§2.1 Motion). If uploads use non-unique names, job B's upload can overwrite job A's input between A's upload and A's graph execution → A renders video from the *wrong image*, silently, because the hash check already passed. The doc doesn't specify the naming scheme; hash-prefixed filenames (the sha256 is already in hand) close it in one line. Relatedly: nothing described cleans ComfyUI input files after terminal jobs → unbounded disk growth degrading every lane on a box that also serves video.
6. **P1 — `permanent:true` on mismatch conflates tampering with infra.** A truncated upload (disk full in ComfyUI input) or an input-dir wipe (`free_memory`, restart) presents as permanent asset corruption. The minute-scoped idempotency key means a resubmit a minute later actually escapes the "permanent" verdict — so nothing is truly stranded, but the error taxonomy lies to the operator. Classify upload-corruption as retryable (cap 2) and reserve `permanent` for R2-side hash disagreement.
7. **P2 — Twin assets across months.** Key = sha256 per owner per month (§3 Q4): identical bytes in March and July = two `MediaAsset` rows with *independent* frozen provenance and publish state — one commercially cleared, one not, same pixels. That's a licence-state divergence machine, not a storage-cost issue. Unique index on (owner, sha256) + return-existing at persist.
8. **P2 — Dual project keys.** `workspaceId` in tags vs `MediaAsset.projectId` as a content_projects FK left null (§2.2): two homes for one concept invites both tag-scan queries and, later, writing a non-FK value into the column. Decide the one home before a second site exists.

## ATTACKS
- **Correctness:** /estimate's dead-lane guarantee holds only at estimate time — a lane dying between Brief and Still is exactly the promise-then-refuse the packet bans; the predicate must be shared and re-checked at execute. Sync-timeout → re-click behavior depends on whether the idempotency key is client-stable (unverifiable). Minute-granularity motion keys: legitimate resubmits across a minute boundary duplicate jobs; NTP steps distort windows (theoretical). Persist failure mid-batch after GPU spend surfaces stills that are Motion-locked — honest, but the UI needs an explicit "generated, not persisted" state or it's a silent dead-end.
- **Security:** Owner scope is asserted only for `GET /asset/:id` (§2.1); `POST /asset/:id/status` and `/reference` scope is unstated — publish is the money action, verify before merge (IDOR candidate). Taste-brain loopback pinning: confirm no redirect-following and a literal `127.0.0.1` pin (not `localhost`/`::1`). MCP: `stop_comfyui`/`free_memory` unguarded with a prose-only allow-list is tolerable *only* while no tool-enabled agent consumes corpus-derived text; the moment one does, corpus poisoning → tool abuse is live — encode the allow-list as config even keeping Sean's no-per-tool-disable call. Hosted lane: OpenRouter prompts assemble operator-typed briefs with no scrubber at the seam — a client name in a brief violates the zero-PII rule; add a deny-list or an explicit "this text leaves your machine" gate.
- **Data-truth / schema drift:** `initImage` is two shapes (object in the ticket, filename in the graph) across the queue boundary — same key, different type, the classic drift seam; version the ticket schema and validate at agent ingest. Blocker 8's tags-vs-column split. `buildProvenance` freezes a licence snapshot, but publish-time decisions need *both* snapshot and current licence-table hashes recorded or audits become unreproducible after table edits. `/limits` enum extension (`claimed` → `unavailable` post-probe) must not crash a lane strip that only knows three states. No test touches a real DB row shape (§2.2), so PascalCase-model vs camelCase-route drift is entirely unprobed.

## HIGHEST RISK
The disconnected policy gates (Blocker 2). Broken embeds announce themselves; legal exposure from commercially publishing H3-derived output doesn't — and it's the one failure the entire provenance machinery exists to prevent, currently inert while looking implemented (gates exist, 195+ tests pass, nothing fires). Cheapest de-risk before merge: invert the default so a licence-table entry requiring consent/grant plus a **null** flag means *refuse* with a distinct error code (turning "never set" into fail-closed), add a config-driven grant map (`SWAN_ATELIER_GRANT_<MODEL>`), and put the consent setter where human-originated bytes enter the system — an explicit attestation at persist ("depicts an identifiable person; release on file"), stored in provenance. Roughly a day of work plus one test per gate. Treat the 4h-URL fix as the immediate fast-follow.
