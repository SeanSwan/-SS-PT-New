## BLOCKERS

1. **P0 — The validator's root of trust is self-attestation; the gate can be legitimately bypassed by its own inputs.** Scenario: any agent (or compromised process) edits `assets/registry.json` to add an id, writes a manifest with `similarityReviewed: true` and `provenance: {tool:"x", command:"echo ok", date:"2026-08-25", commit:"deadbeef"}` → `validate-asset.mjs` exits 0 and the asset is "gated." Evidence: §2.1 `validate-asset.mjs` bullet (requires `similarityReviewed !== true` rejected, provenance shape only) + F2/F3/F4. The one cheap truth check — `git cat-file -e <commit>` — is explicitly not done (F3). A gate whose keys are inside the gate is not a gate; everything downstream (budgets, license policy, Draco rule) inherits this.

2. **P0 — `swan_pipe.py` is scheduled to be the first thing run after install, and it has never executed, with two calls its own docblock marks UNVERIFIED.** Scenario: Owner installs Blender 4.5, runs `blender -b --python tools/blender/swan_pipe.py` → `export_scene.gltf` fails or silently mis-exports in background mode (upstream issue 83188, cited in §2.1), or `uv.smart_project` rejects kwargs → the failure is entangled across 269 lines and seven pipeline stages, undebuggable as a first run. Evidence: §2.1 `swan_pipe.py` ("UNRUN", two UNVERIFIED calls); F7 (the proof fixture is hand-authored bytes, cannot fail the way a Blender export can). This is exactly the calibration error class of §1 — "written against the 4.5 API" covering calls never checked — recurring in the branch built to kill it.

3. **P1 — `chromeLaw` and eight other registry fields are declared and never read; the constraint that justified the entire P0 correction is unenforced.** Scenario: a future manifest puts Voxel Realm chrome on a Swan-branded surface → validator passes it, because no code path reads `chromeLaw` (§2.1 registry bullet, F1). The branch's reason to exist is a correction; the correction's encoding is decorative.

4. **P1 — Push procedure for a shared pre-commit hook under four active agents is unaddressed.** F8 checked file overlap (0/26) but explicitly did not check behavioural overlap: a new pre-commit stage added in those 18 `main` commits could interact with the guard's fail-open-on-error and docs-only scope. Scenario: rebase applies clean, guard lands, another stage's failure is swallowed by the guard's fail-open ordering (or vice versa) → hooks silently stop blocking. Evidence: F8 "What is NOT checked."

## ATTACKS

- **Correctness:** The truncated-evidence-guard is fail-open on its own errors (§2.1) — combined with F5's scope (docs/ + .ai-workflow/ only), the most likely vector for the next false absence claim (a commit message or chat reply, per F5) is unguarded *and* the guard can silently stop guarding. `catalog-check.mjs` on `.md` is a superset scan: PRESENT is weak — but nothing prevents a downstream consumer from treating a weak PRESENT as strong, recreating the entry-16 incident in reverse. `measure-glb.mjs` STRIP/FAN n−2 assumes no degenerate triangles and no primitive restart index (0xFFFF/0xFFFFFFFF in indexed strips) — a restart-indexed strip overcounts; fine for budgets, but it's the same "fixture hid the unit" class the P1 panel already burned on.
- **Security:** Path containment is checked "before any read" (good), but symlink refusal + 256 MB cap is enforced at validation time, not at runtime load time — a TOCTOU swap between `validate-asset.mjs` passing and the engine reading the file is unaddressed (low likelihood in this threat model, but the doc claims containment as a property, and it is a point-in-time property). F4 is the real multi-tenant/agent-scope leak: registry write access == gate bypass. No rate-limit concern; no PII-to-LLM issue visible (IDs only, consistent with house rule).
- **Data-truth / schema drift:** Nine declared-but-unread registry fields (§2.1) is textbook schema drift — the registry's declared shape and its enforced shape have already diverged on the branch that introduces both. `budgets: null` + advisory `budgetPriors` means the budget schema has two parallel representations; the validator reads one, humans read the other, and the sanity flag (4 MB texture on a 1500-tri prop) lives only in the unenforced one. `swan_pipe.py` emits `"compression": "none"` and the validator only inspects compression when `draco` (F6) — a future `optimize.mjs` emitting `meshopt` or `ktx2` passes silently.

## HIGHEST RISK
Blocker 1/2 are tied in impact, but **Blocker 2 is the most dangerous because it is the most certain to fire**: an unrun 269-line script with two self-flagged UNVERIFIED calls *will* be the first thing executed after install, and its failure mode is a tangled multi-stage mess that will be misdiagnosed (the exact §1 error class). Cheapest de-risk: before `swan_pipe.py` ever runs, execute a ~10-line smoke script — import one `.obj`, `export_scene.gltf` to a temp path, assert the GLB magic bytes — in `blender -b`. That isolates the single UNVERIFIED call with an upstream failure report from everything else, costs fifteen minutes, and converts "UNRUN" into a known-good foundation.
