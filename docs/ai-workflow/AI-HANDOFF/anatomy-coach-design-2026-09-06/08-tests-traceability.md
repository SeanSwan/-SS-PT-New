## Executable acceptance specifications and coverage

[Atlas port manifest conformance](acceptance/atlas-port-contract.test.mjs), [API contract suite](acceptance/api-contract.test.mjs), [pure recovery model conformance](acceptance/model-conformance.test.mjs), [UI fixture suite](acceptance/ui.spec.cjs), and [scenario manifest](acceptance/scenarios.json) are supplied for the builder. They are not application implementation. Proposed test adapter names are contracts to implement in an isolated harness, not existing endpoints.

API runner requires a private fixture config and a loopback-only server with an explicit disposable-fixture marker. It refuses public/production hosts before any write. Never put tokens or a production DATABASE_URL in the packet. The test-only fixture-identity endpoint belongs solely to an isolated test server; never add it to production. Scenario payloads use synthetic users.

Model runner requires a reviewed pure adapter exporting evaluateRecovery. It has no DB/network access. Missing adapter/setup is BLOCKED/NOT RUN, never EXPECTED RED. UI suite uses the installed frontend Playwright dependency and requires SPA_BASE_URL plus the same fixture isolation marker. It is outside the normal green suite until the builder intentionally configures it. No failing import is an intended regression.

Tests not present as executable files yet have exact proposed commands and observable manual steps below. Builder must materialize those in the owned implementation slice and capture valid behavioral RED→GREEN. Plan completeness does not imply all automated suites already exist.

## Coverage gaps and honest status

All 35 requirements have linked tests; this is **planned traceability**, not 100% behavior coverage. Source-only backend checks do not cover PostgreSQL, assignment revocation at runtime, encrypted new fields or external provider consent. UI fixture mocks do not prove actual persistence. Model conformance does not validate physiological recovery. Wireframe rendering does not prove physical-device accessibility.

Unverified boundaries: release/worktree identity, complete dynamic caller inventories, licensed production asset catalog, real device/GPU limits, all-role browser journeys, transactional history migration, coach durable intent reconciliation, calibration/content review and deploy proof. These are explicit gates in S0–S12. The structural readiness gate must report open blockers and B01 FAIL; it must not be weakened to produce a green label.

No new app tests were added to the normal test suite, no database migration ran, and no app build was necessary for planning artifacts. The packet checker/skill validator/diagram render are artifact-only checks whose actual results are added to the receipt.
