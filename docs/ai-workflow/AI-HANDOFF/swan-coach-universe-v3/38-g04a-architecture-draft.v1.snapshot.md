**Owner API and invariants**

Use positive safe-integer actor/target IDs and a UUID task ID generated by `crypto.randomUUID()` on explicit task creation. Missing identity yields no task. Do not use `"new-session"`, thread IDs, route strings, timestamps, or array indices as task identity.

Suggested API:

```ts
useCoachSessionDraft(): {
  draft: Readonly<CoachSessionDraft> | null;
  submitted: Readonly<SubmittedDraft> | null;
  pendingTargetChange: TargetChange | null;
  begin(targetUserId, origin): ScopeToken;
  edit(scopeToken, expectedRevision, patch): EditResult;
  freezeForSubmit(scopeToken, expectedRevision): SubmittedDraft;
  requestTargetChange(nextTargetUserId): TargetChangeResult;
  resolveTargetChange(scopeToken, decision): SelectionIntent;
  discard(scopeToken): void;
}
```

These are proposed names, not existing exports.

- One authoritative draft object; every consumer receives the same context-backed reference. Do not copy exercise arrays into page, dock, or Logger state.
- Every semantic edit increments revision; tab changes, rendering, speech playback, and navigation do not.
- Freeze creates a deep immutable snapshot with its own UUID `requestKey`, exact revision, target, and task identity. Repeated transport attempts reuse it. Freeze alone neither saves nor clears the unsaved-work indication.
- Editing after submission preserves the old snapshot and produces a new editable revision with new submission identity. Approval references never move to the edited payload.
- Do not maintain a roster-sized draft map. One active working task plus its submitted snapshot and a pending switch is sufficient for the next slice. Server receipt history remains server-owned.
- Memory only. No draft text, exercises, health information, or snapshots enter sessionStorage, localStorage, IndexedDB, logs, or provider prompts.

Actor ID/role change or logout masks the previous owner’s content during rendering, retires its generation at the committed boundary, and clears references. A→B→A cannot resurrect A’s previous task. Pending async continuations must check actor generation, task ID, target, and revision before publishing. Async work must not claim domain rollback merely because local interest ended.

**Target integration contract for activation**

The owner proposes decisions; `useCoachPinnedClient` remains the actual selection adapter.

Before G04b exposes editing, wire selection requests **before** pin, URL, conversation-clearing, or thread-selection side effects:

- Clean task: commit the target change through the existing pin/route path.
- Dirty task: hold the requested change and present Return / Discard.
- Return before selection commits: retain the original real selection and task.
- Browser navigation or another surface may already change selection. In that case suppress the old task’s editable/private content, retain the conflict, and make Return restore the real original target and compatible thread route through the existing selection functions. Simply clearing the warning is prohibited.
- Discard removes the old editable content, retires its preview/submission continuations, then commits the requested target. It never cancels a server operation implicitly.
- Reject malformed or unavailable target selections. Client/general-user mode gains no staff draft authority.

Do not put route-specific navigation callbacks or copies of the client roster into the owner. A page adapter translates the returned selection intent using `buildThreadSelectionSearchParams` and the existing pin workflow.

**Canonical workout compatibility**

Freeze the model around the actual strict backend boundary:

- Session fields: date, optional title/notes/duration/intensity/source.
- Exercise: stable `exerciseInstanceId`, canonical library `exerciseId` and/or `exerciseKey`, optional matching canonical name, explicit unit, ordered sets.
- Set: unique positive `setNumber`, exact nonnegative integer `reps`, explicit nonnegative numeric `weight`.
- Missing editable numeric input stays null/incomplete; it is not zero.
- Use `weight` as the owned field. Do not maintain divergent `load` and `weight` values.
- Bodyweight requires explicit zero load. Preserve kg input as unsupported-for-save; the current library resolver refuses kg with `UNIT_MAPPING_REQUIRED`. Do not invent conversion.
- Exercise IDs come from `/api/exercises/library`. Client-generated instance UUIDs identify repeated instances, not library exercises.

The earlier loose `Array<Record<string, number|string|null>>` set shape is unsuitable.

G04b maps the validated snapshot to the existing versioned endpoint envelope. G04a sends no endpoint request.
