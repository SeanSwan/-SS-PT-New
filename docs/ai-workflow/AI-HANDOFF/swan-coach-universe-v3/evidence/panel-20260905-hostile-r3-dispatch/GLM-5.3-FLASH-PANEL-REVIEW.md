## HIGHEST RISK
The single most dangerous item is the intersection of blocker 2 and the missing retry contract: a domain effect commits without an atomically-written receipt on most command families, the operation reports `unknown`, and a user (or a helpful future auto-retry) repeats it — silently duplicating health-adjacent writes on real member records with no cross-domain guarantee and, outside workouts, no way to *ever* resolve the unknown. Cheapest de-risk, doable in roughly a day with no new infrastructure and no new write authority: (1) write the one-page seam table into the canonical contracts doc (family → named existing authority → transaction boundary → verifier → compensation); (2) one fault-injection integration test per family that kills the process between effect commit and receipt write and asserts same-requestKey retry never redispatches; (3) freeze two sentences as hard rules — unknown is never auto-retried, and retries always reuse the original request key.
