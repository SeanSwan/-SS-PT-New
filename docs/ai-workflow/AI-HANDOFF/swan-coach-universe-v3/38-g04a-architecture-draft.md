**Owner API and invariants**

Use positive safe-integer actor/target IDs and a UUID task ID generated by `crypto.randomUUID()` on explicit task creation. Missing identity yields no task. Do not use `"new-session"`, thread IDs, route strings, timestamps, or array indices as task identity.

Suggested API:

```ts
useCoachSessionDraft(): {
  draft: Readonly<CoachSessionDraft> | null;
  submitted: Readonly<SubmittedDraft> | null;
  pendingTargetChange: TargetChange | null;
  begin(targetUserId, origin): ScopeToken;
  edit(scopeToken, expectedRevision, patch): EditResult;
  freezeForSubmit(scopeToken, expectedRevision): SubmittedDraft;
  requestTargetChange(nextTargetUserId): TargetChangeResult;
  resolveTargetChange(scopeToken, decision): SelectionIntent;
  discard(scopeToken): void;
}
```

These are proposed names, not existing exports.

- One authoritative draft object; every consumer receives the same context-backed reference. Do not copy exercise arrays into page, dock, or Logger state.
- Every semantic edit increments revision; tab changes, rendering, speech playback, and navigation do not.
- Freeze creates a deep immutable snapshot with its own UUID `requestKey`, exact revision, target, and task identity. Repeated transport attempts reuse it. Freeze alone neither saves nor clears the unsaved-work indication.
- Editing after submission preserves the old snapshot and produces a new editable revision with new submission identity. Approval references never move to the edited payload.
- Do not maintain a roster-sized draft map. One active working task plus its submitted snapshot and a pending switch is sufficient for the next slice. Server receipt history remains server-owned.
- Memory only. No draft text, exercises, health information, or snapshots enter sessionStorage, localStorage, IndexedDB, logs, or provider prompts.

Actor ID/role change or logout masks the previous owner’s content during rendering, retires its generation at the committed boundary, and clears references. A→B→A cannot resurrect A’s previous task. Pending async continuations must check actor generation, task ID, target, and revision before publishing. Async work must not claim domain rollback merely because local interest ended.

### Concrete owner contract

This replaces the earlier “suggested API” wording. Names may follow local
conventions, but these discriminants and validation semantics are normative.

~~~ts
type ActorRole = 'staff' | 'admin' | 'coach';
type DraftOrigin = 'talk' | 'review' | 'history';
type TargetId = number;
type Revision = number;
type TaskId = string;
type RequestKey = string;

type ScopeToken = Readonly<{
  taskId: TaskId;
  actorId: TargetId;
  actorRole: ActorRole;
  actorGeneration: number;
  targetUserId: TargetId;
  revision: Revision;
}>;

type OwnerError =
  | 'MISSING_IDENTITY' | 'ROLE_NOT_AUTHORIZED' | 'INVALID_TARGET'
  | 'TASK_NOT_FOUND' | 'STALE_SCOPE' | 'STALE_REVISION'
  | 'INVALID_PATCH' | 'INCOMPLETE_SNAPSHOT' | 'GENERATION_RETIRED'
  | 'TARGET_CONFLICT' | 'UUID_GENERATION_FAILED';

type OwnerFailure = Readonly<{ ok: false; error: OwnerError; message: string }>;
type ScopeResult = Readonly<{ ok: true; token: ScopeToken }> | OwnerFailure;
type DraftPatch = Readonly<{
  date?: string | null; title?: string | null; notes?: string | null;
  exercises?: readonly DraftExercise[];
}>;
type EditResult =
  | Readonly<{ ok: true; draft: Readonly<CoachSessionDraft> }> | OwnerFailure;
type FreezeResult =
  | Readonly<{ ok: true; submitted: Readonly<SubmittedDraft> }> | OwnerFailure;
type TargetDecision = 'return' | 'discard';
type TargetChangeResult =
  | Readonly<{ ok: true; pending: TargetChange }>
  | Readonly<{ ok: true; intent: SelectionIntent }> | OwnerFailure;
type CoachSessionDraft = Readonly<{
  taskId: TaskId; actorId: TargetId; actorRole: ActorRole;
  targetUserId: TargetId; origin: DraftOrigin;
  revision: Revision; exercises: readonly DraftExercise[];
}>;
type SubmittedDraft = Readonly<{
  taskId: TaskId; requestKey: RequestKey; actorGeneration: number;
  targetUserId: TargetId; revision: Revision;
  payload: Readonly<CanonicalWorkoutDraft>;
}>;
~~~

begin validates actor and target IDs, role, origin, and UUID generation.
edit accepts only the allowlisted DraftPatch, validates date and the
canonical exercise/set shape, and uses compare-and-set against the complete
ScopeToken. freezeForSubmit rejects incomplete or malformed content and
deep-freezes the snapshot. requestTargetChange is idempotent for an identical
pending target and rejects malformed/unavailable targets. resolveTargetChange
requires the current task/generation and has no selection side effect.
discard is local retirement only and never claims to cancel a server operation.

~~~mermaid
stateDiagram-v2

  Empty --> Masked: missing or retired identity
  Editing --> Editing: edit(CAS success)

  Rejected --> Editing: caller refreshes current token
  Editing --> Frozen: freeze(valid complete snapshot)
  Editing --> PendingTarget: requestTargetChange(dirty)
  PendingTarget --> Editing: resolve(return)
  PendingTarget --> Empty: resolve(discard)
  Frozen --> Editing: edit(new revision)
  Editing --> Masked: actor or role generation changes
  Frozen --> Masked: logout or actor generation changes
  Masked --> Empty: committed cleanup
  Editing --> Empty: discard
~~~
