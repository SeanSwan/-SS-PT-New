## Lead decisions, no further historical-unit question

1. Keep new `WorkoutSession.totalWeight` as the sum of compatibility pound loads times reps,
   matching new `WorkoutLog.weight`. Do not add another unit column or store kg there.
   New unit-aware aggregates derive kg from explicit set pairs, exclude unknowns with coverage,
   and do not use old session totals to fabricate normalized history.
2. Explicit wire mode is top-level integer `weightContractVersion:1` on the existing writer
   request, not a new route. Every NEW/CHANGED version1 weight supplies numeric `weight` plus
   exact `weightUnit` lb/kg; missing/ambiguous/conflicting units reject before transaction.
   Sean1B in23 requires untouched historical unknowns to stay untouched; the separate
   authenticated existing-row preservation mode needs a precise next-slice contract. No
   missing-unit new set may masquerade as historical preservation. New unit fields without
   version1 also reject; unsupported versions reject. Existing versionless, unitless requests
   keep legacy semantics and clear/leave NULL the explicit pair when rebuilding sets.
3. Persisted/normalized internal sets carry compatibility `weight` in pounds PLUS enteredWeight
   and enteredWeightUnit. Do not attach a kg `weightUnit` label to compatibility pound values.
   Diary JSON, session totals and WorkoutLog writes must be atomic and agree on this basis.
   New v1 compact AI set-count syntax is not implicitly supported: adapters must first produce
   explicit set arrays. Do not infer a unit from locale, preference, UI label or old metadata.
4. API v1 weight is a strict finite nonnegative number <=999999.999999 and must round-trip
   unchanged through six fractional decimal digits; reject excess precision, never round silently.
   DB NUMERIC strings are a separate adapter: unsigned ordinary decimal notation only, no
   whitespace/exponent/comma/plus/infinity/NaN, maximum six integer and six fraction digits;
   preserve NULL, reject malformed values, and only then decode to number. No parseFloat prefix.
5. Existing BodyMeasurement `lbs` maps to canonical `lb` only through KG0's explicit alias
   boundary; kg maps directly. This was already decided in12, not an unresolved choice.
6. AI/import new unit-aware writes missing provenance must request clarification/422 with zero
   writes. Synthetic backfill remains explicitly synthetic and excluded by the source policy;
   do not tag generated historical loads as verified pounds to make a chart green.

These decisions bind the next writer blueprint, but are not authorization to change every
listed file now. Error envelopes, actual middleware paths, idempotency and compact AI caller
adaptation still require source-backed per-slice detail. No provider output replaces that work.
