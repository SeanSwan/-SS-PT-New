## VERDICT
REVISE — the relationship lane is sound for create/send, but `POST /conversations/:id/participants` never applies that lane to the new IDs, and the consent surfaces still lie about sleep data.

## BLOCKERS
1. **P0 — relationship user can inject an outsider into a coaching thread.** Inputs: free/trial-expired client `C` with `ClientTrainerAssignment.status='active'` to trainer `T`; `C` `POST /conversations` `{participantIds:[T]}` (create-scope allows it); then `POST /conversations/:id/participants` `{participantIds:[STRANGER]}`. State: middleware uses `scope:'conversation'`, which only subset-checks *existing* `others` (`T` ∈ counterparties) and never reads `req.body.participantIds`. Output: 2xx from the gate; `STRANGER` is now a `conversation_participants` row on a thread the comments themselves call an injury/pain/safety channel. If `STRANGER` is elite/trial/staff they then pass Lane 1 and can read the history. Evidence: `backend/routes/messagingRoutes.mjs` mounts `messagingThread` on `POST /conversations/:id/participants` (hunk at new ~59–63); create-scope check is only in `requireMessagingAccess.mjs` ~216–230; conversation-scope (`~232–244`) inspects `loadConversationMembers` only. Their own standard in the file header: a gate that depends on a later controller is “authorization by luck.” Tests never cover this — `groupParticipantAuthzExecution.test.mjs` stubs the new middleware to `next()`, and `messagingRelationshipLane.test.mjs` has no add-participants case.

2. **P1 — consent copy is false about sleep.** `deIdentify` still forwards `lifestyle.sleepHours` (test *asserts* `toBe(7)` and the comment says it is “NOT gated”). User-facing copy says sleep is withheld/never sent. Failure: client consents under “supplements, sleep, and stress data are never sent” → provider receives `sleepHours: 7` (and any other non-listed sleep path). Evidence: `backend/tests/api/aiPrivacy.test.mjs` ~221–241; `GATED_HEALTH_PATHS` in `backend/services/deIdentificationService.mjs` ~82–94 (has `lifestyle.sleep` / `lifestyle.sleepQuality`, not `lifestyle.sleepHours`); `frontend/src/content/aiConsentCopy.ts` ~82–85 and header ~30–32; `AiConsentScreen.tsx` ~652; `ConsentSection.tsx` hardcoded “Removed before sending” bullet.

3. **P1 — v2.0 re-consent is claimed, not enforced.** `AI_CONSENT_VERSION = '2.0'` and `CONSENT_VERSION_NOTES` / `AI_CONSENT_RECONSENT_PROMPT` say v1.0 consents were captured under overstated anonymity and *require* re-consent (owner Q5). Nothing in this diff reads a stored consent version, compares it to `2.0`, or renders the prompt. Failure: every live client who already granted v1.0 keeps Swan Coach on under the old “anonymous” capture; only new grantors see the correction. Evidence: `frontend/src/content/aiConsentCopy.ts` ~49–55, ~140–145; `AiConsentScreen.tsx` imports only `AI_CONSENT_VERSION` for the title (`~17`, `~669`) and still ships a separate inline disclosure body (`~671+`); `AI_CONSENT_RECONSENT_PROMPT` / `AI_CONSENT_PROTECTIONS` have zero call sites in the packet.

## ATTACKS
- Correctness: `MessagingView` only consumes `capabilities.canMessageAssignedCoach` (`MessagingView.tsx` ~34–35) and never `canUseCommunityDirectMessages`, so a relationship-only user gets the full compose/search surface; writes 403, but `?composeTo=` and user-search still run. `useMessagingCapabilities` has no in-flight cancellation (`useMessagingCapabilities.ts` ~45–66): `enabled` true→false (or a refresh) can apply a stale 200 and open the composer until the next load. Conversation-scope 403s a thread whose other members were all soft-deleted (`others.length === 0`, `~238`) — fail-closed, but it also bricks a 1:1 after the trainer row is hidden. `list` scope (`~214`) is “any assignment ⇒ next”; leftover community threads remain listable (previews/names) even though open/send will 403. `resolveMessagingCapabilities` always hits assignments even for elite; the middleware does not — not a functional bug, but a second oracle for load/failure behavior. Focus trap bails forever if `containerRef.current` is null on the activating effect (`useFocusTrap.ts` ~52–54). House rule: `requireMessagingAccess.mjs` is 289 lines; `AiConsentScreen.tsx` / `ClientOnboardingWizard.tsx` were edited well past 300.

- Security: Staff bypass `role === 'admin' || role === 'trainer'` (`requireMessagingAccess.mjs` ~178) still skips membership *and* relationship before any SQL — same as old `requireTier`, so any trainer can pass the gate for any `:id`; safety is entirely the controller. `GET /users/search` remains `protect`-only (`messagingRoutes.mjs` tail) and is now reachable from the relationship-lane UI. `toId` uses `parseInt`, so `"900abc"` ≡ `900` — not a bypass by itself, but the create-scope check is on the coerced list while the controller still sees the raw `req.body.participantIds` (no sanitization). WebSocket / `useMessaging` send path is not in this packet; if sockets do not mount this middleware, the entire relationship lane is HTTP-only theater. Assignment revocation is only `status = 'active'`; a revoke that only sets `deleted_at` would keep the lane open. Kill switch `TIER_GATING_ENABLED=false` still opens community DMs for everyone. House rule “zero PII to LLMs (IDs only)” is violated by design: stable `Client #<id>` plus measurements, injuries, pain, and *all* `health.conditions` / `health.medicalConditions` are forwarded (`TRAINING_SAFETY_PATHS` ~100–116; `deIdentify` name rewrite ~245–249). Owner Q2 split does not erase the rule.

- Data-truth / schema drift: SQL shapes match the packet (`client_trainer_assignments` quoted camelCase; `conversation_participants` snake_case); the drifted `ConversationParticipants` model is still unused — good, but still a footgun. Consent SoT is a fiction: `AI_CONSENT_PROTECTIONS` is unused; `ConsentSection` and `AiConsentScreen` each hardcode bullets; `AiConsentScreen` long-form is *not* `AI_CONSENT_DISCLOSURE`. Copy says “medical conditions that affect exercise”; code forwards the entire conditions array with no exercise filter. Header comment in `deIdentificationService.mjs` ~68–76 still says DENIED includes “conditions” while `TRAINING_SAFETY_PATHS` and the dry-loop fix say the opposite — that is how the asthma regression returns. Denylist gaps vs copy: `lifestyle.sleepHours` (proven), and any `health.sleepHours` / `wellness.sleepHours` / `clientProfile.sleep` / allergies / free-text notes the builder packs. `TRAINING_SAFETY_PATHS` lists `health.medicalConditions` / `health.pain` but the keep-test only asserts `health.conditions` / `health.currentPain`. Capabilities JSON vs hook: hook requires `response.data.canMessageAssignedCoach === true`; if `api.service` already unwraps axios `data`, production fail-closes every client (tests mock `{ data: {…} }` and would still pass).
