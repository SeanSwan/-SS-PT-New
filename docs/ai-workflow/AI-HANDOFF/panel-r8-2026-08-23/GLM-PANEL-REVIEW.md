## BLOCKERS

1. **P0 — `"hooks": null` yields zero verdicts (silent clean).** `hook-registration.mjs:~170`: `if (cfg.hooks != null && (typeof cfg.hooks !== 'object' || ...))`. With `cfg.hooks === null`, `null != null` is `false`, the guard is skipped, and `Object.entries(cfg.hooks || {})` → `{}` → zero iterations → `findings: []` → the gate prints nothing. Concrete scenario: a botched merge/hand-edit produces duplicate-key JSON `{"hooks": {...real registrations...}, "hooks": null}` — `JSON.parse` accepts it (last wins), every real registration is silently discarded by the harness, and the audit reads clean. This is inconsistent with the module's own policy: `hooks: false`, `"str"`, `42`, `[]` all produce findings; only `null` is silently equated with absent. It is also inconsistent with the round-7 root guard two lines up, which explicitly names null as the worst case. The per-entry invariant survives only because the entry *set* was emptied by a malformed shape — which is precisely the 2026-08-22 outage signature, one level up, again.

2. **P1 — Fix #3's realpath containment demotes MISSING→UNVERIFIED under a symlinked root, contradicting its own comment.** `hook-registration.mjs:~104-112`: `let real = abs; try { real = realpathSync(abs); } catch { /* absent — the lexical check below still applies */ }` then `if (!abs.startsWith(resolve(root)+sep) || !real.startsWith(rootReal+sep))`. The comment's claim is false: when the file is absent, `realpathSync(abs)` throws ENOENT, `real` stays the *lexical* `abs`, and it is compared against `rootReal` — the *fully resolved* root. If any component of the root path is a symlink (macOS `/tmp` → `/private/tmp`, symlinked CI workspaces, junctions), the lexical fallback can never match `rootReal`, so the `||` fires and a genuinely missing hook file reads UNVERIFIED ("check by hand") instead of the loud MISSING alarm ("restore the file or remove the registration"). The asymmetry: file exists → realpath succeeds → matches → OK; file absent → cannot realpath → guaranteed mismatch → demoted. Every MISSING in such a checkout is neutered to the skim-category. The fix should apply realpath containment only when realpath succeeded.

3. **P2 — NBSP inside a path produces a phantom MISSING.** `hook-registration.mjs:~59`: `cmd.trim().split(/\s+/)` — JS `\s` matches U+00A0, which a shell does **not** treat as a separator. `node ./a<NBSP>b.mjs` (a real, runnable file) splits into `['node','./a','b.mjs']`; sole candidate `b.mjs` passes every decline; `statSync(root/b.mjs)` → ENOENT → healthy registration reported as "DOES NOT EXIST." Exotic input, but the module's own header names false alarms as the other way to kill the gate ("trains operators to ignore it").

4. **P2 — `process.exitCode = 0` unconditionally, findings or not.** Gate emit tail. The gate's loudest alarm ("protection is off and reads as on") exits 0; enforcement depends entirely on a human reading piped stdout — which is exactly how the 2026-08-22 outage survived for weeks ("ledger went unread"). If nonzero exit is deliberately reserved for "block the session," fine — but that contract isn't stated anywhere in the supplied code, and nothing visible distinguishes advisory from enforced.

## HIGHEST RISK
Blocker 1 (`hooks: null` silent clean) — it is the module's founding invariant broken by a two-token input, and the stated fuzz almost certainly doesn't cover it (the invariant is framed per-*entry*, and `hooks: null` has no entries; a cmd-string fuzzer passes while the audit stays silent). Cheapest de-risk: change the guard to flag null explicitly — `if ('hooks' in cfg && (cfg.hooks === null || typeof cfg.hooks !== 'object' || Array.isArray(cfg.hooks)))` — and add one audit-level property test: for every malformed settings shape in `{root non-object} × {hooks: null/false/"s"/42/[]/{} } × {groups non-array} × {group missing hooks}`, the audit must emit ≥1 finding OR the input provably registers nothing. That moves the fuzzed completeness property from entries to the audit itself, which is where all seven prior silent-cleans actually lived.
