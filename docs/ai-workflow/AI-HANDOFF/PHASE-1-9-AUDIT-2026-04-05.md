## Findings

### 1. MEDIUM - Full backend suite is red because the Phase 9 eval harness warning scenario no longer matches validator behavior

**File refs**

- `backend/services/ai/outputValidator.mjs:273`
- `backend/eval/goldenDataset.mjs:918`
- `backend/tests/unit/evalHarness.test.mjs:407`

**What's wrong**

The validator now counts self-healing corrections as warnings, but the Phase 9 `warnings_05` golden scenario still expects `0` warnings for a day with exactly 20 exercises. That scenario builds each exercise with only `name`, so self-heal adds correction warnings for missing tempo/rest data and the full backend suite fails.

This is a real regression because `cd backend; npm test` is not green anymore even though the targeted security suite is green.

**Suggested fix direction**

Pick one contract and make it consistent:

- either keep self-heal corrections counted as warnings and update the golden dataset/test expectations
- or stop counting self-heal corrections as warnings in eval assertions
- or make the warning scenarios use fully valid exercises so they only test the `>20 exercises` boundary

### 2. LOW - New Marketing and Security workspaces bypass the theme-token system with hardcoded phase colors

**File refs**

- `frontend/src/components/DashBoard/workspaces/MarketingWorkspace.tsx:74`
- `frontend/src/components/DashBoard/workspaces/MarketingWorkspace.tsx:117`
- `frontend/src/components/DashBoard/workspaces/SecurityWorkspace.tsx:68`
- `frontend/src/components/DashBoard/workspaces/SecurityWorkspace.tsx:111`

**What's wrong**

The new workspace chrome hardcodes gradient and active-tab colors with raw purple/cyan literals instead of theme tokens. That undercuts the Phase 1 multi-theme work because these surfaces will not fully follow theme changes the way the rest of the dashboard does.

This is not a compile/runtime failure, but it is a real theme-compat regression against the stated dashboard rules.

**Suggested fix direction**

Replace direct color literals in workspace shells with CSS variables using the existing `var(--token, fallback)` pattern so the new workspaces inherit theme changes correctly.

### 3. LOW - Legacy admin route metadata is out of sync with the new Marketing/Security workspace routes

**File refs**

- `frontend/src/config/dashboard-tabs.ts:401`
- `frontend/src/components/DashBoard/index.ts:90`
- `frontend/src/components/DashBoard/UniversalDashboardLayout.tsx:503`

**What's wrong**

The actual admin routes for the new workspaces live under `/dashboard/admin/marketing` and `/dashboard/admin/security`, but older exported admin metadata still points Security at `/dashboard/security` and does not map Marketing in the legacy route-title helper at all.

Today the primary sidebar uses `WORKSPACE_CONFIG`, so the main route works, but any legacy consumer still depending on the deprecated admin tab metadata or `getAdminRouteTitle()` will get stale titles or wrong paths.

**Suggested fix direction**

Update or retire the legacy exported admin metadata so all admin route maps agree on the new `/dashboard/admin/...` workspace paths.

### 4. LOW - Phase 4 rebrand is still inconsistent in the TeachMeToggle CTA

**File refs**

- `frontend/src/components/Shared/TeachMeToggle.tsx:216`

**What's wrong**

The CTA still says `Ask AI Coach for help`, which does not match the Swan Coach rebrand described in Phase 4.

This is minor and non-blocking, but it is still a visible regression in naming consistency.

**Suggested fix direction**

Rename the CTA to match the current brand language used elsewhere in the product.
