The card is released 30 seconds into a live render → next batch admitted mid-frame → VRAM contention/OOM/corrupt output — the exact hazard the module was extracted to eliminate. The caller passed the watchdog duration deliberately ("wait as long as we would have waited"); the clamp silently discards a 4000× larger value, making the argument a no-op. Either the grace must be ≥ p99 render time (i.e., bounded by the watchdog), or a short grace must be paired with actual cancellation (AbortSignal → runner kill → release on exit confirmation). Evidence: `composeGpu.mjs` clamp expression; call site in `composeStills.mjs` catch block (unnumbered).

2. **P1 — Watchdog exists on the local lane only; hosted lane can hang forever holding the reservation.** `settled = lane==='local' ? await Promise.race([syncWatchdog(...), batchWork]) : await batchWork`. If the hosted provider stalls (open socket, no bytes), `await batchWork` never settles → catch unreachable → `releaseWhenSettled` never called → reservation held until process restart, request hung, and money already committed with no refund path (monotonic ledger). Pair: **local/hosted**. Evidence: the lane ternary in the work closure (unnumbered). Fix: race a watchdog (its own bound) on both lanes, or document the provider-side timeout that makes the asymmetry safe.

3. **P1 — Async lane's reservation release has no reachable safety net; ownership is unproven.** Path: `lane==='local' && req.async !== false` → `settle.res(accepted)` → `runLocalBatch({...}).finally(() => store.delete(key)).catch(()=>{})` → `return accepted`. Unless `runLocalBatch` internally releases (not shown in the document), every async batch leaks its reservation for process lifetime — N leaks on an N-card pool silently bricks local rendering until restart. Pair: **sync/async**. One-line fix at the call site: `.finally(() => releaseWhenSettled(reservation, inFlightWork, deps.watchdogMs))` — correct regardless of `runLocalBatch` internals, and makes ownership symmetric and visible.

Unhandled error paths: catch ordering (4), swallowed async errors (3 — the `.catch(()=>{})` also means a failure between batch creation and runner start leaves a permanently "queued" batch the client polls forever; no telemetry). Happy-path-only logic: the reservation's success-path release lives entirely in the elided `... persist ...` — not shown, cannot confirm it exists. - **Security:** (a) **deriveKey collision across tenants**: the listed tuple is `{...req, brief, lane, model, count, brandKit, lawProfile, aspect}, now` — no visible user/tenant ID. If `req` doesn't carry identity, two tenants with identical briefs collide on one key → user B replays user A's cached result or coalesces into A's pending — a cross-tenant data leak. One field in the tuple settles it. (b) IDOR: `statusUrl`/`batchId` ownership checks are not shown — polling must verify the caller owns the batch. (c) Idempotency/replay: TOCTOU (5); keyless retries get fresh derived keys (`now`) by design — acceptable, but it means the client key is the *only* replay protection, which makes 5 and 7 more important. (d) DoS: `estimateOnly` bypasses caps and key dedupe entirely — verify it's rate-limited and cannot enqueue or hold capacity. (e) **PII-to-LLM rule**: `buildPrompts` consumes `brief`/`brandKit` verbatim and `deriveKey` hashes(?) raw brief text; no scrub step is shown between brief intake and the model call. GATE 1 shows a law filter, not a PII screen.
- **Data-truth / schema drift:** Response-shape drift on the same endpoint: live callers get the full result; replaying callers get `{...slimmed, replayed:true}` — the client must be built to treat payload-absent + `replayed:true` as "refetch by batchId," or the replay path crashes the frontend. Also two shapes by mode (`accepted` 202 stub vs full result) — the polling contract must be explicit. Cosmetic: `commit({ runs: count, ... })` maps `count`→`runs` — a rename waiting to drift. No table/FK drift assessable from pseudocode.

(7) Document the allowed shape delta for `replayed:true` responses in the client contract.
