The route's DoS story currently rests on a default in a file nobody reviewed.
2. **P1 — no single-flight guard + no rate limit on ingest (Q3/Q5).** Concrete: owner double-clicks → two concurrent runs → 2× platform quota, 2× `creator_item` upsert churn, and if item upserts share a transaction and `catalog.list()` returns unordered rows, cross-ordered row locks → 40P01 deadlock → receipt-less 500. 3. **P2 — enabled-count invariant false positive under READ COMMITTED (Q4).** The domain types (`'ai-discovered' | 'imported'`) anticipate creators that are NOT in the seed file. Same pattern for `subscriber_count`/`video_count`/`uploads_playlist_id` when absent from seed — a stale seed snapshot also re-asserts old counts over anything fresher. ## ATTACKS
- **Correctness (Q1, Q4, Q5):** Q1: **no reachable `enabled=true` path in the shown code** — mapper ignores it, upsert omits it from INSERT and SET, route hardcodes `actor='owner'` behind `requireRole`. Residual: the trigger authenticates an *event row*, not a session — any code able to INSERT `creator_event(actor='owner', action='enabled')` can enable; harden with `set local app.actor` + `current_setting()` in the trigger. Also: `enable_creator` must insert the event **before** the UPDATE (BEFORE trigger fires first) — ordering unstated; if reversed, every enable raises. `(xmax = 0)` insert-detection is a heuristic (freeze/aborted-updater edge cases) — acceptable here, keep the test. The 19-column/19-value positional mapping matches today, but a paired reorder in both lists passes the shape test and silently corrupts rows — consider named mapping. Q5: ingest-vs-disable leaves a benign staleness window (items land for a just-disabled creator; visibility derives from the join, so the feed stays clean — but the receipt reports success for a creator the owner believes is off).
- **Security (Q3):** no rate limit / no concurrency guard / no body-size cap / unbounded `creatorIds` array length. CSRF: cookie-session POST with no CSRF token and no content-type enforcement — safe only if cookies are SameSite=Lax/Strict (unverified); a `text/plain` body bypasses preflight and still parses as JSON. Secrets: key/token confined to env, route sees only the interface — good; but reading `SWANGUARD_TWITCH_APP_ACCESS_TOKEN` from static env contradicts the blueprint's "exchange, not .env" and guarantees silent token expiry → Twitch reported `skipped` (visible, but no ops alerting). No injection (parameterized SQL; `REFRESHABLE_COLUMNS` is a frozen const). No SSRF surface shown. IDOR: none — all `/api/creators*` owner-gated including reads, correctly.
