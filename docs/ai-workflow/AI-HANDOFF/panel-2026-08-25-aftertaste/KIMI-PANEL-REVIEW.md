## VERDICT
REVISE — the plan is structurally sound but is written against a repo state it admits is 2246 commits behind origin/main (G7), anchors to a hallucinated design-brain entry (G8), and under-specifies the one security boundary (Blender-MCP as local code execution) that can actually hurt the Owner's machine.

## BLOCKERS
1. **P1 — Blueprint written against a drifting codebase.** G7: working branch is 443 ahead / 2246 behind `origin/main`. §3.7/§3.9 name canonical objects (`CompanionPetService.mjs`, `ClientProgress.overallLevel`, Crystal Ring quality modes) whose paths and APIs the plan itself says to "assume drift." Concrete failure: P1 asset-factory proof builds manifest IDs and reward-receipt contracts against `CompanionPetService` signatures that no longer exist on main → the "no competing silo" law (G2) is violated on day one by accident. Fix: hard gate — rebase/merge to origin/main *before* P0 preproduction is finalized; re-verify G2/G5 facts post-merge.
2. **P1 — Blender-MCP threat model has mitigations but no enforcement mechanism.** §3.10 lists "work on copies, checkpoint, review generated Python, restricted network" — all manual. Concrete failure: an LLM-generated Blender Python script runs `bpy` with full user privileges; one unreviewed pass with `os.system`/`subprocess` or a phished prompt in a `.blend` exfiltrates the Owner's filesystem or deletes non-checkpointed work. "Review generated Python" does not scale past week two. Fix: run Blender worker in a sandboxed user account / container with a read-only mount of sources and write access only to an export dir; make checkpointing a pre-pass hook in the wrapper script, not a habit.
3. **P1 — Local image→3D provenance is asserted, not cleared.** §5 recommends TRELLIS/Hunyuan3D on the 5090 as a Meshy replacement, and §3.10 requires a provenance/license field in `swan.game-asset.v1`. Concrete failure: generated meshes ship in a commercial product while the model's license (and the licenses of its training-data-derived outputs) were never checked — the exact IP-separation rigor §3.5 applies to characters is not applied to the *generator*. Fix: license review of each local model is a P0-preproduction checklist item; manifest `provenance.license` must be a required, validated enum, not free text.
4. **P2 — Reward-receipt contract is named but undefined.** §3.7 specifies `swan.training-reward.v1` / `aftertaste.game-result.v1` as "signed idempotent receipts" with no schema, no signing-key location, no idempotency-key derivation, no replay window. Concrete failure: client replays a `game-result` POST → duplicate Vault loot / XP; or key lives in frontend bundle → forged receipts. Fix: define the schema, key custody (server-only), and idempotency key = hash(userId, sessionId, resultHash) in P0, even though integration is deferred — retrofitting receipt semantics after P3 is the expensive path.
