**Control flow (atomic, fail-closed):**

```
_handle_refresh(update, context):
  1. Owner gate — reuse same filter that gates existing MessageHandlers.
     If user not in TELEGRAM_ALLOWED_USERS → generic denial message, log
     "unauthorized /refresh from <sanitized chat shape>", return.
     (No capability disclosure per PC-5.)

  2. Reply immediately: "⏳ Refresh initiated — session will rebuild on reconnect"

  3. Learn/store notification recipient (PC-6):
     - Read effective_chat.id from update
     - Write ~/.hermes/runtime/notify-recipient.json atomically:
       { "chat_id_disk": <int>, "learned_at": "<UTC ISO8601>" }
       via tempfile + os.replace, mode 0600
     - Log "recipient learned: <CHAT_ID>" (NEVER log raw id)

  4. Atomic sessions.json purge (PC-2):
     a. shutil.copy2(sessions.json, sessions.json.bak-<UTC-timestamp>)
        (kept for 1 session — cleanup deferred to Sprint 5+)
     b. json.load with fail-closed: if parse fails, reply
        "❌ Session store unreadable — aborted. Check service log." and return
     c. Filter: keep every key that does NOT match ^agent:main:telegram:dm:
        Drop the rest.
     d. tempfile NamedTemporaryFile in same dir → json.dump → fsync →
        os.replace (atomic rename — crash-safe on Linux)
     e. Log "purged N keys of shape=agent:main:telegram:dm:<digits:10>"
        (shape only, never raw keys)

  5. Create PC-7 refresh marker:
     marker = {
       "request_id": str(uuid.uuid4()),
       "created_at": "<UTC ISO8601>",
       "chat_id": <int>,          # disk-only; logs show <CHAT_ID>
       "initiator_shape": "agent:main:telegram:dm:<digits:10>",
       "status": "pending"
     }
     Write to ~/.hermes/runtime/refresh-request.json via tempfile +
     os.replace, mode 0600.

  6a. PC-1 detached restart (ONLY if sudo capability confirmed at boot):
     rc = subprocess.run([
       "sudo", "-n", "systemd-run",
       "--unit=hermes-refresh",
       "--on-active=1s",
       "systemctl", "restart", "hermes-gateway.service"
     ], timeout=5, check=False).returncode

  6b. If rc != 0 (restart command FAILED to even dispatch) — SINGLE POLICY:
      - Reply: "⚠️ Restart command failed — see journalctl. Session purge already applied."
      - Atomically flip marker: reopen ~/.hermes/runtime/refresh-request.json,
        set status="failed", rewrite via tempfile + os.replace (same PC-7 shape).
      - Log "refresh restart-dispatch failed, marker flipped to failed".
      - DO NOT retry. DO NOT delete the marker here — the startup hook is
        responsible for seeing status=failed, logging "never confirming",
        deleting the file, and sending NO success push.
      - Rationale: a subsequent unrelated restart MUST NOT pick up a lingering
        pending marker and send a false "✅ Refresh complete".

  7. Return. Handler exits. If rc == 0, systemd bounces the service in ~1s and
     the boot hook confirms. If rc != 0, service keeps running; the failed
     marker prevents any future false confirmation.
```

The hook location is **UNVERIFIED** and must be resolved in §6.5 before code is written. Receipt shows `await self._app.start()` at telegram.py:684, not `run_polling()` / `run_webhook()`. Whether `ApplicationBuilder.post_init(...)` fires under this adapter's manual initialize/start sequence is **NOT assumed** by this patch doc — §6.5 must prove it empirically. **Required resolution (one of):**

- **B.** §6.5 shows `post_init` does NOT fire. Either way, **the hook must be idempotent** — it must run at every service boot regardless of why the service started (manual restart, systemd-run detached, crash-recovery).

**`boot_refresh_confirmation` behavior:**
- Open `~/.hermes/runtime/refresh-request.json` if present.
  - If absent → no-op.
  - If file `status == "failed"` → log `"refresh marker was failed, never confirming"`, delete file, no Telegram spam. (Covers the marker written by a `/refresh` whose `systemd-run` returned non-zero — see §4.1 step 6b below.)
  - If `created_at` is >5 minutes old → log `"stale refresh marker, discarded"`, delete file, no Telegram spam.
  - If `status == "pending"` AND fresh (≤5m) → send confirmation to `chat_id` via `self._bot.send_message(chat_id=..., text="✅ Refresh complete")`, mark file status=`confirmed`, delete.
  - If `send_message` raises → log, delete marker, no retry loop.

**Fail-closed invariants (rule 17 hostile review) — single policy, no ambiguity:**
- `sessions.json.bak-<ts>` written BEFORE purge → can restore if purge corrupts.
- Marker written AFTER purge (so a purge failure never produces a confirmable marker).
- Marker written BEFORE the restart call.
- **On restart-dispatch non-zero exit:** the marker is atomically flipped to `status="failed"` (tempfile + os.replace, same PC-7 shape). The marker is NOT deleted at this point.
- **Startup hook policy:** `status="failed"` → log `"refresh marker was failed, never confirming"`, delete the file, send nothing. `status="pending"` AND age ≤5m → send confirmation, flip to `confirmed`, delete. Stale >5m → log "stale", delete, send nothing.
- `send_message` failure inside the startup hook → single log, delete marker, no retry storm.

**Loop (async, 30s cadence):**

```
every 30 seconds:
  tailscale_state = run("tailscale status --json", timeout=10)
    → parse: BackendState, Self.Online, peers[*].Online for Windows peer

  bridge_state_raw = _action_status()      # remote_ai_bridge_tool.py:79
    → PER §6.7 MAPPING (not guessed here); fallback to explicit probes below
      if §6.7 shows _action_status() cannot disambiguate.

  Fallback probes (used only if §6.7 proves needed):
    ssh_ok = _run_ssh("true", timeout=10) succeeds
    tmux_list = _wsl_tmux("ls") returns non-empty

  Compute combined state (PC-3 table) per §6.7 answer:
    - "pi-tailscale-down"          if tailscale not Running / Self.Online=false
    - "desktop-peer-unreachable"   if no Windows peer Online in peers JSON
    - "ssh-bridge-unreachable"     if ssh_ok == False (or _action_status says so)
    - "tmux-missing"               if ssh_ok but tmux_list empty (or _action_status says so)
    - "healthy"                    otherwise

  If state != last_state:
    maybe_notify(old=last_state, new=state, now=<local time>)
    last_state = state

maybe_notify(old, new, now):
  # Rate limit
  if now - last_transition_sent < 60s for the same (old, new) pair: skip

  # Flap collapse
  if >3 transitions in the last 60s:
    send single "⚠️ Bridge flapping — suppressed further alerts for 60s"
    suppression_until = now + 60s
    return

  # Quiet-hours gate (Q4 LOCKED: 00:00–06:00 local time)
  if quiet_hours(now):
    if new == "healthy" or old == "healthy":
      # Bridge offline/online transitions during quiet hours
      # are queued into a wake-time digest delivered at 06:00.
      queue_for_wake_digest({old, new, at: now})
      log "bridge transition queued for wake digest: {old} -> {new}"
      return
    # Other inter-degraded-state transitions: skip entirely.
    # Rationale: Sprint 1 does not yet have N2/deploy-fail events that bypass
    # quiet hours. Bridge-state-only transitions never bypass quiet hours in v1.
    return

  # Normal-hours send
  send_message(recipient.chat_id, format_transition(old, new))
  last_transition_sent[(old, new)] = now
```
