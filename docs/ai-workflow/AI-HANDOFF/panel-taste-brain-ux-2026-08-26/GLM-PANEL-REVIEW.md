## BLOCKERS

1. **P0 — Silent capture can arm a graph Sean never chose, and the plan has no boundary on which run counts.** Three concrete scenarios: (a) Sean *deletes* `comfy-workflow.local.json` because a capture grabbed the wrong workflow, clicks Make, and step 2 silently re-captures the same run from still-live history and queues — deletion is a decision the system forgot; (b) the watcher fires on whatever ran *last*, which may be a LoRA test graph, not the `00 SWAN — H3 local` the page copy names — the message then promises one workflow while arming another (truth drift, the exact fixture-lie class this repo has a law about, `workflow.mjs:22–27`); (c) `graphFromHistory` takes the last run regardless of success (`workflow.mjs:159–166`, no `status` check; `capture-workflow.mjs:31–36` same), so a run that *errored* becomes the template and every Make 502s with node errors. Smallest fix: at click time record the history high-water mark (`max prompt[0]`), only capture runs **newer than it** and **successful**; write a tombstone on deliberate template deletion; after auto-arm, print provenance in the makebar ("armed from run `<promptId>`, N nodes, classes … — not right? Re-arm"). ~30 lines, no new surface.
2. **P1 — The held pending intent is underspecified for restart, multiplicity, and memory switch (Q2).** The only existing persistence is `intents.jsonl`, where "unrendered" is a *normal* state (ComfyUI down, drive unmounted — `pruneIntents` explicitly treats it so, `renders.mjs:163–179`), so persisting holds as plain intents means a restart auto-queues every stale unrendered intent; holding in memory means a restart silently drops a promise the page made. Two prompts held for two memories must queue FIFO against the shared template with each intent's *own* namespace (the token already binds it — `tokenFor`, `renders.mjs:60–61`), and the completion notice must name that namespace or it lands under the wrong memory bar (round-5 class). Fix: a separate `held` record `{token, profile, project, heldAt}` with TTL; watcher revalidates `nsOk` + `describe().ok` at fire time; singleton watcher, never one per click.
3. **P1 — The capture/status GETs follow redirects; only the POST is hardened (Q3's sharpest edge).** `routes-make.mjs:29` sets `redirect: 'error'` on the graph POST and documents the compromised-plugin threat (`:23–28`) — but `capture-workflow.mjs:33` and `:103` and `routes-make.mjs:67` all use default `redirect: 'follow'`. A 302 on the loopback port makes a **non-local body become the template** (`graphFromHistory` runs on attacker JSON → `land()` writes it), which is then executed locally by Make. This is the same threat the round-3 fix closed, one layer down, and step 2 makes capture *automatic*. Fix: `redirect: 'error'` plus an `r.url` origin check on every ComfyUI fetch.
4. **P1 — Judging-from-Make must route through the one judge instance (Q4).** Embedding a second grid in the Make tab forks `judge/last/seed` state and re-opens the exact misattribution the round-5 guard exists for; `probe.js` must not drift. The control should be `show('judge') + load(null)`, nothing more. Separately, a pre-existing crash window the plan widens: `onMemory` nulls `judge` (`app-judge.js:96`) but leaves `#done` enabled with `record` bound (`:54`) — clicking Done before the reload resolves hits `judge.event` on null (`:59`). ## ATTACKS
- **Correctness:** failed-run capture (Blocker 1c); zero-seed identical batches (Blocker 6); `record()` null-judge crash (Blocker 4); `load()` has no try/catch — a fetch rejection leaves the Judge tab stuck on "loading…" forever (`app-judge.js:26–42`); partial-failure batches render `first.prefix` as `undefined` when `results[0]` failed but a later prompt queued (`app-make.js:51–55`, multi-prompt only today).
- **Security:** redirect-following GET/capture chain (Blocker 3 — the one real hole; SSRF is otherwise closed by loopback enforcement `workflow.mjs:42–43`, symlink hardening via `lstat` is in place `renders.mjs:119,148`); unmounted Z: drive is a *handled* state (`renders.mjs:45–48`) but the watcher must treat "up, history empty after a restart" as *keep waiting*, never "give up and drop holds silently" (Q3); no rate limit on `/api/make` — acceptable under the loopback-by-design constraint.
- **Data-truth / schema drift:** **the page never renders `workflow.notes`** — `routes-make.mjs:60–63` computes the multi-seed/multi-prompt truth and `app-make.js:74–77` drops it, showing only "your workflow ready (N nodes)." The round-3 truth-telling mitigation exists server-side and dies at the client. New copy channels (§4) will repeat this pattern unless every field sent is a field rendered. Also: after step 3, `waiting` ("still rendering") will count *held* intents that were never queued — held ≠ rendering, and the label will lie; and the step-3 message hardcodes a workflow filename that will drift the day he renames it — list `/userdata/workflows` instead.
- **Corpus containment (Q5):** routing judging through the single `/api/probe` + `/api/event` path keeps pool law, provenance, and never-show-twice intact; the only new leak surface is explainer copy (covered in Blocker 7) and the auto-capture provenance line, which must not print corpus contents — run id, node count, class names only.

## HIGHEST RISK
Blocker 1: silent arming converts the system's honest failure mode ("no workflow captured") into silent wrong execution, in a repo whose founding law is "never queue a graph that is not his" (`workflow.mjs:4–9`). Cheapest de-risk before ship: the high-water mark + success filter + tombstone + provenance line — small, testable ("a check that fails without it" per the constraints), and it also settles Q1's ceiling: **cut step 4 entirely**. If it is ever revived, the only honest adoption path is convert → *queue as a probe* → capture what ComfyUI actually ran from `/history` → diff → adopt the **captured** graph, never the converted artifact. Build order I'd actually take: (1) labels + explainers + empty states, 44px/token-compliant; (2) "Taste pictures" = `show('judge')` only; (3) step 2 with the Blocker-1 guards, extracting `land()` into `lib/` so CLI and server share one capture path; (4) held intents + `lib/watch.mjs` singleton with TTL; (5) step 4: not built.
