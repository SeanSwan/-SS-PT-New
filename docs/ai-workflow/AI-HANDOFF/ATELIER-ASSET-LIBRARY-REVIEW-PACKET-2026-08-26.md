**Owner scoping is structural, not checked.** The query is built from `req.user.id` and the builder reads no other owner field — a test passes `ownerUserId: 9` alongside `userId: 7` and asserts the clause still says 7. There is no id to tamper with because there is no id parameter.

**Filters are an allowlist.** An unknown `kind` or `status` is `E_BAD_FILTER`, not ignored — a filter that silently matches everything while the operator believes they filtered is the plausible-wrong-answer failure, relocated into a list.

**Paging is a cursor of `createdAt|id`.** The id is not decoration: two stills from one batch share a millisecond, and a timestamp-only cursor drops one of them. `hasMore` comes from fetching one extra row and discarding it, so there is no `COUNT` over an unindexed table.

**The storage key never leaves the server.** A path is not a URL, and handing one out invites someone to build the other.

## 4. What is deliberately NOT here

- **Free-text prompt search.** The prompt lives inside `provenance` JSONB. Searching it needs a promoted column or a `to_tsvector` index — neither exists, and **neither can be verified from an environment with no Postgres**. Shipping a query I cannot execute is the dormant-code failure this lane has already paid for twice. **Trigger:** a migration that promotes the prompt or adds the index.
- **Indexes.** `MediaAsset` declares none, so every filter is a sequential scan. Fine at one operator's volume; not fine later. **Trigger:** the first time this list feels slow — which will happen long before anyone thinks to look.

## 6. What I want attacked

1. **Is withholding prompt search right?** It is the feature a person actually wants ("find the glacier one"). I withheld it because I cannot verify the query. Is "ship it unverified and labelled" better than "withhold it and name the trigger"?
2. **Tag-based filtering.** Brand, workspace, lane and seed live in a JSONB tag array (`brandkit:universal`). That is queryable and GIN-indexable, but it is also stringly-typed data in a column meant for labels. Should these be promoted to columns now, before there is data to migrate?
3. **`Op.contains` on `tags`.** I assert the clause shape; I cannot execute it. Is the shape right for Sequelize + Postgres JSONB, and does it do what I think for an *array* containment?
4. **The empty state.** It distinguishes "nothing made yet" from "nothing matches your filter" and tells the operator their other assets are still there. Is that the right anxiety to design against, or am I solving a problem nobody has?
5. **What is missing?** Selecting an asset from the library into Compose or Motion (reuse — the word in the slice name, and arguably not delivered by a *list*), deleting, bulk actions, a real thumbnail (the card currently shows dimensions, not the image), sort options, date filters. Rank them and say what you would cut.
6. **Gaps and context I may be missing** — anything about this that looks wrong from outside it.
