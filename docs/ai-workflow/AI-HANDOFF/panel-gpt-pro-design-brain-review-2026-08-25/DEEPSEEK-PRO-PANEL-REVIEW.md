## PANEL QUESTIONS
- **Q1 – Minimum first build.** Week‑1 ship: (a) catalog index with stable IDs over the 223 SREFs + 407 handles + facets; (b) `events/<session>.jsonl` append‑only log; (c) a local comparison page (127.0.0.1:7331) that shows Midjourney grid outputs Sean already generates and local‑only Midlibrary reference thumbnails, records A/B/both/neither/depends + one reason tag; (d) grill‑me visual‑taste mode that runs Q1–Q6 then hands off. Defer Bradley‑Terry, active sampler, media heads, temporal QA until ≥200 real events exist.

- **Q2 – Scoped claims.** GPT is partly right but straw‑mans several claims. The Swan corpus scopes “creative is the heavy lifter” to C13/awe surfaces and explicitly excludes in‑app surfaces (LAW 6). “2‑3 rounds” is the variant‑tournament cap, not a style‑learning limit. Personification formula, rating², and 25% floor are correctly identified as priors, not laws. The 30→60 interpolation claim is correctly debunked as non‑mandatory. The “~100× costlier” number is unsupported theatre. So GPT’s attacks are correct on the over‑claimed parts but occasionally misread scoping.

- **Q3 – Architecture.** One shared core + three media heads + project/brand overlay is architecturally correct but overkill for week 1. A simpler alternative that avoids collapse‑and‑drift: a single taste profile with a `media` tag (web/still/film) on each event and a lightweight per‑media weight mask on the same dimensions. Media heads can be computed later as derived views of the same events. The project/brand overlay is a separate policy layer, not a model head.

- **Q4 – Cheapest real comparison surface.** Midjourney grids Sean already pays for (the 4‑up grid outputs from the Forge) plus local‑only Midlibrary reference thumbnails. The Midlibrary images are copyrighted and cannot leave the machine or be committed to git, but a local‑only page (127.0.0.1:7331) that renders them directly from a private directory is legally safe as it is never distributed. Generated 256–512px candidates are an unnecessary expense when the grids already exist.

- **Q5 – TasteEvent schema.** Missing fields: `keptArtifactId` (nullable), `shipped` (boolean), `media` (the session’s medium), `candidateA`/`B` must include `provider`, `modelVersion`, `seed`, `promptHash`, `sourceHand`, `facets` (array), `references` (array), `aspect`, `contentSubject`. The schema must also support a “none” response for when neither candidate is acceptable. The write rules for themes/rejected/loved‑srefs/kept must use the same event IDs for cross‑reference. The biggest breakage: the schema currently cannot record that a kept artifact later superseded an earlier pairwise win, so the learning hierarchy is lost.

- **Q6 – Grill sequence.** The questions are mostly right, but the order should be: Q1 medium → Q2 emotional result → Q3 refusals → Q4 realism boundary → Q5 light/value → Q6 scale/camera → then the visual switch. A missing question that would most change the outcome: “When you imagine the ideal visual, what is the single most important physical property — light, material, space, or time?” (Sean’s taste is dominated by caustics/ice/water, which are light‑material interactions). The failure mode of hiding style names: if the system later reveals a style name that Sean already associates with a bad experience, it may bias future choices, and the hidden‑label promise is broken. The system must also never leak the label during the “because” reason step.

- **Q7 – What the truncated sections must contain.** The worked example must show the complete grill sequence run against Sean’s actual taste corpus, with real Midlibrary images and concrete outputs (a style direction, a set of SREFs), proving that the text questions plus visual comparisons can reliably distinguish his preferences. The 12 style suggestions must be concrete, provider‑specific SREF/handle mappings with the reasoning behind each. The action list must be prioritized, must start with the catalog index and local comparison page, and must explicitly defer the model until after event accumulation. Without these three pieces, the design is untestable.

- **Q8 – Anything else.** The review repeatedly uses academic language (Bradley‑Terry, active sampler, Gaussian processes) that will mislead Sean into thinking these are required before value appears. The “provider‑neutral GenerationSpec” is a good long‑term direction but introduces a large abstraction layer that a solo founder cannot build in week 1. The review’s P0‑1 governance‑theatre fix (machine‑readable enforcement inventory) is too heavy; a simpler fix is to delete the false claims and mark the remaining as aspirational. The review correctly identifies the absence of a visual comparison surface and the need for a catalog resolver; those are the two ship‑stopping gaps.
