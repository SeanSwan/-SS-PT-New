## VERDICT
REVISE — the architecture is honest and the disclosed failure modes are unusually candid, but there are four genuine defects (fail-open money-gate defaults, an unbounded idempotency store retaining image payloads, a taste-lane brand-scope bypass via the lawProfile override, and replay-after-cap ordering) plus one unresolved house-rule violation, none of which should ship as-is.

## BLOCKERS

1. **P1 — Fail-open defaults on the money gate and coalescing store.** `composeStills.mjs` destructures `usage = { runs: 0, spendUsd: 0 }`, `commit = () => ({ allowed: true })`, and `store = new Map()` as *defaults*. Scenario: the route (not shown) omits or misspells any one of these injections → hosted batches run with the ceiling compared against zero forever and double-clicks never coalesce, with no error anywhere — the *exact* two-lane defect `laneLedger.mjs`'s header says this codebase already shipped once, now resurrected as an API-shape footgun. Evidence: `composeStills.mjs`, `deps` destructure (`commit = () => ({ allowed: true })`, `store = new Map()`). Fix is one line: throw `E_WIRING` when `commit`/`usage`/`store` are not injected.

2. **P1 — Idempotency store leaks unbounded on every synchronous-path success.** Only two `store.delete` sites exist: the async-local `.finally()` and the catch. The hosted path and local-with-`async:false` path call `settle.res(result)` and return without deleting. Scenario: hosted lane enabled, ~100 four-up batches/day at ~1–4 MB base64 per still → each batch's *resolved result including full image payloads* is retained in the Map for process lifetime → heap exhaustion within days. Derived keys (salted with `now`) mean the entries aren't even useful as replays.

3. **P1 — Taste-lane brand-scope bypass through the lawProfile override.** `E_TASTE_IS_SWAN_ONLY` tests `lawProfile !== 'full'` where `lawProfile = resolveLawProfile(kit.lawProfile)` — i.e., the *merged* value, after the caller's explicit override already won (`registry.mjs`: `lawProfile: lawProfile || kit.lawProfile`). Scenario: `{ brandKit: 'acme', lawProfile: 'full', promptSource: 'taste' }` passes the gate → the Swan-rated corpus dresses a non-Swan brand render, silently — the precise leak the gate's own comment says "every seat of the panel named." The check must consult `kit.lawProfileFromKit` (or kit identity), not the post-override value.

4. **P1 — Spend-ledger default path silently re-mints the budget.** `DEFAULT_LEDGER_DIR = '.ai-workflow/spend'` resolves under `process.cwd()`. Scenario: any containerized deploy with the env var unset → rebuild/redeploy deletes the counter mid-day → missing file reads as a fresh day → the billed lane's daily ceiling resets with *no signal*, repeatedly, for the life of the infra. Disclosed in the header, but a money control whose *default* fails open on the most common deploy shape is a ship blocker, not a footnote. Compounded by the disclosed N-replicas = N×cap invariant. Minimum fix: refuse the billed lane when the env var is unset (fail closed on money), or detect prior-initialization-then-deletion.

5. **P2 — Replay contract broken at the cap boundary.** GATE 2 (run cap) executes *before* GATE 3a (idempotency replay). Scenario: cap 100, usage 96, first request commits 4 → 100; the user's double-click reads fresh usage, `96+4` already consumed → second click throws `E_RUN_CAP` instead of replaying — directly contradicting "a double-click must replay without touching the GPU." No overspend, but a wrong answer at exactly the moment someone is most likely to double-click. Move the `store.has` check above all quantity gates; a replay costs nothing and must never be re-judged by caps it already paid.

6. **P2 — House-rule violation: `render-agent.mjs` is 344 lines against the ≤300 cap.** Disclosed inside `laneLedger.mjs`'s docblock, and the mitigation (constructing the ledger elsewhere) keeps it from getting *worse* — but the file remains over cap and nothing in this slice retires the violation.
