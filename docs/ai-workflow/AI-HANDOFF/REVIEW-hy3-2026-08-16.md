## A. Design decisions — attacked

**1. Spend $0 fail-closed / run 50 finite — DEFENSIBLE.**
You set an explicit `run` default of 50 (a configured number, not “unconfigured”), and spend defaults to 0 which only denies *billing* providers. Free local provider reports cost `0`, not `null`, so `0 ≤ 0` passes. The literal commitment (“unconfigured cap denies”) is satisfied because both caps are configured with values. No weakening.

**2. Flagging possible real people instead of blocking — NOT DEFENSIBLE (major).**
Commitment: “no depiction of identifiable real people without consent.” Flagging relies on a human to act on the flag on every one of potentially thousands of assets. That is a control that is advisory, not enforceing. A licensor will read “filter” as block+audit. If the reviewer is tired, rushed, or the flag UI is subtle, a real person slips. **Call:** block by default, require an explicit, logged `override_with_consent` action before publish. Flagging alone is rationalizing convenience.

**3. Documented bypasses (digit/space obfuscation) pinned as passing tests — DEFENSIBLE WITH CAVEAT.**
Given a mandatory human review per asset and the false-positive cost of aggressive de-obfuscation, shipping known holes with tests that *document* them is honest. But you must surface the evasion attempt in the review UI (“prompt contained obfuscated minor term”), not just let it pass silently. If the human reviewer sees a clean pass, the hole is effectively invisible.

**4. Upload failure fails job RETRYABLY, not `uploaded:false` — DEFENSIBLE (correct call).**
Writing an `r2Key` that points to a non-existent object is a ghost record; it corrupts provenance. Preserving local GPU output and naming it in the error is the only sane path. Keep it.

**5. Provenance as JSONB on `media_assets` without DB-level immutability — NOT DEFENSIBLE (blocker).**
“Frozen” in app code is not frozen in the database. A JSONB column can be `UPDATE`d by any future admin query, ORM endpoint, or migration. An auditable commitment needs a dedicated table with `INSERT ONLY` (or a trigger that rejects `UPDATE`/`DELETE`), or at minimum a DB constraint / column-level rewrite. Right now `buildProvenance()` produces a blob that a caller with SQL access mutates after the fact. That defeats the licensor’s “durable record.”

**6. Licence gate trusts caller’s `commercial` flag — PARTIALLY DEFENSIBLE.**
You can’t know future use. But you *can* bind the flag to the generation request and freeze it in provenance, then warn that repurposing post-hoc violates licence. Current code stores it but doesn’t challenge mismatches later. Acceptable as boundary, but add a hard notice in the publish flow: “this asset was generated as non-commercial; marking commercial requires re-licence.”

## B. Attack-surface findings (ranked)

### 1. `backend/services/videoRenderArtifactUpload.mjs` · `artifactObjectKey()` · **BLOCKER**
- **Failing input:** `jobId = "../../../etc/swan"` (or any job id containing `/` or `..`)
- **Why:** Key is built as `renders/<jobId>/<leaf>` with no path normalization. A job id from the orchestrator that isn’t strict-uuid yields `renders/../../../etc/swan/file.mp4`, escaping the namespace and allowing overwrite of arbitrary objects in the bucket. The “never the client” claim holds only if job id is trusted; it isn’t guaranteed by the code shown.
- **Fix:** reject job ids not matching `^[a-z0-9-]{20,}$` before key build.

### 2. `shared/providers/video/provenance.mjs` + `backend/migrations/20260816230000-add-media-asset-provenance.cjs` (unrun) · **BLOCKER**
- **Sequence:** insert provenance → later `UPDATE media_assets SET provenance = jsonb_set(provenance, '{licence}', '"evaded"')` via any SQL console.
- **Why:** No trigger, no separate append-only table. The “frozen” record is mutable. Licensor audit expects immutable. Migration must add `REVOKE UPDATE ON media_assets FROM app_user` or use a log table.

### 3. `shared/providers/video/spendGuard.mjs` · `makeFileLedger()` · **MAJOR**
- **Failing input:** corrupt ledger file containing `{"used": "%%%"}` or truncated JSON.
- **Why:** documented fail-open reads corrupt ledger as zero. An operator (or a crashed write) can trash the ledger file, resetting usage to 0 and defeating the daily cap entirely. Bookkeeping problem becomes a compliance bypass. Should fail-closed (refuse generation) or alert + retain last known good.

### 4. `shared/providers/video/promptPolicy.mjs` · `evaluatePrompt()` · **MAJOR**
- **Naive failing prompt:** `"a kid doing pushups in a home gym"`
- **Why:** “kid” is a naive minor reference, not deliberate evasion (no digit/space tricks). If the lexicon only blocks explicit age numbers and words like “child/minor/infant”, this yields a synthetic minor and passes. Nine fixes today missed developmental-stage nouns. This is the exact class that matters.

### 5. `backend/scripts/handlers/generateVideo.mjs` · `runGenerate()` retry class · **MAJOR**
- **Misclassification:** spend-cap rejection (`E_SPEND_CAP`) is marked *retryable* because “caps expire at UTC day boundary.”
- **Why:** spend cap is `$0` default and only changes via config, not day rollover. Retrying a billing job every minute until an admin sets a number is wrong; it should be permanent (`E_BAD_CAP` class). Only *run* volume resets daily. Misclassifying spend as retryable wastes GPU and logs noise.

### 6. `shared/providers/video/spendGuard.mjs` · `checkRunAllowed()` · **MINOR**
- **Failing input:** `cap = { spend: 0, run: NaN }` or `run: -1`
- **Why:** `NaN` comparisons return false, `-1` is technically “unbounded” if code does `if (cap.run < 0) allow`. Not a third path if validated, but the described “malformed throws” likely only checks type, not `NaN`. Add `Number.isFinite`.
