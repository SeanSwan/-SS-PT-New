Round-7 correctness pass. I adopt the candidate except F4’s HOW and F13’s wrap scope. Both prescribe implementations that fail Postgres/state-machine truth on the packet’s own command and send paths.

**F4 HOW is not implementable as written.** `AiCommandAuditLog.mjs:24-91` has actor/role/target/outcome and no `action_id`, no status column, no unique idempotency key — the missing-contract claim stands. The prescribed fix does not:

- `UNIQUE(idempotency_key)` in Postgres allows multiple NULLs. Omit the key → duplicate applies. Unscoped unique also collides across actors/tenants (one client’s key denies another). Required: `idempotency_key TEXT NOT NULL` and `UNIQUE(actor_id, idempotency_key)` (or equivalent tenant-scoped pair). Packet has zero schema; this must be in the contract before any migration.
- “execute/confirm/cancel cannot both succeed” is at-most-once, not exactly-once. C6 offline retry will re-POST the same key. Correct CAS: `UPDATE … SET status=$next WHERE action_id=$id AND status=$expected RETURNING *`. Zero rows + row already in `$next` for same actor → return existing receipt. Zero rows + different terminal → conflict. Same transition must be replay-safe.
- Machine `draft→pending_confirm→applied|denied|cancelled|failed` has no recoverability transition. Constraint 2 requires wrong-client mutation to be recoverable. `useCoachCommand.ts:96,170,207` exposes only `/api/ai-command/execute|confirm|cancel`. Cancel is pre-apply. After `applied`, nothing can mint a compensating receipt.

**F14 (new MAJOR)** is that code-level gap, not a restatement of F4. Command lane cannot express undo; audit log cannot express scoped idempotent CAS. Low-risk actions may skip `pending_confirm` (`draft→applied`) but still need the same unique key + replay rule. `failed` retries must use a new `action_id` or a specified replay rule — F4 specifies neither.

**F13 HOW is the wrong call-site set.** Evidence gate names the canonical send as `CoachCommandCenter.actions.ts:203-204` (`sendMessageWithConversation`) via `useAIChat.ts:217,425,448`. Wrapping only `AITerminalPanel.tsx:116-139` leaves the mounted Coach surface’s write path with the same undefined rejection. Probe the hook first (residual g). If it does not map throw → UI failure enum, wrap every send site, including `:203-204`. Two signatures at `AITerminalPanel.tsx:116-139` (`requestContext` + `'both'` vs four-arg) remain an N2/N3 persistence-mode split; try/catch does not collapse them.

No other consensus item is rejected. Residual (f) stays residual: `AiConversation.mjs:24-83` embedded `messages` + `messageCount`/`lastMessageAt` + no version is a lost-update shape, but write-SQL is not in the packet. I will not promote it.
