**REJECT F4 “renders success only on receipt.”** Constraint 4 forbids “saved” before an authoritative write *and verification*. F4’s own enum is `draft→pending_confirm→applied|denied|cancelled|failed`. A receipt with `denied|cancelled|failed` is not success. `AITerminalPanel.tsx:116-139` already false-succeeds: it `await`s `sendMessageWithConversation` and returns with no receipt-state branch. The fix is not “any receipt ⇒ success.” The fix is: **Saved/success only on `status===applied` after verify.** `denied|cancelled|failed` render those states. `dispatchAIWorkoutEvent` boolean (`aiWorkoutEvents.ts:121-128`) still never maps to success. Do not reuse `AiCommandAuditLog.mjs:24-91`.

**New MINOR F14 — dual-write is locatable now.** `AiConversation.mjs:24-83` stores embedded `messages` *and* `messageCount`/`lastMessageAt`. That is a denormalized dual-write, not merely residual (f)’s unproven lost-update. Until write-SQL is excerpted, count/timestamp are not authoritative over `messages[]`. Write path must update all three in one transaction/statement. Residual (f) stays only for the version/CAS race.

**F3 HOW must close the token sink.** Collapse `clientId` (`AITerminalPanel.tsx:119,133`), `targetUserId` (`aiChatRoutes.mjs:308-344`), and `selectedClientId` (`aiCommandRoutes.mjs:111-145`) into one server-issued context token. `clientResolver.mjs:110-166` must existence+tenant check admins, not role-only. The token is ephemeral/server-side: never read from or written to `AiConversation.metadata` / `messages` / `status` (`AiConversation.mjs:24-83`). `status` on that model is conversation lifecycle, not the F4 receipt enum.

**F4 schema is migrate→seed→migrate.** Packet has zero receipt schema. Create a *new* receipt table in a forward migration *before* any seed; empty UNIQUE(`idempotency_key`); do not ALTER `AiCommandAuditLog`; do not seed receipts; never add UNIQUE after seeds. Denied ops cannot mint `applied`.

All other candidate clauses (F5–F9/F12, N1–N3, C6–C8, F10/F11 struck, residuals a–e) stand.
