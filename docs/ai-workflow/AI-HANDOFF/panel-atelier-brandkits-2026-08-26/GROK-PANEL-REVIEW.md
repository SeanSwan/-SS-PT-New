## VERDICT
REVISE — the kit-vs-workspace split is right, but this slice still lets a resolved kit fail to change pixels (taste), fail to constrain laws (`lawProfile` / `universal`), and fail to be recorded on the asset, which is the original “label that changes nothing” bug in a new costume.

## BLOCKERS
1. **P0 — taste path resolves a kit and then ignores it.** Inputs: `brandKit=universal` (or any future non-Swan kit) + compose mode `taste`. State: `applyBrandKit` runs only on the brief path (`composeStills.mjs:206`); taste prompts come from Sean’s Swan-rated corpus. Output: Swan art direction and Swan taste, while the request (and any resolve-at-`:102` metadata) claims a different kit. That is the incident in §1 restated: a workspace/kit that does not change the output. Refusing unknown kits (`E_UNKNOWN_BRAND_KIT`) does not help, because `universal` is known and is a no-op on this path.

2. **P0 — omitted `brandKit` default is unspecified at the only resolve site.** Inputs: every pre-existing caller that already sends `workspaceId` and does not know the new field. `composeStills.mjs:102` “resolves the kit” before paid gates; the packet only defines unknown-id → 400. Missing-id → `swanstudios` re-dresses other sites in Swan (the bug you set out to kill). Missing-id → `universal` silently strips Swan laws from production Swan renders. Missing-id → 400 breaks the existing surface. Any of the three is a ship-level behavior and none is pinned in the 12 tests as described.

3. **P1 — request `lawProfile` beats the kit, recorded only as a boolean.** Inputs: `brandKit=swanstudios` + `lawProfile=universal` (or the inverse). Output: Swan anchors under weaker laws, or full Swan laws with no Swan language; `lawProfileOverridden: true` is an audit footnote, not a control. Laws already proved they are the only thing stopping kit authors from putting CSS gold into a subject (`LAW2` incident in §2). An unprivileged override makes that protection optional.

4. **P1 — `universal` is a one-click brand-law escape hatch in the Swan UI.** Inputs: AtelierCompose picker built from `/limits` (`AtelierCompose.tsx`, 267 lines) with both shipped kits and no stated tenant/workspace filter on the client-safe view (`registry.mjs`). Output: a Swan operator selects `universal`, nothing is appended, `lawProfile=universal`, Swan brand laws do not apply. Inverse of §1, same root cause: kit identity is not scoped to who may use it.

5. **P1 — apply vs law-gate order in `composeStills` is unstated and can void LAW2.** Resolve is at `:102`; apply is at `:206`; “before any gate that costs time or money” does not say whether cheap law gates run on the pre-apply brief. Inputs: a future (or drifted) kit palette word that LAW2 would refuse. Output if laws run in `(102, 206)`: illegal brand language reaches the model, while `brandKits.test.mjs` can still pass because it never asserts compose order. You already hit this class of bug once.

## ATTACKS
- Correctness: Happy path is brief + `swanstudios`. Taste is an unhandled path, not an open question — it is a second compose product that never calls `applyBrandKit`. `universal` + taste is a type lie (kit id says “no Swan,” corpus is Swan). No stated behavior for `null` / omitted kit, wrong type, or empty string (is `""` unknown → 400, or default?). Stale state: picker from `/limits` with no described cache/ETag; a new kit can exist on the server while an old tab submits a now-valid or now-invalid id. Race: two in-flight composes with different kits share nothing obvious, but lane choice was split to `composeLaneChoice.mjs` with no kit input — a kit cannot force a lane, so hosted/gated lanes can still spend money on the wrong brand. Off-by-one: prompt concatenation order is an unmeasured model claim (Q4); not a crash, but it is a correctness claim with zero renders (`§4 NOT proven`). Error paths: unknown kit is specified; apply-after-partial-failure, `/limits` down (empty picker vs hard-coded fallback — the new test only checks “options come from the server”), and Motion (explicitly no kit) are not.

- Security: Authz/IDOR — any caller who can compose can apparently send any allowlisted kit id; no per-tenant binding, so Swan look can be requested for a non-Swan filing label and `universal` can be requested for Swan. Injection — operator words are placed first *because* the front of the prompt is believed to dominate, which is an operator-wins prompt-injection stance against the brand suffix; kit copy itself is code-reviewed, so catalogue injection is low. SSRF — none in this slice. Secrets — scan CLEAN; nothing here should hold keys. Replay/idempotency — re-posting the same brief with a different kit is a different image and there is no mention of an idempotency key that includes kit id, so retries can change brand. Multi-tenant scope leak — `workspaceId` remains free text and unread for art direction; the client-safe view of the catalogue is the leak surface (anchors, palette words, law profile names) if `/limits` is global. Rate-limit/DoS — resolve is in-process and cheap; `universal` does not reduce spend, and per-kit budgets are explicitly absent, so the new picker does not change cost-DoS.

- Data-truth / schema drift: You split the concepts and then declined to persist the new one. Asset rows still get `workspace:whatever-you-typed` and (as you list in Q5) do not store which kit rendered. After this ships, the DB cannot answer the question the feature exists to ask. PascalCase/camelCase: packet uses `workspaceId`, `lawProfile`, `lawProfileOverridden`, `E_UNKNOWN_BRAND_KIT`; the compose POST field name for the kit is never given (`brandKit` vs `brand_kit` vs `kitId`). Frontend shape: picker from `/limits` / client-safe view — one new test asserts option source, not that the selected id is the same field compose resolves at `:102`. FK target: none, because this is a module pretending it will never need a table; the moment a kit id is written onto an asset (which it must be), you have a string FK to a code allowlist with no migration story. Response-shape: `lawProfileOverridden` is recorded “in the result” with no guarantee the library, queue chunk, or `CreatorRenderQueue` sibling ever sees it. House-rule surface: new Brand picker in `AtelierCompose.tsx` (267) is silent on styled-components, Dual-Button Glow, 44px targets, dark-first, WCAG 4.5:1, and `var(--token,#fallback)`. That is not proof of a violation; it is a packet that cannot be approved against binding UI law.
