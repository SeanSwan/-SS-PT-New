Round-3 correctness attack (state machines, races, FK/identity, Postgres predicates). Consensus candidate is mostly right on the write-path holes; two of its proposed contracts are wrong as written, and three additional races/FK gaps are not covered.

**Adopted (evidence holds).**
F1 is a real double-execute / confirm-after-cancel hole: `AiCommandAuditLog.mjs:24-91` has actor/role/target/operation/outcome/hash and **no** `action_id` unique key; `useCoachCommand.ts:96,170,207` are three independent HTTP verbs with no cited status predicate. F6 is the same class of bug on proposals (`coachProposalRoutes.mjs:30-54`): packet claims a pending-row claim but does not show `UPDATE … WHERE status='pending'` + terminal receipt in one transaction — concurrent approve/reject is a lost update. F2 (capability check after `commandExecutor.mjs:309-343` resolve, deny must write audit and return a denial shape) is the missing pre-execute state. F4/F8/F10 match constraint 4/2 and the cited execute-with-no-gate / event-boolean / debate start path. F5/F7/F9/F11 stay as written. Express specific-before-prefix at `routes.mjs:630-634` is not a defect.

**REJECT F3 as written.** Blanket `400 TARGET_REQUIRED` on null targets is a correctness bug in the fix. `CoachCommandCenterPage.tsx:34-43` makes `isClientMode` first-class; `AITerminalPanel.tsx:116-139` sends `clientId || null` as the normal path; chat creation accepts `targetUserId` only for admin/trainer (`aiChatRoutes` `:308-344`). Client self-service **must** bind `targetUserId = auth.userId` and `403 TARGET_FORGED` any other supplied target. Admin/trainer null/unresolved → `400 TARGET_REQUIRED`. Receipts echo alias + resolved user PK. One canonical field: `targetUserId` (user PK). `selectedClientId` / `clientId` are aliases only.

**REJECT “admin unbounded scope accepted as intentional”.** Constraint 2 forbids unbounded **writes**. `clientResolver.mjs:110-166` scoping trainers but not admins may be policy for **READ/list only**, and only if every such row is audit-tagged. Admin WRITE still requires F3 explicit target + F2 capability. Treating write-unbounded as intentional would legalize wrong-client mutation.

**New MAJORs (correctness lens).**
F12: `AiConversation.mjs:24-83` stores `messages` + denormalized `messageCount` on the conversation row. `useAIChat.ts:425,448` POSTs messages. No version/CAS/child-table append is in the packet. Concurrent posts are a JSONB lost-update. Fix: `ai_conversation_messages(conversation_id FK, seq)` with `UNIQUE(conversation_id, seq)` and monotonic `INSERT`, or a single `UPDATE … SET messages = messages || :msg, message_count = message_count + 1, version = version + 1 WHERE id=:id AND version=:seen RETURNING version`. Probe: two concurrent POSTs must both persist.

F13: `aiCommandRoutes.mjs:111-145` execute and `coachProposalRoutes.mjs:30-54` apply are two live write authorities on the same Coach surface with no shared `actionId`, per-`(targetUserId, resource)` lock, or receipt stream. Concurrent command-execute + proposal-approve can diverge domain state (constraint 2/3). Fix: one sequencer/outbox per resource; both lanes mint the same receipt shape; second writer hits the F6-style predicate and returns the stored receipt or `409 CONFLICT`.

F14: no FK/lineage from intake (`coachIntakeRoutes.mjs:23-33`) to proposal (`coachProposalRoutes.mjs:30-54`). Apply can orphan or resurrect purged health intake — not recoverable (constraint 2). Fix: `proposals.intake_id` nullable FK `ON DELETE RESTRICT`; apply aborts if intake missing/expired; audit copies intake id.

**Endorse remaining fixes (apply as specified).**
- F1 `AiCommandAuditLog.mjs:24-91`: add `action_id UUID NOT NULL UNIQUE`. Executor: `INSERT … ON CONFLICT (action_id) DO NOTHING RETURNING *`; on conflict return stored receipt, do not re-run side effects. Confirm: `UPDATE … WHERE action_id=:id AND status='pending_confirm'`. Cancel: `UPDATE … WHERE action_id=:id AND status IN ('queued','pending_confirm')`. Terminal replay returns stored row. `target_user_id` FK `users(id) ON DELETE RESTRICT`.
- F6 `coachProposalRoutes.mjs:30-54`: one txn `UPDATE … SET status='applying', action_id=:id WHERE id=:pid AND status='pending' RETURNING *`; rowcount 0 → read terminal row and return idempotent receipt or `409`; then domain apply; then `applied`/`failed`. Crash reconcile: `applying` older than T.
- F2 `commandExecutor.mjs:309-343`: after resolve, before mutate, registry check; deny writes audit `outcome=denied` and returns denial shape (never a success receipt).
- F4: IndexedDB queue keyed by `actionId`; UI ∈ {queued, sending, verified, failed, cancelled}; reconcile replays exactly once against F1.
- F5: do **not** clone chat middleware blindly; publish a per-lane parity table (rate, PII, TTL) and apply matching gates to `coachIntakeRoutes.mjs:23-25` and `coachProposalRoutes.mjs:15-16`. Health intake TTL ≠ proposal TTL.
- F8: cite the review-gate on the execute path or strike the header claim. `CoachCommandCenterPage.tsx:34-43` is role derivation only.
- F10: `ensureClientAccess` on `aiDebateRoutes.mjs:57-76` before job create.
- F7/F11/F9 as consensus.
