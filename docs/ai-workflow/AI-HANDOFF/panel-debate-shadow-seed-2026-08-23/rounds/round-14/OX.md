Fresh-eyes pass, round 14. I held the remit lens: hunt for the defect *class* the running consensus structurally cannot see. I found it, and it is one family appearing twice: **association-direction/type blindness** — every place the packet touches `model.associations` treats any association as if it were a `belongsTo` owned by this model. The consensus has been patching *symptoms* of this class (fix (1) adds attribute-derived parents on top of a corrupt walk; fix (3) patches the read side) without naming or removing the class.

**F1 — NEW MAJOR: `normalizeModel` resolves FK targets through a type-blind association lookup.**
In `backend/scripts/seed-shadow-db.mjs`, `normalizeModel()`: `const found = Object.values(assocs).find((x) => x.foreignKey === col);` matches the FIRST association whose `foreignKey` string equals the column — regardless of `associationType`. A `hasMany(C, { foreignKey: 'tenant_id' })` declared on model M stores `foreignKey: 'tenant_id'` even though that column lives in C, not M. If M *also* has a local column `tenant_id` with `references` (shared FK-column naming is routine across 217 models), the `.find` hits the hasMany first, and `entry.foreignKeyTarget.table` is set to C — the wrong parent table. Downstream: `generateRowValues` pulls ids from the wrong `insertedIds` slot, and the section-4 cycle bookkeeping (`fkColsOf`) keys off the same corrupt target. Fix: constrain the lookup to `x.associationType === 'BelongsTo' && x.foreignKey === col` (hasOne/hasMany/belongsToMany foreignKeys live on the *other* model or a join table and must never resolve a local column). One-line change, locatable at the `.find` in `normalizeModel`.

**F2 — REJECT consensus fix (1) as insufficient; the §3 deps loop defect survives it.**
Fix (1) hoists `tableNameToModel` and *adds* attribute-derived parents after the associations walk — but the walk itself (`for (const a of Object.values(m.associations || {})) … parents.add(a.target.name)`) is left intact and still adds every hasMany/hasOne target as a parent of THIS model, i.e. inverted edges. Concrete failure path in the packet: `User hasMany Post` + `Post belongsTo User` yields `deps(User)={Post}` and `deps(Post)={User}` → spurious 2-cycle → both land in `cycleSet`; any third table with a **non-nullable** FK into either gets `allBlocked` → `skipped.push({table: nm, reason: 'FK cycle with no nullable edge…'})` (section 4 cycle-skip branch) — a perfectly seedable table silently dropped from the shadow DB, weakening exactly the gate this project exists to strengthen. Correct fix: delete the associations walk entirely and build `parents` solely from `meta.get(nm)` entries with `foreignKeyTarget` (after F1's BelongsTo-only repair, attribute-derived edges are complete: every FK column resolves via associations-or-`references` fallback in `normalizeModel`). Adding correct edges on top of inverted ones is not a fix.

**F3 — NEW MAJOR: acceptance criterion 2 still has no executing witness, and the consensus FIX ALL silently dropped it.**
The running state carries "workflow runs neither seed-shadow-db.test.mjs nor the pure-Node selftest anywhere," yet the consensus candidate contains no fix for it — an unresolved finding laundered into silence. Evidence: `.github/workflows/migration-shadow-check.yml` steps run `pre-migrate-guard`, `migrate`, seed, assert, migrate, import — no `vitest`, no `node scripts/seed-shadow-db.selftest.mjs`. Brief §7 criterion 2 ("test suite passes and covers every case in 5.2") is therefore unverifiable in the very gate that ships. Fix: add a step immediately after "Install backend dependencies": `working-directory: backend; run: node scripts/seed-shadow-db.selftest.mjs` (dependency-free by design — DELIVERABLE 3 header — so the rollup-native-binary blocker cannot touch it). Without this, the safety-gate regressions the suite pins are unprotected in CI.

**F4 — MINOR: skip/fail diagnostics never reach the uploaded artifact.**
The Seed step (`run: node scripts/seed-shadow-db.mjs --rows 5 > seed-shadow.log`) redirects stdout only; `console.error('SHADOW-SEED SKIP …')` and `SHADOW-SEED FAIL …` go to stderr, so `upload-artifact` (path `backend/seed-shadow.log`) archives a log missing the skip/fail reasons the report JSON summarizes. Fix: `> seed-shadow.log 2>&1`.
