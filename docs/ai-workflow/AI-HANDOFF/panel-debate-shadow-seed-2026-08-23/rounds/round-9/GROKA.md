The packet’s control flow is a single-thread state machine: safety gate → load models → build deps → Kahn order → insert (NULL on cyclic edges) → backfill → COUNT → one report line. Every MAJOR below breaks a transition on that path or the Postgres contract the workflow claims to implement.

**(1) Deps graph is associations-only.** `seed-shadow-db.mjs` §3 walks `m.associations` into `parents` and never reads `normalizeModel`’s `foreignKeyTarget`. `tableNameToModel` is built *after* that loop, so it cannot be used there. Attribute-level `references` without a matching association are invisible to Kahn: child can insert before parent → NOT NULL/FK violation → `failed[]` or an empty table. `normalizeModel` already resolves `a.references.model` when no association exists; the graph ignores that output.

**(2)+(3) Single-column PK assumption is load-bearing and wrong.** §4 `pkCol = Object.keys(attrs).find(c => attrs[c].pk)` plus `updateOnDuplicate: [pkCol]` plus `values.map(v => v[pkCol])` stores scalars. `generateRowValues` then does `out[col] = parents[rowIndex % parents.length]` (whole slot). That is only correct while slots are scalars. Composite PK: conflict target is incomplete; `insertedIds` drops every PK column after the first; a child FK cannot address `foreignKeyTarget.pk`. §4b computes `tPk` and never uses it; it reads `insertedIds.get(bf.targetLower)?.[0]` (scalar) and writes that into the FK. Self-cycle and 2-cycle backfill therefore cannot target a named parent column. `insertedIds` is a `Map` — the fix must use `.get()`, not `insertedIds[targetLower]`. Tests/selftest pass scalar arrays (`{ users: [1,2,3] }`, `{ users: [p0,p1] }`); after maps, those readers assign `undefined` unless fixtures become `{ users: [{ id: … }] }`.

**(4) Postgres auth vs the file’s own comment.** `.github/workflows/migration-shadow-check.yml` L15–L16: user/password/database are the literal word `shadow`. L25: `POSTGRES_PASSWORD: "***"`. Brief §4 same contract. Quoted `***` is a real password, not a YAML alias. Export `DATABASE_URL` is redacted in-packet; if it uses `shadow`, migrate/seed cannot authenticate; if it uses `***`, the job can go green while violating the brief. Builder header (“`***` alias bug caught and quoted”) contradicts both the comment and §4.

**(5) Assert grep is order-dependent, not format-wrong.** Seed stdout is `SHADOW-SEED OK …`, optional `SHADOW-SEED cycle-backfill …`, then `serializeReport` → `SHADOW-SEED {"tables":…}`. Current `grep '^SHADOW-SEED ' | tail -1` works only because the JSON line is last. `^SHADOW-SEED {` matches that line (space then brace) and does **not** match OK/cycle-backfill. The running-state claim that the tighter pattern “would not match (space before brace)” is false.

**(6)** `backend/vitest.config.mjs` L34–L35 `retry: 1` lets a deterministic suite pass on a second try. Delete it.

**(7)** §4 `backfill.push` is inside the per-row loop; §4b `UPDATE … WHERE col IS NULL` already fills every NULL on the first execution. Dedupe on `(table,col)` before UPDATE.

SQLi: `countRows` quotes `plainTable` after stripping `"`. Not user input. No injection finding. No race: one connection, sequential `bulkCreate`/`update`. Residual holes after the seven fixes: FKs expressed neither as attributes nor associations; `normalizeModel` still `.find`s the target PK (should prefer `association.targetKey`); `getTableName()` object form if any of the 217 models set `schema`; skipped hard-cycle tables stay empty for migrate-2.
