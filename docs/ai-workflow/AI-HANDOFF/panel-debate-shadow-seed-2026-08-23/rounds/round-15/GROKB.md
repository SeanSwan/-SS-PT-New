**False-success surface (CI).** Step order is the one brief §5.3 required: `npm ci` → migrate (empty) → seed → assert → migrate (with data) → import. Ordering is not the bug. The assert and the artifact are.

`.github/workflows/migration-shadow-check.yml` Seed step is `node scripts/seed-shadow-db.mjs --rows 5 > seed-shadow.log` (stdout only). Assert then does `grep '^SHADOW-SEED ' | tail -1`. The seeder writes three stdout prefixes: `SHADOW-SEED OK …` (per table), `SHADOW-SEED cycle-backfill …`, then `SHADOW-SEED {…}`. `tail -1` is print-order luck, not a contract. Tighten to `grep '^SHADOW-SEED {'`. Seed must be `> seed-shadow.log 2>&1` so `SHADOW-SEED SKIP` / `FAIL` / `REFUSED` (all `console.error`) land in the uploaded artifact.

No workflow step runs `node scripts/seed-shadow-db.selftest.mjs`. Acceptance criterion 2 is therefore unenforced in the only job that can go green on a silent no-op. Add that step after `npm ci`, `working-directory: backend`. Do not add vitest here — builder already recorded the rollup native-binary block; the selftest is the dependency-free gate.

**Trust boundary (password).** Workflow comment L15–19 and brief §4 say user/password/database are the literal word `shadow`. L25 is `POSTGRES_PASSWORD: "***"`. DATABASE_URL is redacted, so pairing is unprovable from the packet; the file contradicts itself. Set L25 to `"shadow"` and make the exported URL password `shadow`. Mismatch is fail-closed (migrate cannot connect) — still a broken contract, not a silent green.

**Data-truth (deps / FKs / PKs).** `main` §3 builds `deps` with `for (const a of Object.values(m.associations || {})) parents.add(a.target.name)` — HasMany/HasOne/BelongsToMany become reverse edges, so almost every real pair is a false 2-cycle. Insert then NULLs FKs and backfills only nullable edges to parent row 0. `normalizeModel` resolves targets with `Object.values(assocs).find((x) => x.foreignKey === col)` with no `associationType === 'BelongsTo'` guard. Delete the associations walk; build deps only from `meta` attrs that have `foreignKeyTarget` (after 1a). Move `tableNameToModel` above that loop so table names map back onto topo nodes.

`pkCol = Object.keys(attrs).find(c => attrs[c].pk)` plus `updateOnDuplicate: [pkCol]` plus `insertedIds.set(tLower, pkCol ? values.map(v => v[pkCol]) : [])` is three defects in one: composite PKs drop columns; FK assignment writes a scalar (`out[col] = parents[i]`) instead of `parentRow[a.foreignKeyTarget.pk]`; a pk-less parent stores `[]`, so `insertedIds.has(tLower)` is true and the backfill push (`v[c] === null && !insertedIds.has(tLower)`) never fires — child FK stays NULL. Store full row maps; point generate/backfill at `foreignKeyTarget.pk`; drop the unused `tPk` `.find`. Update vitest/selftest `parentIds` fixtures to row maps (`{ users: [{ id: p0 }, { id: p1 }] }`). Dedupe `backfill` on `(table,col)` — the UPDATE already writes every NULL row, so N duplicate entries are wasted extra writes, not extra correctness.

**Leave alone.** `vitest.config.mjs` `retry: 1` is inert on this deterministic suite. Selftest has 32 `ok()` calls; the 32/32 claim stands on the current code. PII guard, deterministic generation, synthetic-over-snapshot remain accepted intentional. F5/F6 stay deferred — `validateShadowUrl` only reads `new URL(url).hostname` and `/shadow/i` on the raw string; `database.mjs` is not in this packet, so a `?host=` override is not a locatable connect-time defect this round.
