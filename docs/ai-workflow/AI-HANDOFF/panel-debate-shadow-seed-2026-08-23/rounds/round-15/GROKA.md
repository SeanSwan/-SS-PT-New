The §3 association walk is a graph-polarity bug, not a style issue. `HasMany`/`HasOne`/`BelongsToMany` edges are recorded as *parents*, so every typical Sequelize pair (`belongsTo` + inverse `hasMany`) becomes a 2-cycle. `cycleSet` then treats required child FKs as hard-cycle edges and `continue`s the child. Parents still insert, `dbRows > 0`, CI greens, and migration run 2 still sees empty child tables — the exact silent-green failure mode the brief forbids.

`normalizeModel()` compounds it: `Object.values(assocs).find((x) => x.foreignKey === col)` accepts the first association with that key, including non-`BelongsTo`. Deps must be rebuilt only from `foreignKeyTarget` *after* that lookup is restricted.

Scalar `insertedIds` plus `pkCol = Object.keys(attrs).find(...)` is wrong for composite PKs and for pk-less parents (`set(t, [])` makes `insertedIds.has(tLower)` true so the backfill push never fires). Store inserted row objects and read `parentRow[foreignKeyTarget.pk]`.

Workflow L25 password `"***"` contradicts the comment that user/password/database are all `shadow`. Auth fails or the “named shadow” contract is a lie. Assert `grep '^SHADOW-SEED '` matches `SHADOW-SEED OK` / `SHADOW-SEED cycle-backfill`; tighten to `'^SHADOW-SEED {'`. Seed redirect drops stderr. No CI step runs the 32-check selftest.

Adopting the candidate. Applying (3) as full row maps (not PK-only) so unmarked `references.key` columns still resolve. Build `tableNameToModel` *before* the deps loop.
