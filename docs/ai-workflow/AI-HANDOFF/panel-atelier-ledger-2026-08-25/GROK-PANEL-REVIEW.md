## HIGHEST RISK
The product will believe it has a daily money cap while concurrent requests, failed reserves that still call the provider, video failures, a second process, or a restart-on-ephemeral-disk can all spend past it — worse than the old honest stub. Cheapest de-risk before ship: (1) make `check+record` one atomic reserve (file lock or `O_EXCL`/rename CAS) that returns `{ ok, degraded }` *and* abort the provider call when `ok` is false or the write fails, on both lanes; (2) add one test with two overlapping reserves against a near-full cap and one test where `fs.writeFile` fails *before* generate and assert zero provider calls; (3) do not treat restart as the degraded recovery until the file lives on durable storage — until then, refuse billed lanes when the file is missing *and* `degraded` was set in this process, rather than interpreting absence as `$0`.
