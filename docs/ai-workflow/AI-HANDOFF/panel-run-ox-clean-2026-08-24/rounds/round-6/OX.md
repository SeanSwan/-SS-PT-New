## Round 6 — Ox Alpha (fresh-eyes adversarial)

I adopt the consensus candidate as the base ruling, but applying a fresh-eyes pass to the *fixes themselves* (not just the original findings) exposes three defect classes the prior rounds structurally missed: the proposed idempotency fix is unimplementable as written, its uniqueness scoping is a tenancy hole, and the argument-drift fix covers the wrong (or rather, an incomplete) set of call sites.

### New findings

**F5 (MAJOR) — The F1 fix cannot satisfy its own acceptance criterion.** The consensus says: add `commandIdemKey` to `AiCommandAuditLog` (L24-91) and "reject duplicate submissions with the original receipt." But the packet's own receipt-boundary section states the audit log records "actor, role, resolved target client, operation ID, outcome, error code, parameter hash/redaction, and duration" (`backend/models/AiCommandAuditLog.mjs:24-91`) — **no response payload**. A duplicate POST replaying the same key must return the *original* receipt (AC #1); an outcome/error-code row cannot reconstruct it. The fix as scoped guarantees a duplicate is detected but returns a fabricated or empty receipt — violating packet constraint #3 ("durable action receipts are truth"). Fix: extend the model with a `receiptPayload` JSONB column (or a sibling `AiCommandReceipt` table keyed by the same composite), written transactionally with the audit row on first execution.

**F6 (MAJOR) — Bare `UNIQUE(commandIdemKey)` is a cross-client denial-of-service vector.** The consensus specifies "a `commandIdemKey` UUID UNIQUE column." Global uniqueness means any authenticated caller can pre-insert (or race-insert) another user's client-generated key, causing every legitimate submission of that key to be "rejected with the original receipt" — i.e., the attacker's receipt. Packet constraint #2 (wrong-client mutation catastrophic, least privilege) makes this a tenancy boundary defect in the fix itself. Fix: composite `UNIQUE(user_id, commandIdemKey)` on the model (L24-91), and the executor's duplicate lookup must filter on the authenticated actor, not the key alone.

**F7 (MAJOR) — F2's scope misses the canonical call site.** The consensus fixes argument drift only in `AITerminalPanel.tsx:124-133`. But the packet's canonical-surface receipt identifies a second positional call into the same fragile signature: `CoachCommandCenter.actions.ts:203-204` calls `sendMessageWithConversation` (per the Consumer hook/service row), and `CoachCommandCenter.controller.ts:42` consumes `useAIChat`. AC #2 ("a test proves both branches of AITerminalPanel send identical context/mode") therefore certifies the *non-canonical* shared shell while leaving the canonical `CoachCommandCenterPage` path untested for the exact drift class F2 exists to kill. Fix: `buildChatParams` must be defined once (e.g., in `frontend/src/hooks/useAIChat.ts` alongside the typed signature the consensus already flags as residual risk) and consumed at both `AITerminalPanel.tsx:116-139` and `CoachCommandCenter.actions.ts:203-204`; AC #2 must assert identical context/mode across all call sites of `sendMessageWithConversation`.

**F8 (MINOR) — Check-then-insert idempotency is racy and offline-hostile.** "Enforce insertion idempotency in the command executor" implies an application-level existence check before insert — a TOCTOU window under concurrent duplicate POSTs (packet probe table explicitly demands "replay/concurrency" verification for proposals; the same applies here). Fix: rely on the composite unique constraint's violation path (insert-first, catch conflict, read original receipt) inside `commandExecutor.mjs` near the resolve step (L309-343 region). Additionally, because packet constraint #6 requires an offline/degraded gym-floor story, the client-generated key must be persisted locally at intent-creation time (not at send time), or a crashed tab retry mints a new key and defeats dedup entirely.
