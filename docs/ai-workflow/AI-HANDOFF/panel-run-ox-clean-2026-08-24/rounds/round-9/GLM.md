## B. Candidate fixes, line by line

**F1 — AMENDED (MAJOR defect in the fix as written).** Candidate: UNIQUE `commandIdemKey` on `AiCommandAuditLog.mjs L24-91`, "reject duplicates with the original receipt." Schema truth: the model at L24-91 records `outcome` and `error code` — i.e., the log is the record of *attempts including failures*. A UNIQUE key on every row means a transient 5xx permanently fences the command: the retry gets the failed receipt back, violating constraint 2's "recoverable" and the candidate's own criterion (1), which never splits outcomes. Fix: nullable `commandIdemKey`, UNIQUE partial index over CONFIRMED rows only; FAILED/CANCELLED attempts append audit rows without the key; duplicate POST → CONFIRMED returns original receipt with no new row and no re-execution, PENDING returns 409, FAILED permits retry. Execute+receipt must be atomic (transaction or pre-claim row) — packet is silent on the DB engine, so this is an implementation gate, not an assumption.

**F5 — AMENDED (MAJOR defect in the fix as written).** Candidate: "reject any command without a validated target client."
