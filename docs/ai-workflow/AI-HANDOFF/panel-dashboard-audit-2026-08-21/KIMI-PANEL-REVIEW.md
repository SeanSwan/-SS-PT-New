## HIGHEST RISK
The fake-save (blocker #1) guarded by the fake test (blocker #3). It destroys user data silently *and* demonstrates the test suite cannot be trusted to catch regressions of the fix. Cheapest de-risk before ship: (1) delete the noop fallback — make `onUpdateProfile` required and let the absence be a compile error, not a runtime lie; wire `dashboard.updateProfile` at both mount sites (the function already exists at `:218`); (2) in the same PR, replace the regex contract test with one that renders `UserSettingsHub` with no callback and asserts `apiService.put('/api/profile')` fires; (3) run a census of every `*.contract.test.ts` for `readFileSync` — quarantine any that grep source. That's a day of work and it closes the hole *and* the meta-hole.
