## VERDICT
REJECT — The proposal fundamentally misunderstands the nature of the ComfyUI MCP (it is a stateful, interactive agent interface, not a deterministic API), and the "Multi-Project" schema change (P5) is architecturally impossible without a complete rewrite of the existing FK-coupled queue, making the "blueprint" a fantasy rather than a plan.

## BLOCKERS
1. **P0: MCP Mischaracterization (Security/Correctness).** §3 and §4 treat the MCP as a "control plane" for deterministic operations. The MCP is an LLM-driven agent interface designed for *reasoning* about workflows, not for executing them in a production pipeline. Using it to "install nodes" or "diagnose errors" in a multi-tenant SaaS context creates a massive attack surface (prompt injection via workflow names, arbitrary code execution via node installation) and violates the "zero PII to LLMs" rule if the MCP context includes user project data. The MCP is for *operators* (Sean), not for the *application*.
2. **P0: Multi-Project Schema Drift (Data-Truth).** §2.2 explicitly states `videoJobQueue.mjs` and `renderAgentRoutes.mjs` are FK-coupled to SwanStudios. §4 P5 proposes "Multi-project is the schema change." This is not a change; it is a migration. The existing `contentStudioRoutes.mjs` (167 ln) and `videoRenderJobService.mjs` assume a single tenant context. There is no evidence in the document of a `project_id` column in the queue, assets, or brand kits. Proposing this as a "blueprint" without a migration plan for the existing 4,618-file brain-vault and the live queue is a P0 blocker.
3. **P1: "Comfy Cloud" Credit Leakage (Security/Finance).** §4 P3 suggests registering Comfy Cloud partner nodes as "ordinary hosted providers." Comfy Cloud credits are tied to the *user's* ComfyUI instance and API key, not to a SaaS backend key. If SwanStudios acts as a proxy, it must hold the user's Comfy Cloud API key. Storing third-party API keys in a SaaS backend without explicit, encrypted, user-managed key rotation is a P1 security failure. The "spendGuard" in §2.1 is local; it cannot enforce limits on a remote credit balance unless the backend polls the Comfy Cloud API for every request, which is not described.

## ATTACKS
- **Correctness:** The "Describe -> Brief -> Still -> Video" ladder (P4) assumes a linear, deterministic flow. ComfyUI workflows are graph-based and non-linear. A "Brief" generated by an LLM (Swan Brain) is unstructured text. Converting this to a ComfyUI graph requires a *code generation* step (LLM -> JSON), which is highly error-prone. The proposal lacks a "Graph Validator" step that checks the generated JSON against the installed nodes *before* submission. If the LLM hallucinates a node name, the job fails silently or crashes the local worker.
- **Security:** IDOR risk in Multi-Project. If `project_id` is added to the queue, does the `renderAgentAuthService` token scope include `project_id`? If not, a user with a valid token for Project A could submit a job to Project B's queue if the backend only checks token validity, not project ownership. The document does not mention updating the auth service to be project-scoped.
- **Data-truth / schema drift:** The "Brand Kit" (P5) is new. The existing `contentStudioRoutes.mjs` does not have a `brand_kit` table. The "Taste Brain" in §2.4 is a *file-based* vault (`~/hermes2/brain-vault`). Moving this to a relational DB for multi-project support requires a massive ETL process. The proposal ignores the cost of migrating 4,618 files into a structured, queryable brand kit schema.

## HIGHEST RISK
The highest risk is **operational complexity leading to abandonment**. Sean wants a "creation tool," but the proposal adds a complex multi-project schema, a new MCP integration, and a new "Compose" UI on top of an already complex local worker system. The "Doctor" surface (P6) is a maintenance burden, not a feature. The cheapest way to de-risk this is to **drop P5 (Multi-Project) and P1 (MCP as control plane) entirely.** Instead, build a simple "Project Selector" dropdown in the existing UI that filters the *existing* single-tenant queue by a `project_tag` string field (no schema change, just a column add). Use the MCP *only* for Sean's local debugging, not as part of the SaaS product.
