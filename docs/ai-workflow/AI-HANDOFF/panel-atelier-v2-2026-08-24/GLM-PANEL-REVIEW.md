## BLOCKERS
1. **P0 — No mutual exclusion between the MCP and the live queue.** Scenario: 4-minute local render in flight on the 5090; Doctor (P6) uses MCP server-lifecycle (§3: "start/stop, needed when installing new nodes") to restart ComfyUI for an install; `comfyuiLocal.generate()` times out; `generateVideo.mjs` retry classification (§2.2) marks it retryable; second dispatch duplicates render, artifacts, and (on a partner route) spend; provenance records two runs for one job. Evidence: §3 lifecycle ops + §2.2 queue/agent files + P1/P6. Fix, which also answers §5.1: P1 is right — the strongest counter-case is a self-healing hot path (diagnose→repair→retry mid-job), but that value is captured without nondeterminism by making MCP repairs land as *new versioned manifest entries* that a human/Hermes gate approves and the queue re-dispatches. The drift trap is real but it is **shared-mutable-state drift, not code drift**; the mechanism that prevents it is a single-writer rule: the queue is the only actor that may mutate render-relevant state, and every MCP write op requires a queue-held lifecycle lease (installs blocked while jobs ≥ dispatching; dispatch blocked while lease held).
2. **P0 — P5's project scoping is asserted, not designed.** `videoRenderArtifactUpload.mjs` + Video Library (§2.2/§2.3) key artifacts to SwanStudios entities. Scenario: project #2 renders land in Swan's storage namespace; the library lists by Swan user → cross-project asset bleed in both directions — an IDOR the moment a second operator or client-site collaborator exists. Required from day one: `project_id` in the authz middleware of every content-studio route (even single-operator), per-project storage namespace, `projects` root table with Swan seeded as row #1. §5.2 criteria: stay scoped now, extract on trigger — first external collaborator account, second non-Swan project in active production, or bookkeeping-mandated spend isolation. Topology will eventually force extraction (studio is local-GPU-first; the SaaS is cloud), but extracting now repeats §2.5's substrate-first failure.
3. **P0 — P4's brief lane violates zero-PII-to-LLMs as written.** `promptPolicy.mjs` governs provider prompts (§2.1); nothing governs the describe→brief prose sent to the taste-steered LLM over Swan Brain context (§2.4). For non-Swan client projects that prose will carry client-identifying material. Need a scrub/ID-substitution boundary at the LLM call, or a declared per-project LLM-safe corpus.
4. **P1 — spendGuard is unenforceable at source under P3.** Comfy Cloud is one pre-paid credit pool across ~10 partner providers; per-provider ceilings become ledger fiction, and mid-batch depletion yields partial runs. P7 promises pre-run pricing but specifies no reconciliation of ledger vs Comfy's authoritative balance and no batch-cost hard stop against remaining balance.

7. **P1 — VRAM floors with no admission controller are decoration.** Doctor snapshot at T, dispatch at T+δ: two 12 GB-floor jobs admitted against a stale 20 GB reading → OOM on both; if OOM is retry-classified you get livelock/duplicate-spend. ## ATTACKS
- **Correctness:** Retry classifier is blind to lifecycle events (B1). Stale capability snapshots (B7). Variant rung: each variant is a full-cost re-render — display N×price before spawn or "variants" is a 5× surprise. Routing (P3) must pre-flight `verify()` before commit: §3 says stale installs *silently* expose fewer partner nodes, so a catalogue-declared route can fail only at submit. Minimum Compose surface (§5.3): brief → taste suggestions → still in <60s → approve (artifact-bound) → animate with route/price/ETA/queue-position → per-unit-priced variants → asset card with provenance + licence badge. The ladder misleads at the still ("this becomes frame 1; the motion prompt owns everything after" — a beautiful still can be motion-poor) and at describe (same description ≠ same brief; show the editable diff on re-roll).
- **Security:** Custom-node install via MCP is arbitrary Python execution on the box that holds `renderAgentAuthService` tokens — require Hermes approval (T-gates exist, §2.4), a commit-pinned allowlist derived from the manifest's required-nodes field, and install isolation (venv/container). `pip install comfy-cli`/`comfy-mcp` is itself a supply-chain surface — pin versions. FTS5 MATCH injection if Compose free-text reaches `swan-brain.mjs` unescaped — quote-escape phrases. Comfy Cloud token dual-homed between MCP agent config and backend env for Doctor's balance read — one holder, backend env, operator-gated tab. Idempotency: Compose submit needs a client key (brief id + still asset id) or a double-click spawns two paid jobs.
- **Data-truth / schema drift:** The FK retarget (queue/asset FKs → `project_id`) is the entirety of P5's risk — storage path templates must gain a project namespace or library queries drift. New table naming must match the existing convention (PascalCase-vs-snake unverifiable here — see CONFIDENCE). P3 conflates two provider shapes: local graph-backed vs Comfy-credit-backed hosted — `verify()` semantics and provenance fields differ per shape and the catalogue must model that or the registry normalizes a lie. Brain/taste data reaches the frontend with no DTO (it's a CLI today, §2.4) — define the response shape or Compose drifts. Grant state exposed to the agent must be derived from env at call time, never copied into agent context. §2.3's 9-stage rail ("filmed", "youtube_ready") is Swan business logic baked into the hub — multi-project needs per-project stage templates. `comfyuiLocal.mjs` sits at 296/300 lines (§2.1) — decompose (progress/WS polling out) before v1 of v2 or the worker-bot breaches the cap in slice one.

## HIGHEST RISK
B1: an agent with process-control and install powers attached to the production render box with zero synchronization — one diagnosis session restarting ComfyUI mid-job silently destroys the only thing the existing system is trusted for: deterministic, auditable, licence-gated runs. Cheapest de-risk: grant the MCP a **read-only toolset first** (handshake/introspection/diagnosis only) and gate every write op behind the lifecycle lease + Hermes approval before it is ever enabled — and sequence slice #1 as Compose-alpha on the existing adapter (visible describe→still→animate→asset in days, `project_id` column seeded), because §2.5 records exactly how substrate-first sequencing walks away from the original ask.
