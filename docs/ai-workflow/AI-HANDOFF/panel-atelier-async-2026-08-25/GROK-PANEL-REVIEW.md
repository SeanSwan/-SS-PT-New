## ATTACKS
- Correctness: Happy path is 202 → 3s poll → `terminal`. Null/stale: after restart the client’s `batchId` is stale-but-real; server answers 404 so the UI must not treat 404 as “safe to start another local batch” without reconciling assets. Race: reservation vs idempotency (blocker 1 and 4); `persist` then crash before `pushStill` → durable asset the poll never lists (the inverse of the pinned test “every still the poll sees already has its asset id”). Off-by-one / shape: `rendered` vs `stills.length` vs `count` vs `failures[]` are unnamed; UI “rendered of count” will lie if `rendered` includes failed frames or excludes them inconsistently. Unhandled: background work after 202 if it still reads `req.user` / ALS instead of a closure snapshot → `persist` with `undefined` owner or thrown userId; unhandledRejection that bypasses the catch around `finishBatch` never `release()`s. Hosted/local branch: hosted remains sync 200; any client that assumes one response shape will drop `stills[]` on 202 or block the hosted lane on a poller. Batch-id regex `/^[0-9a-f-]{36}$/` is UNTESTED and accepts 36 hyphens, not RFC UUID; Map lookup is safe, filesystem use would not be (not claimed). No job timeout (blocker 3). Mid-batch `partial` vs `failed` vs 0-stills is prose-adjacent: predicates do not say `rendered==0 → failed` else `partial`.

- Security: Authz on poll is owner-scoped 404 (good IDOR posture, does not leak existence). 404 is overloaded (other owner / expired / restart / never / bad id) so it is not an info leak, but it **is** a confused-deputy for the client, which will retry. Injection: batchId is a Map key in the packet; persist/SQL not shown — if `batchId` or prompt fields flow into `persist({stills:[still]})` unchecked, that is out of band of these tests. SSRF: `statusUrl` returned to client; if it is ever an absolute URL from config, fine; if it can be influenced by host headers, classic password-reset-style open redirect of the poller. Secrets: none in packet. Replay/idempotency: in-process only; restart **breaks** idempotency (duplicate spend/GPU). Multi-tenant: poll is scoped; asset rows from `persist` must carry `userId` from the **accept-time** closure or stills land ownerless / on the next request’s user. Rate-limit/DoS: 3s poll × ~40 hits on `protect, adminOnly` is fine for one operator; N tabs × N minutes with no ETag/If-None-Match and no Retry-After on GET is needless auth+serialize load; varying payload bypasses coalesce and then hits 409 — ok. `Retry-After` exists only on `E_LOCAL_BUSY`, value unspecified (too small → hammer). §3: Motion jobs in another process are invisible to `reserveGpu()`; admission-by-VRAM is a TOCTOU vs those jobs (documented, still an OOM path).

No FK `batchId` on assets is specified, so library cannot reassemble a partial batch after 404. PascalCase/camelCase in HTTP (`batchId`, `statusUrl`, `assetId`) vs whatever `persist` writes (snake_case columns?) is unspecified — classic `assetId` vs `asset_id` drop. Frontend: 202 `{accepted, batchId, statusUrl}` (+ optional `replayed`) vs poll `{status, stills[], failures[], rendered, count, persistence, error, terminal}` vs hosted inline result — three shapes, no schema pinned in this packet. `error.code` on failure is gated; `error` payload could echo prompts/paths. Expiry 1h after **finish** vs assets forever: poll 404s, library (if any) still shows stills with no batch. House-rule gap (not a code violation in this text, but this is an enhancement pass that ships UI): new chrome (“rendered of count”, “this page can be left”, disabled Generate) does not specify styled-components-only, Dual-Button Glow, 44px targets, dark-first, WCAG 4.5:1, or `var(--token,#fallback)`. 300-line cap unverifiable. ## HIGHEST RISK

Do not wait for SSE, cancel, or Telegram.
