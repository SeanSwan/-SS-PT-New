## VERDICT
REVISE — round-2 fixes are real, but the new tokenizer still goes silent on realistic commands (`file.mjs; …`) and still phantoms `~` paths, which are the two failure modes this check exists to prevent.

## BLOCKERS
1. **P1** — False negative / original outage shape. Input: a registered hook whose `command` is the completely normal `node scripts/hooks/lane-session-start.mjs; echo done` (or `…mjs; true`, `…mjs&&true`, `(node …/x.mjs)`). `tokenize` keeps the metacharacter glued to the path (`scripts/hooks/lane-session-start.mjs;`). `SCRIPT_EXT` is `$`-anchored, so the token is discarded. If the file is absent: `missing=[]`, `unresolvable=[]`, no finding — silence is again indistinguishable from clean. Evidence: `scripts/hooks/drift-check-gate.mjs` (`tokenize` = `match(/(?:"[^"]*"|'[^']*'|[^\s"'])+/g)` then `if (!SCRIPT_EXT.test(tok)) continue`).

2. **P1** — False positive / trains operators to ignore the gate. Input: `settings.local.json` command `node ~/.claude/hooks/personal-guard.mjs` (or `"~/.claude/hooks/x.mjs"`). `/[$%{}]/` does not treat `~` as unresolvable; `isAbs` is false; `existsSync(join(SS_PT, '~/.claude/hooks/…'))` is false. Output: `N registered hook file(s) DO NOT EXIST` for a healthy local hook. They wrote this exact failure mode down for `$VAR` and then missed the other unexpanded prefix humans actually type. Evidence: same file, the `/[$%{}]/.test(tok)` branch vs `isAbs ? tok : join(SS_PT, tok)`.

3. **P2** — False negative on a broken command. Input: unclosed quote, `node "scripts/hooks/missing.mjs`. The glue regex cannot enter `"[^"]*"` without a closer, and `[^\s"']` cannot consume `"`, so the path token is dropped entirely. Missing file → clean. Evidence: `tokenize` in `scripts/hooks/drift-check-gate.mjs`.

## ATTACKS
- Correctness: Happy-path tokenizer only splits on whitespace/quotes, not shell syntax, so `;|&><()` glued to a script path never reach `existsSync` (blocker 1). `~`/`~user` is not in the unresolvable class (blocker 2). Unmatched quotes drop the only interesting token (blocker 3). Other leftover holes: `node --import=./register.mjs` and `curl example.com/setup.sh` (no `://`) become phantom-missing relative files; `file:///abs/hooks/x.mjs` is skipped by `URL_SCHEME` even when the local target is gone; `npm run session-start` / extensionless binaries / `.zsh`/`.bat` never enter the check, so a missing target is clean by construction. Empty `hook.command` is not a finding. `existsSync` does not require a file (a directory named `x.mjs` counts as present). Outer `catch` fail-opens into `findings` while the filename still says “gate” and the comment says “must not block session start” — those two policies cannot both be true, and the emit path is not in the snippet. `consult-panel.mjs`: `--dry-run` `process.exit(0)` is unconditional, so dry-run + zero runnable seats is success; the all-skipped and partial-failure exits are not in the supplied tail, so fix #4 is not evidenced on those paths. `SEATS[n].paid` will throw on an unknown seat name if an earlier validator does not exist.

- Security: Gemini key-in-header and `split(apiKey)` on the error body are the right shape; empty/`A`-length keys would mutilate the error text (`''.split('')`) but that is cosmetic. Host is fixed, so `${model}` is path injection into Google, not SSRF. `JSON.stringify` of `prompt` prevents body-structure breakout; prompt-injection into the model is inherent. No idempotency key — a retry double-spends. `consult-panel.mjs` still slurp-reads the raw document/seed for the token estimate (local only in the visible code). ox retention warning is present for `premium && !paid`; paid premium seats still egress and do not get a data warning. House-rule PII: every user string in the Gemini `prompt` is *structurally* passed through `readForEgress`/`redactForEgress`, but those functions are not in the document, so name-bearing seed/remit (the case they cite) may still hit Google.

- Data-truth / schema drift: Parser assumes Claude’s `hooks[event] = [{ hooks: [{ command: string }] }]`. A string-valued event, a group-level `command`, or `command: ["node","x.mjs"]` will not be existence-checked (`String(array)` → `node,x.mjs` would actually phantom-missing if it ever reached the loop; the array/group shape is currently diverted to unresolvable). `JSON.parse` rejects JSONC — if the harness accepts comments, this check alarms “NONE of the hooks run” while they do. `seen` is per-settings-file; OK. `readForEgress(document, { label })` vs `redactForEgress(text)` are different arities; if `readForEgress` injects an unredacted filesystem path (`/Users/Jane/…`) under that label, the wire shape drifts from “redacted body” to “redacted body + raw path”. Parent `consult-panel.mjs` estimates tokens from *unredacted* lengths, so spend preview ≠ bytes actually posted after redaction.

## HIGHEST RISK
Blocker 1: a missing registered guard whose command is `node <path>.mjs; …` is reported clean — the 2026-08-22 outage, still reachable. Cheapest de-risk before ship: in the token loop, split/strip trailing shell metacharacters (`[;|&><()]`) *before* `SCRIPT_EXT`, classify `~`/`~user` as unresolvable next to `[$%{}]`, and add those three strings plus `file://…/x.mjs` and an unclosed quote to the case matrix they already claim exists. That is a ~15-line change with no schema risk.
