## BLOCKERS

1. **P0 — Global `idleSince` + reap-every-model kills work it never evaluated.** Sequence: Model A (Qwen) resident and idle past grace → `state.idleSince` is old → a second job loads Model B whose *first* inference is delayed 30s behind a slow upstream fetch (the document's own scenario 1d). The load-spike lands in the 57s of each 60s watch cycle that `sampleGpu()` doesn't cover (4 samples × 700ms ≈ 2.8s = ~4.6% duty cycle), so the clock is never reset. Next poll: `models = [A, B]`, util low, `idleMinutes` inherited from A → `reapable` → `reap()` iterates **all** of `obs.models`, unloading B mid-queue. Evidence: `observe()` uses a single `state.idleSince || now`; `reap()` does `for (const m of obs.models) sh('ollama', ['stop', m.name])`; `firstSeenModels` is written and then **never read or compared**, so a model-set change never resets or forks the clock. This is the document's self-declared expensive failure, reachable on default config.

2. **P1 — Telemetry and config parse fail-deadly on NaN.** If `nvidia-smi` ever prints `[N/A]` or garbage (driver recovery, unsupported counter), `Number(v.trim())` → `NaN` → `maxUtil >= CFG.busyPercent` is `false` → observation counts as **idle**, clock accrues, reap fires during real work. Same class: `SWAN_GPU_BUSY_PCT=2five` → `Number("2five")` = NaN → the busy branch is permanently false, silently, on every invocation. The `if (!out) return null` guard only catches *empty* output. No `isFinite` guard in `sampleGpu()`; no CFG validation at boot. Fail-direction here is exactly backwards for a tool whose expensive failure is the false positive.

3. **P1 — Unload is never verified; failure produces a lying memo and a retry loop.** `sh()` swallows every error and returns `''`. If `ollama stop` fails (version without the subcommand, server hiccup), `reap()` still writes "freed ~X GiB" to the Hermes inbox, resets state, and `--watch` re-arms — looping every grace period for up to 240 minutes, each cycle writing another memo claiming a reap that didn't happen. Hermes reads "unloaded"; VRAM stays resident; the room keeps cooking behind a green checkmark. Compounding: the top-level catch `process.exit(0)` means any scheduler alerting on exit codes sees eternal success. The original sin of this incident was *invisibility*; this recreates it with false confidence.

4. **P1 — The mission fails whenever the desktop uses the GPU.** Utilization is queried **whole-GPU**, and any single sample ≥25% resets the clock. A browser compositing, video playback, a game, or a training job that spikes util once every <10 min keeps an abandoned model resident *forever*; `--watch` exits at its 240-min ceiling and the 4-hour incident recurs silently. Inverse direction: a legitimate non-Ollama GPU workload both shields the idle model (room cooks) and gets its own signal misattributed. The discriminator answers "is the GPU working," never "is the *model* working."

5. **P2 — 10-minute grace is miscalibrated against the user's own workflow.** A user who reads a long response for 12 minutes before the follow-up is "working" by any reasonable definition; reaping there buys pennies and costs a 30–90s reload of 17 GiB. The incident was 4 *hours*. Grace should be 30+ min, or scaled by `vramGiB` (reload cost), not tuned to the near-miss.

6. **P2 — State file read-modify-write race.** `--watch` plus any timer/hook invocation both do unguarded read→write on `gpu-idle-state.json`. A lost update can erase a spike-reset, shaving up to one cycle off grace. No locking, no atomic tmp+rename write (partial-write on crash is caught by `readState`'s catch, so corruption is survivable — but the race isn't).

7. **P2 — Markdown injection into an LLM-consumed inbox.** Model names come from Ollama and flow unescaped into a pipe-table in a memo Hermes (an agent) reads as context. `ollama create` accepts arbitrary names; a name containing `|` and agent-directed text becomes prompt injection into the Hermes inbox. Adjacent in spirit to the zero-PII rule: the memo's *integrity* is an input-trust boundary. Sanitize/escape names.

8. **P2 — CPU-offload inference can generate below threshold.** With partial layer offload (`num_gpu` < layer count, common on tight VRAM), sustained generation may sit under 25% GPU util → mid-generation reap. Uncertain how far below 25% real offloaded decode sits on a 5090; see CONFIDENCE.

## ATTACKS

- **Correctness:** Stale global state vs. a changing model set (Blocker 1 — the dead `firstSeenModels` field is the smoking gun that per-model tracking was intended and never finished); NaN parsing in both telemetry and config (Blocker 2); unverified side effect with unconditional success reporting (Blocker 3); RMW race (Blocker 6); NTP clock step can make `idleMinutes` jump instantly reapable (harmless in the safe direction, instant-reap in the other); `--watch` on persistent `status: 'unknown'` burns its entire ceiling no-op logging. Happy-path verification was genuinely done (`/api/ps` empty, 26,469→2,997 MiB) — the verified matrix never once varied the *number of models* or the *presence of other GPU processes*, which is precisely where the logic is weakest.
- **Security:** Shell calls are `execFileSync` with fixed arg arrays — no injection, correctly done; fixed `localhost:11434` URL — no SSRF; no secrets handled. Real items: (a) untrusted model names → agent-read markdown (Blocker 7); (b) exit-0-on-all-failures converts an accountability signal into silence for whatever scheduler eventually runs this (Blocker 3) — fail open on *action* is right, fail *quiet* on *signal* is wrong; a failing timer-run reaper should exit nonzero and/or memo its own failure. Rate-limit/DoS: local only, N/A.
- **Data-truth / schema drift:** Depends on the `ollama stop` CLI subcommand — version-sensitive; the API-stable unload is a request with `keep_alive: 0`, which would also remove the exec dependency. `/api/ps` field names (`size_vram`, `expires_at`) were exercised live by the author, so drift risk is low — but `expires_at` has a zero-value sentinel for `keep_alive: -1` (the likely incident configuration!) which the code only passes through to the memo as a raw string; any future logic keyed on `expires_at` must handle it or it will misjudge exactly the models that never self-unload. Multi-GPU drift: only line 0 of `nvidia-smi` output is read while Ollama may be pinned to another GPU — observation and action then describe different hardware. Frontend response-shape: N/A (no frontend).

**The document's Q2/Q6/Q7, answered directly:** Better discriminator: poll `/api/ps` twice ~60s apart — Ollama resets `expires_at` on every request, so a model whose expiry *advances* is being touched (busy) and one whose expiry is *static* is idle by the server's own request-activity knowledge. Immune to desktop spikes, per-model, zero sampling heuristics. Right trigger: an OS-level timer (cron/systemd timer/Task Scheduler) invoking `--reap` every 5–10 min — a Stop hook fires exactly when the user is *present*, which is the complement of the walk-away case; grace does the waiting. Wrong shape? Partially yes, and the memo admits it: `OLLAMA_KEEP_ALIVE=15m` is the mechanism and this should be only the backstop for `keep_alive: -1` overrides baked into some tool's payload — in which case its grace should be *longer* than the configured keep-alive so it fires only on pathology. Scope creep (Q8): log `power.draw` alongside util for the memo, but do **not** extend reaping to arbitrary GPU processes — killing someone's training job to save watts is Blocker 1's catastrophe one taxonomy level up.

## HIGHEST RISK
The triple granularity mismatch: **per-GPU signal → single global clock → all-model action.** Every axis of observation and action disagrees, and all four top blockers fall out of it. Cheapest de-risk before any automatic deployment: (1) set `OLLAMA_KEEP_ALIVE=15m` today — one env var eliminates ~95% of the reaper's job and makes the incident structurally impossible for finite keep-alives; (2) a ~30-line rewrite of `observe()`: per-model state keyed by name, `expires_at`-delta as the discriminator (two polls), util retained *only* for zero-value-sentinel models with grace ≥30 min; (3) verify unload by re-querying `/api/ps` before writing any memo, with a distinct failure memo and nonzero exit on failure.
