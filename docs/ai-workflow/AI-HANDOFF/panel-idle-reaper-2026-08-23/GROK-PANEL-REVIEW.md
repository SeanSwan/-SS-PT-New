## VERDICT
REJECT — not safe to run unattended: a `/api/ps` blip makes `--watch` report "GPU is clear" and exit while VRAM still cooks the room, and a reboot-/model-swap-surviving global `idleSince` can `ollama stop` a model that just loaded for real work.

## BLOCKERS
1. **P0 — false "clear" is `--watch`'s exit condition.** `residentModels()` maps every failure (`!res.ok`, timeout, JSON throw, connection refused) to `[]`. `observe()` then treats empty as "nothing resident", wipes state, and `--watch` breaks out. Sequence: Ollama hung / restarting / slow under load → `fetch` 8s abort or non-OK → `{status:'clear'}` → watch prints "nothing left to watch — exiting" → 17 GB stays resident for hours with no watchdog and no Hermes memo. Evidence: `residentModels` `96:108`, clear path `129:131`, watch exit `217`.

2. **P0 — `idleSince` is wall-clock, global, and not bound to the model set or a continuous observation window.** `firstSeenModels` is written once and never read. Unobserved time counts as idle. State survives reboot and model swap. Sequences: (a) Friday idle writes `{idleSince: Friday}`; Saturday reboot + `ollama run` for paid work + first `--reap`/`--watch` → `idleMinutes` is huge, util still 10% while weights land or the first prompt is typed → immediate stop. (b) Model A idle 9 min; Model B loaded for a job; 1 min later both are reaped because the clock was A's. (c) `--check` once, nothing runs for 10 min (including a full inference that started and finished between probes), `--reap` kills whatever is resident and currently between kernels. Evidence: `143:149`, write-only `firstSeenModels` at `144`, no `lastObservedAt` gap detection, `readState`/`writeState` `111:117`.

3. **P0 — TOCTOU: `reap()` trusts a stale verdict and never re-samples.** Sequence: grace already elapsed → `observe()` returns `reapable` → user/agent hits `/api/generate` and kernels go 90% → `reap()` still runs `ollama stop` on every name in the old snapshot → in-flight (possibly paid) completion dies. Same window exists in `--watch` between `observe()` and `reap()`. Evidence: `191:196` (no second `sampleGpu`/`residentModels`), callers `218:221` and `232:234`.

4. **P1 — GPU 0 only, GPU-wide util, NaN counts as idle.** `out.split('\n')[0]` discards every GPU after the first. `Number("N/A")` is `NaN`; `NaN >= 25` is false, so a driver glitch looks like 0% work and feeds the reap path. Sequence: Ollama scheduled on GPU 1 at 95% util; GPU 0 sits at 10% (or nvidia-smi prints `N/A`) → status `reapable` → `ollama stop` kills the live job. Evidence: `81:88`, busy check `138:140`.

5. **P1 — `ollama stop` failure is reported as success.** `sh()` swallows all errors to `''`. `reap()` still writes the Hermes "unloaded / freed GiB" memo and clears state. Sequence: stop fails (name drift, ollama CLI missing, permissions) → inbox claims the room is saved → idle clock resets → another 10 min of heat before the next chance, and Hermes is now lying. Evidence: `72:74`, `193:195`, memo `166:167`.

## ATTACKS
- Correctness: Happy path (`--check` idle, `--reap` after grace, `--watch` exit on real clear) is the only path that was executed. Discriminator is the wrong observable: `/api/ps` already returns `expires_at` (fetched at `106`, rendered in the memo at `171`, never used for the verdict). Sustained SM util cannot see "idle between turns", "batch gap", "waiting on a slow upstream tool", or "3.8B / short decode that finishes between 700 ms samples". Comment at `29:31` promises "continuous observed idleness"; code implements "wall clock since first low sample" with 4 probes covering ~2.1 s then a 60 s hole (`64:67`, `80:85`, `227`). Once `reapable`, only a `>= busyPercent` spike can save the model — load, queue, tokenize, and tool-wait do not. `--watch` is not itself a thermal runaway (240 min ceiling, 60 s sleep, exit on clear) but it becomes useless in the exact failure it exists to catch (blocker 1), and `SWAN_GPU_WATCH_MAX_MIN` / `SWAN_GPU_SAMPLES=0` / `SWAN_GPU_GRACE_MIN=0` are unsanitized `Number()` so a bad env makes `Math.max(...[]) === -Infinity` (always idle) or instant reap (`58:70`, `88`). Fail-open `238:241` plus `sh`/`residentModels` swallowing errors means the hook still blocks up to 8 s + 15 s on timeouts (`73`, `98`) — it does not "never block a turn", it just always `exit(0)`. Between-turn / tool-wait after 10 min is a *designed* false positive; treat it as acceptable only if every caller can pay a 17 GB reload. Multi-GPU and second-process util are untested. Laptop sleep advances `Date.now()` so lid-open is immediately `reapable`.

## HIGHEST RISK
Unsupervised `ollama stop` of live work (blockers 2+3), which the prompt correctly ranks above a hot room. Cheapest de-risk before any cron/daemon: (1) `residentModels` failure → `{status:'unknown'}` never `'clear'`; (2) abort `reap()` unless a *fresh* `sampleGpu()` is below threshold *and* `models.map(m=>m.name)` still equals the set stored with `idleSince`; (3) reject `idleSince` unless `Number.isFinite(util)` for every sample and `now - lastObservedAt` is ≤ `2 * watchInterval` (gaps reset the clock, including post-reboot). Two extra reads, no new daemon. In parallel set `OLLAMA_KEEP_ALIVE=10m` on the 62 s panel call — default Ollama keep-alive is already 5 m; a 4 h hold is a client request, not a missing reaper.
