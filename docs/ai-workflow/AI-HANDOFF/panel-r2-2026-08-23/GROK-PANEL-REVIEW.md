## BLOCKERS
1. **P1 — PATH_RE false positive on `$CLAUDE_PROJECT_DIR/...` (and `${VAR}/...`).** Input: a legitimate hook command `node $CLAUDE_PROJECT_DIR/scripts/hooks/session-start.mjs` (or the unquoted `${CLAUDE_PROJECT_DIR}/...` form). The lookbehind `(?<![\w./\\-])` treats `$`/`{` as a valid start, so the match is `CLAUDE_PROJECT_DIR/scripts/hooks/session-start.mjs`. `NOT_A_FILE` does not strip env-var prefixes. `join(SS_PT, rel)` points at a path that does not exist → `missing.push(...)` → a phantom “registered hook file(s) DO NOT EXIST” finding on a healthy registration. That is the failure they told us to hunt: a false positive that trains operators to ignore the gate. Evidence: `scripts/hooks/drift-check-gate.mjs` PATH_RE + `NOT_A_FILE` + `abs = /^(?:[A-Za-z]:|\/)/.test(rel) ? rel : join(SS_PT, rel)`.

2. **P1 — PATH_RE false negative on the other two official-ish forms; the absolute-path branch is dead.** Input A: `node "$CLAUDE_PROJECT_DIR"/scripts/hooks/session-start.mjs` (quoted var, path after `/`). `$CLAUDE_PROJECT_DIR` has no extension so it does not match; `scripts/hooks/...` cannot start because it is preceded by `/`, which the lookbehind forbids. Input B: `/abs/path/hooks/foo.mjs` or `C:\abs\hooks\foo.mjs`. First-char class is `[A-Za-z0-9_.]` (no `/` `\`), and the lookbehind also forbids starting after `/` or `\`, so PATH_RE can never emit a token that starts with `/` or `X:`. `existsSync` is never called → a missing file produces no finding → “clean” while the guard is off. The comment “Absolute paths are used as-is” and the `^(?:[A-Za-z]:|\/)` branch are unreachable given this regex. Evidence: same PATH_RE / `abs` lines in check 7.
