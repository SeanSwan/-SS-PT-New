### Question 1 — concrete plans and reversibility, per unfixed item

**§3.1 Token schism.** Do not let either scale "die" by fiat, and do not reconcile doctrine against doctrine. The defensible rule has two parts that compose: (a) *value selection* — code is ground truth, because the packet's own verification shows the token names in 0 lines of code, which means reconciling doctrine cannot ship a visual regression today and the only question is what future builds get told; the packet's "changes geometry on every surface" over-claims this (F13). Run a one-time census of `frontend/src/**` for literal values (radius 6/10/12/16/20/24/999/9999; the 11 spacing steps). Where code is unanimous, canon must describe code, not vice versa — that is the migration path with zero build risk. Where code is mixed, the owner makes a design decision, canon records it, and code converges only opportunistically, never in this slice. (b) *precedence* — "canon wins, satellite documents the exception" is defensible precisely because the corpus already has a hierarchy: `index.md` declares canon. The generalization that prevents recurrence: a satellite may hold a divergent value only behind an explicit `EXCEPTION:` marker naming the canon section, rationale, and affected surfaces; the gate fails on unmarked divergence. Reversibility: the conflict banner, the precedence rule, the marker convention, the gate extension, and the doctrine convergence are all reversible doc edits. The first irreversible-ish step is code adoption of canonical token names — and per the packet's own verification, that step does not exist today and is out of scope.

### §5.3(a), (b) and §6 answered directly

**(a) Is the dialect problem the actual root cause?** Partially — and the distinction matters. The renumbering caused the *measured* rot; the dialect free-for-all explains the *silence*: an author citing `reviewers.md §3` or `anti-patterns.md §27` gets no feedback because no file declares what a valid citation to it even looks like, so every citation form is locally plausible. On "normalized heading scheme vs better link checker": neither as posed. Flattening `A1`/`T1` to plain numbers would re-run the renumbering disaster in miniature — those prefixed identifiers are plausibly stable vocabulary cited from elsewhere, and renumbering them manufactures a brand-new dead-ref class. The middle path is F8: preserve the dialects, declare each file's citation form in its header, and make the gate validate the *used* form against the *target's* form. For `index.md` and `anti-patterns.md`, choose: number them, or formally ban `§N` to them — note the irony that `index.md`, whose own law is enforced by D2, is itself uncitable.

**(b) Measuring prose/title-form refs.** Build a title index: extract every heading's title text across all 28 files in all dialects, normalize (strip numbering, case-fold, punctuation-free). Scan all surfaces — the 2,031 already scanned plus every row in the second table — for quoted/title-string matches with a minimum n-gram length to control false positives (one-word titles like "Optics" need word-boundary-plus-context rules). Mandatory instrument validation per §4.2: positive controls (a hand-renamed heading whose old title remains cited somewhere must be found; a known-live title citation must be found). Gate warn-only until precision is measured — a noisy FAIL gate would teach people to ignore the gate, which is worse than no gate. I have no count and neither does anyone; F9's severity must be re-graded after the first measurement.

**§6 sweep: right move, wrong order, insufficient criterion.** The enforcement-claim sweep is cheap and clears four known active-harm fictions — run it now. But §5.3(a) is the higher-value structural fix and should be next, because it also unblocks the outbound-ref validation (§5.3(d) — you cannot parse external sections without dialect handling) and simplifies the knowledge.md rewrite. The acceptance criterion ("must fail on a new false claim") is necessary but incomplete: it says nothing about *detection*, and enforcement claims live in prose. Full mechanical detection of arbitrary prose is not achievable; say so and design around it. Mandate a canonical claim format ("Enforced by: `path`"), sweep for enforcement vocabulary, require each hit to resolve a locator *and its wiring* — a script that exists but is referenced by no CI job or hook is still a fiction. Inject a false-claim fixture as the positive control. Without the canonical format and the wiring check, the sweep's output rots into exactly the fifth fictional mechanism the criterion warns about.
