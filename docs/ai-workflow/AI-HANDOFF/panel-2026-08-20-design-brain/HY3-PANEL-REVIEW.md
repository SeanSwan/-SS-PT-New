**FINDING 1 (Most severe): The audit’s Visual Director is prose‑first critique rebottled — it carries the same “doctrine without enforcement” disease and will not reliably catch AI slop. Its P0 ordering also misprioritizes by building the Director before a kernel state machine that gates layout behind material.**

CLAIM: The proposed Keep/Fix/Elevate/Wildcard lanes with screenshot regions and LLM‑assigned confidence/safe‑auto‑apply flags remain a textual report generated by a multimodal model. No deterministic geometric measurement is required to substantiate any finding. This repeats the exact failure the audit diagnoses in the current system (confident prose, zero consumers) inside a new component. Worse, the audit places “Build Playwright Visual Director” as P0 before instituting a hard state machine forcing material‑before‑layout, so even a perfect Director would inspect slop produced upstream.

EVIDENCE/REASONING: Multimodal LLMs exhibit language‑prior bias — they emit phrases like “clean hierarchy” decoupled from pixel geometry. The audit admits current Playwright only checks mechanics, yet its fix adds an agent that outputs the same unverified excellence prose. Without cross‑checking against computed DOM metrics (zone occupancy, focal‑contrast ratio, subtree‑hash template signatures), “safe‑to‑auto‑apply” is a coin flip. The audit also omits a template‑pattern detector — the highest‑value slop signal (3‑col icon grid, centered gradient hero, equal‑weight cards). Premium critique needs evidence‑linked numbers, not confidence vibes.

CONCRETE FIX (Top‑5 change #1 — Rebuilt Visual Director):
- Inputs: rendered screenshots + DOM at 375/768/1440/2560/3840, material pack, domain rubric, current taste profile.
- Outputs: structured JSON per finding with {bbox, domSelector, measuredMetric, proposedCSSDelta, expectedPostMetric, metricAgreement: bool, lane}.
- Mechanism: Stage 1 deterministic Geometry Extractor (Playwright + CV) computes zone maps, type ladder, color‑mass, template‑signature hash. Stage 2 multimodal critic must cite bbox + match claim to extracted metric; mismatch forces Human/Elevate lane, never auto‑apply. Add explicit “Template Pattern” lane flagging known slop signatures. Delete standalone confidence field; replace with metricAgreement.
- Acceptance test (behavior delta): Feed a known slop render (centered hero + 3‑col grid). System must output Template‑Pattern flag with bbox and measured symmetry score >0.8; a human‑written good render must score <0.3 and auto‑apply at least one geometric Fix (e.g., overflow clamp) verified by re‑render showing corrected rect.
- Naive failure: Building it as a prompt that returns “Keep/Fix” text with yes/no confidence → produces another unconsumed report; auto‑apply corrupts good pages.

**FINDING 2: The Studio annotation surface as specified is a static screenshot markup toy — it misses the interaction‑state and patch‑spec mechanics that mechanically separate premium UI from AI template composition.**

CLAIM: The audit’s Studio (N‑up preview, device toggles, region annotation, tweak chips) treats design as fixed images. It lacks stateful interaction annotation, region locking, cross‑direction grafting, and a machine‑applicable patch schema. This guarantees output remains a pretty poster, not a functioning product.

EVIDENCE/REASONING: Premium interaction design differs from template slop by: (a) focal hierarchy derived from task flow not visual filler; (b) custom section grids per zone; (c) material‑driven composition; (d) motion as functional feedback; (e) designed edge‑case states (loading/error/empty). AI templates generate components autoregressively with uniform spacing and decorative motion. The audit’s tweak chips are global tokens — they cannot express “make hero anchor asymmetrical per material pack.” Annotation as chat comment repeats the audit’s own “artifact nobody consumes” defect.

CONCRETE FIX (Top‑5 change #2 — Studio Annotation Surface):
- Inputs: rendered DOM + state snapshots, direction set, material pack, lock registry.
- Outputs: JSON‑Patch diff spec + rationale + expected metric delta, graft spec, locked‑region manifest.
- Required additions: (1) DOM‑selector frozen regions — user locks subtree from auto‑revision. (2) Interaction‑state timeline: annotate hover/focus/active/loading/error per component, not just first viewport. (3) Cross‑direction graft: select region A from dir X + region B from dir Y → merged DOM with conflict resolver. (4) Patch spec schema emitted to builder agent, not comment. (5) Motion previewer with reduced/full‑motion scrubber.
- Acceptance: User annotates a button’s focus state → system emits patch changing only :focus CSS; re‑render shows focus‑ring metric (contrast ≥ 3:1) applied, locked header unchanged. Cross‑direction graft produces valid DOM with zero selector collisions.
- Naive failure: Building only screenshot‑region drawing + chat box → no behavioral change; designer abandons it.

**FINDING 3: Root cause of “AI slop” is autoregressive layout generation without spatial constraints; the audit’s material‑pack theory is necessary but insufficient.**

CLAIM: Audit blames missing asset pack and missing critique loop. Deeper mechanism: LLMs emit HTML/CSS token‑by‑token biased toward training‑majority patterns (flex column, centered max‑width, 3‑up grid). Even with beautiful images, composition snaps to priors because no constraint graph forces zone allocation.

EVIDENCE/REASONING: High‑leverage interventions: (1) pre‑layout constraint schema defining explicit grid zones (hero anchor, negative‑space ratio) from material aspect; (2) geometric fingerprint reject if DOM bbox distribution correlates >0.8 with template signatures; (3) rendered critique measuring focal contrast. Plate Forge without constraint schema yields “Swan‑skinned generic grid with nice photos.”

CONCRETE FIX (Top‑5 change #3 — Constraint Layout Generator):
- Inputs: material pack, brief, domain pack constraints, taste profile weights.
- Outputs: HTML/CSS adhering to explicit zone map (not free‑form) + zone‑map report.
- Acceptance: Same material pack → two directions have hero‑anchor x‑offset variance >30% and template‑score <0.2 each. Changing taste profile density weight alters zone occupancy measurably.
- Naive failure: LLM “designs layout” with images as <img> decoration → slop persists; no zone enforcement.

- Acceptance: Load classroom profile into Swan pack context → generated CSS variable diff shows zero leakage (automated token‑set diff). Reverse test likewise.
- Naive failure: Global profile object merged by concatenation → silent contamination.
