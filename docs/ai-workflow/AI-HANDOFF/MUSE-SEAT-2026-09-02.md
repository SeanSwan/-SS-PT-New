## 1. What the transcript claimed vs. what is true

The transcript was the input, not the evidence. Every number below was checked against
the vendor and OpenRouter pages on 2026-09-02.

| Claim in the transcript | Verdict | What is actually true |
|---|---|---|
| Contributor tier ≈ $0.10/$0.20 per M, cache read $0.002 | **CONFIRMED** | `meta/muse-spark-1.3-contributor` — $0.10 in / $0.20 out / $0.002 cache read, 1M context |
| ~100–250x cheaper than Fable 5.1 | **CONFIRMED, but only on the training tier** | Fable is $10/$50. Contributor is 100x/250x. The *standard* tier is 8x/11.8x |
| "Muse Spark 1.3 is going open weight" | **WRONG as stated** | Meta has **not decided** whether to publish 1.3's weights. It still plans to publish **1.2's**. Muse Spark launched closed in April and ended Meta's open-weight Llama era |
| Benchmarks beat Opus 5 | **Partly, and suspect** | Tops Terminal Bench **2.1**; scores poorly on the newer Terminal Bench **4.0** — a spread Opus 5 does not show. The presenter flagged this himself as possible benchmaxing |
| Contributor tier means Meta trains on your data | **CONFIRMED — and it is the whole product** | Meta's docs exclude "client repositories, personal data, secrets, unreleased product logic, and material under NDA" from that tier |

**The finding that changed the plan:** the standard tier at **$1.25/$4.25** is already
~2.4x cheaper in and ~3.5x cheaper out than the Kimi seat, at #6 on the Artificial
Analysis intelligence index with a 1M context window — **with no data-training deal at
all.** That, not the headline contributor price, is the seat worth having. The 12.5x
extra discount only applies to material this repo has very little of.

## 2. What shipped

### `scripts/consult-muse.mjs` — the seat
Executor-tier consult script, modelled on `consult-kimi.mjs` so it inherits that file's
hard-won handling (cost computed *before* the empty-content guard, truncation decided
before emptiness, dry-run default, `--confirm-spend`).

```bash
# default — standard tier, no training, dry run
node scripts/consult-muse.mjs --document docs/ai-workflow/brainstorms/<task>.md

# live
node scripts/consult-muse.mjs --document <doc> --out <out> --confirm-spend
```

| Tier | Model | $/M in | $/M out | Meta trains on it |
|---|---|---|---|---|
| `standard` (default) | `meta/muse-spark-1.3` | 1.25 | 4.25 | **No** |
| `contributor` (gated) | `meta/muse-spark-1.3-contributor` | 0.10 | 0.20 | **Yes — irreversibly** |

The seat is an **executor, not a decider**. Rule 46 and the Co-Orchestrator chain are
unchanged; its output is a hypothesis until verified here (Rules 30, 73). Its own output
file carries that warning in a banner, so a future reader of the artifact cannot miss it.

### The training-tier gate — `scripts/lib/redact-egress.mjs`
A leaked key is rotatable. Proprietary source absorbed into a foundation model's weights
is not — there is no rotation. So this gate is **fail-closed on content**, unlike the
redactor around it (fail-closed on its own instrument, permissive on content by design).

- **Allowlist, not denylist.** That module's header already records a content scan
  returning "no matches" on a file that demonstrably contained the string. A denylist of
  "sensitive-looking" content would fail open the same way. Default: `SWAN_TRAINING_TIER_ALLOWLIST`
  unset → **nothing** in this repo is cleared → every contributor call is refused.
- **Enforced at the socket, not by a flag.** `fetchForEgress` refuses *any* `*-contributor`
  model whose caller did not pass `armTrainingTierEgress()` in the same process. A flag in
  one script is bypassed by writing a second script — the same reasoning already recorded
  for `assertNotResoldSubscriptionSeat`.
- **Single-use, TTL'd arming**, so one clearance authorises exactly one call.
- **Traversal and symlinks resolved first.** `..` is rejected outright, and the allowlist
  is applied to `realpathSync()` output — a Windows junction inside a cleared directory
  cannot launder a blocked target past the prefix check. (This repo lost a 29MB corpus to
  a junction assumed inert on 2026-08-31.)
- **`--remit` is refused on the training tier.** The allowlist names *files*; a hand-passed
  remit is free text that never passes it, and was a live side channel until closed.

### Spend guard — `scripts/hooks/spend-guard-gate.mjs`
`consult-muse.mjs` added to the gated set with the **standard-tier** price row. The
contributor tier is deliberately *not* listed: the script selects it by `--tier`, not
`--model`, so every Muse call is priced at the standard rate. That errs toward
overestimating, the only safe direction for a spend guard.

## 4. The local lane — and why it is better than "wait for Muse Spark"

Sean called the local plan important. The research changed what it should be.

**Do not wait for Muse Spark 1.3 weights.** Meta has not committed to releasing them.
Planning around an undecided release is planning around nothing.

**Muse Glimmer 30B already exists and fits the box you own.** Released 2026-08-10:

- **Apache 2.0**, on Hugging Face (`meta-models/Muse-Glimmer-30B`, `-GGUF`, `-ExecuTorch-PTE`)
- **30B params; ~4-bit quantised lands under 20GB** — comfortable on the 5090's 32GB
- **Distilled from Muse Spark 1.2**, with a companion draft model for faster decode
- **Ollama / LM Studio / llama.cpp / MLX** support — the same Ollama bridge Hermes
  already uses for Qwen 3.8

That makes the local lane concrete today: pull Muse Glimmer 30B into the existing 18-model
zoo beside Qwen 3.8-27B, and it inherits the whole reason the local brain exists — **zero
data-sharing, zero per-token cost, and fail-closed by default** (no automatic cloud
fallback). It is strictly better than the contributor tier for anything sensitive, because
nothing leaves the machine at all.

**Sequencing.** Cloud seat first (shipped here) for capability the local box cannot match;
Muse Glimmer next as the free lane for bulk work; Muse Spark 1.2 weights if and when they
land. The cloud dependency is a bridge, not the destination.

**Not started here** — this is a plan, not an implementation. It touches the Hermes brain
config, which is a separate workstream and a separate lane (Rule 67).

## 5. Known limitations — attack these next

1. **Raw `fetch()` bypasses the gate.** The training-tier guard, like the existing
   subscription-seat guard, only covers callers that go through `fetchForEgress`. A script
   calling `fetch` directly is unprotected. This is the accepted architecture, not an
   oversight — but it is the first thing a future reviewer should re-check if a new
   consult transport appears.
2. **No live call has been made.** Every result above is a gate/refusal test. The model's
   actual output quality on Swan work is **`[UNKNOWN]`** — the benchmark spread (2.1 good,
   4.0 poor) is a reason to measure before trusting it, not to assume either way.
3. **`.claude/settings.json` was NOT edited** — another agent held it under Rule 67. The
   permission entry `Bash(node scripts/consult-muse.mjs:*)` still needs adding, or the seat
   will prompt on every invocation.
4. **The allowlist is unset**, so the contributor tier is currently unusable by design.
   That is correct until Sean names a genuinely non-sensitive prefix. Do not set it to
   `docs` wholesale — the handoff and brainstorm trees carry business logic.
5. **`consult-muse.mjs` is 304 lines — 4 over the Rule 4 cap, disclosed rather than
   hidden.** It was trimmed from 315 by cutting genuinely redundant comment prose. The
   remaining overage is not shaved further because the only honest extraction left is
   `loadOpenRouterKey` / `assertSafeInputPath`, which are duplicated verbatim across
   `consult-kimi`, `consult-grok` and siblings. De-duplicating them is a real improvement
   but a *different, cross-cutting slice* (Rule 3 surgical scope), and it would touch
   files other agents hold. Shaving comments to reach 300 would trade the load-bearing
   WHYs for a number.
6. **Pricing drifts.** The rows here were read on 2026-09-02. If a call's real cost
   diverges from the estimate, re-read the OpenRouter page before editing the price table.
