## Summary
The client-facing plan PDF must brand per client type: **Move Fitness clients see Move Fitness only** (no SwanStudios anywhere — so Sean never looks like he's poaching his gym's members), **Sean's own clients see SwanStudios** (with an optional "add Move Fitness" cross-promo). Delivery: a **custom-header editor + preview + approve-before-print** gate so Sean controls each printed document. Carries the broader visual redesign direction (cover page, periodization arc, phase cards) mocked up 2026-07-10.

## Key Decisions
- **Export flow = auto-default + preview + 1-tap approve.** Correct branding applies automatically by client type; Sean sees a real preview and taps "Approve & Download"; a "Customize header" affordance is present for tweaks. Fewest clicks for the common case, full control on demand.
- **Presets are saved (backend-stored), auto-applied by client type.** Set the MF header once → every MF client reuses it; same for SwanStudios. Built-in defaults (repo logos) ship so it works before any customization. Needs a small backend branding-preset store (logo + wording per brand) so it syncs across devices and survives cache clears. → NEW backend model/table + routes.
- **Full white-label for MF clients — scrub all 4 leak points.** Header wordmark → MF; footer "Generated by SwanStudios" → MF; filename "SwanStudios-…pdf" → "MoveFitness-…pdf" (client sees it on save); "Swan Coach Recommendations" heading → neutral "Coaching Recommendations"; no swan cover watermark. Nothing SwanStudios reaches an MF member, including the saved filename.
- **Branding logic lives in the shared `swanPdfKit` → all 3 client PDFs (plan, session log, progress report) auto-white-label by client type.** No leaks across document types. Editor + preview/approve UI wired on the plan export first; session-log + progress-report get correct auto-branding now, own editor later. (Also means the plan exporter should finally adopt `swanPdfKit` instead of its own local header.)

## Recommended defaults for the remaining (smaller) decisions — pending Sean's confirm
- **Preview fidelity = the REAL generated PDF** rendered in the modal (jsPDF blob → object URL in an `<iframe>`/embed), so what Sean approves is byte-identical to what prints. No separate HTML proxy that could drift from the real output.
- **Editor fields (the "Customize" panel):** brand logo (pick built-in Swan/MF or upload), brand display name (text), tagline/accent line (text), "add Move Fitness credit" toggle (Swan clients only), and — once the redesign lands — the cover title. Small fixed set; everything pre-filled from the active preset so it's tweak-not-build.
- **Preset ownership = per-owner account** (Sean's presets are his), auto-selected by the client's `clientSource`, with a manual brand override in the editor. Future-proofs multi-tenant (other trainers get their own) without over-building now.
- **"Approve" = a UX gate only** (no persisted approval/audit record) for v1 — Sean prints his own docs, there's no compliance need. Can add an audit stamp later if a client-share/email path appears.
- **Undefined `clientSource` defaults to SwanStudios** (safe: never wrongly white-labels a non-MF client to MF; and the preview gate lets Sean catch a misclassified client before print).

## Suggestions & Enhancements (Phase 2 — grill-me's read)
- **The preview/approve gate is a SAFETY mechanism, not just polish.** A client mis-tagged (an MF member saved as `swanstudios`) would otherwise silently leak SwanStudios onto their plan — the exact poaching risk. Because Sean eyeballs the brand before every print and can override, the gate is the backstop that makes white-labeling trustworthy. Worth keeping the brand identity *prominent and obvious* in the preview (a "Branding: Move Fitness ▾" chip at the top of the modal) so a wrong brand is caught at a glance.
- **Split into two slices.** Slice A = white-label branding model + editor/preview/approve (carries the business value — protects the MF relationship, unblocks safe printing). Slice B = the visual redesign (cover page, periodization arc, phase cards, exercise-name polish) layered on top. Shipping A first avoids entangling two big changes and gets the risk-reducer live sooner.
- **Adopt `swanPdfKit` in the plan exporter as part of Slice A.** It currently runs its own duplicate header/footer code; folding it onto the shared kit is where the white-label logic naturally lives and kills the duplication (rule 4 / hygiene).
- **The branding model is reusable beyond PDFs** (email templates, an MF-linked user's in-app chrome, share cards). Don't build for that now, but name the preset store "studio brand identity" so it can grow into it rather than being PDF-only. Possible home: extend `adminSettingsController` rather than a fully isolated store.
- **Logo sizing rules** must be baked in: uploaded logos need max-dimension + aspect-preserve handling so a tall/wide logo doesn't distort or overflow the jsPDF header band. Define a target box (e.g. ~40×14mm) and fit-within.

## Minimal-Click Opportunities
- **Everyday print = 1 tap** (Approve & Download) — the default-applied preset means no editing in the common case. Before→after: today 1 tap (instant download, wrong brand) → 1 tap (preview + approve, right brand). Same clicks, adds the safety look for free.
- **"Customize" pre-fills from the active preset** so a tweak is edit-one-field, not rebuild-from-blank.
- **Set-once presets** mean the MF logo is uploaded a single time ever, not per client or per print.
