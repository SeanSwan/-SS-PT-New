- **Sean's answer:** Self-service is NOT the wedge — it's the **lowest-risk way to build the first-party workout/progress record the trainer business depends on.** Mechanism: user voice-logs → Swan builds structured history + progress proof → **Swan detects plateaus / missed sessions / pain flags / milestones / weak adherence → routes the user to a coach-led next action** (book consult, request plan review, join a coached challenge, share a milestone, upgrade to trainer-led). ## The Spec

**Who (v1):** admin (Sean) + paying **Crystalline** self-users + Move-Fitness onboarded clients. **Trainer→assigned-clients = v1.1.**

**The one success metric:** % of Crystalline self-loggers who create visible progress proof <7d AND get a **FULFILLED** coach-led action <30d. Sub-metrics (moat): % logs → confirmed record → proof → coach review → repeat/share/consult/paid.
**V1 IN scope:** reuse capture/parse/canonical-writer; consent + redaction + ZDR + draft-purge; review/edit/confirm gate + coach-reviewed stamp; progress-proof card; ONE coach-led CTA; inbound review-request queue (bidirectional admin console); sanitized+attributed shareable proof card; per-user quota + AI-cost telemetry; audit trail; Crystalline gate + Guardian taste-quota + Starter locked-preview; defense-in-depth assignment-recheck **seam** (no-op for self, load-bearing for v1.1).

## 3 Ways This Fails
1. **The denominator never shows up.** v1 ships but acquisition is still the gap → ~5-10 users → even the qualitative mechanism proof stalls (2 closed loops = noise, not signal); the feeder idles waiting on the Marketing Command Center. *Mitigation:* run v1 explicitly as Sean's qualitative mechanism proof; make the **sanitized+attributed share card the bridge that feeds the faucet**; keep the Marketing Command Center the parallel #1. *Residual:* if acquisition doesn't move, this stays a retention feature (Sean's accepted boundary).
2. **The loop dies on the human side.** Users tap "request review" but Sean (only coach) can't sustain <24h fulfillment, OR responses feel generic → "fulfilled" metric technically met but users don't feel coached → no repeat, no conversion. *Mitigation:* SLA + actionable queue; cap the experiment to Sean's real capacity; require the response to be a real plan/recommendation, not a canned reply. *Residual:* doesn't prove scale (Sean accepts — v1.1+).
3. **Privacy/trust break.** A share card leaks a health detail, OR redaction misses a name reaching Gemini, OR a self-user's data feels exposed → trust breach on health-adjacent/minors data = fatal for a coaching brand. *Mitigation:* `redactTranscriptPII()` + consent + ZDR + sanitized-by-default share (no health by default) + the two greenlit live fixes landing FIRST + triangle-fusion hostile review of the redaction & share-sanitization. *Residual:* demands rigorous review; the pre-work slices are the down payment.

## Absence-First Gaps (ranked by value left on the table)
1. **No revenue bridge from $24.99 self → trainer-led service.** The metric ends at "trainer service converted" but nothing in v1 defines HOW a self-logger becomes a paying coaching client — the $25/mo → $175/session chasm. *Highest money left on the table:* a defined consult→paid-plan/package path (even manual) so a fulfilled review can monetize. Without it the feeder feeds a free-ish loop.
2. **No re-engagement / streak loop driving REPEAT logging.** v1 closes the loop once; nothing brings the user back to log the next workout. Winning logging products win on habit (streaks/reminders). *Value:* repeat logging is the denominator multiplier — without it the loop fires once and dies.
3. **No sticky destination for the shared proof.** The share card routes to "Swan community/feed," but memory flags the social page as "dead." *Value:* the share-hook's acquisition conversion depends on landing somewhere engaging; a dead feed wastes the distribution mechanism.
4. **No data-rights surface (export / delete / "what did the AI see").** Rule 62 makes consent/export/deletion product surfaces; v1 has a consent gate but not the broader data-rights UX. *Value:* trust = conversion for health data; also compliance posture.
5. **No iteration lever on the CTA / proof-card framing.** The activation copy is the conversion lever with no way to A/B it. *Value:* later conversion-rate optimization.
