## H10-1 (LOW): bare pseudo-class argument *lists* — only the first id is exempt

**Locus:** `HEX_OUTSIDE_VAR`, 5th lookbehind `(?<!:(?:not|is|where|has)\(\s*)` — tuning-profiles.mjs.

**Mechanics:** the exemption proves id-ness only for the token *immediately* after `:fn(`. A continuation token — preceded by `, `, closed by `)` — satisfies branch 2 exactly (`(?<=[\w)\]]\s*|,\s*)` … `(?=\s*[;})!])`), because the pseudo-class's closing paren is in the terminator class (it's there so `linear-gradient(#f00, #00f)` flags its second color). The two heuristics collide on `, #beef)`.

**Matrix (hand-verified against the regex as written):**

| Case | Today | Should be |
|---|---|---|
| `li:is(#face, #beef) { padding: 0; }` | **RED** on `#beef` | green |
| `p:not(#cafe, #d00d) {}` | **RED** on `#d00d` | green |
| `:where(#face,\n  #beef) {}` (multiline) | **RED** on `#beef` (`,\s*` + `\s*)`) | green |
| `el.matches('li:is(#face, #beef)')` | green (4th exemption) | green ✓ |
| `querySelectorAll('#cafe, #beef')` | green (4th exemption) | green ✓ |
| `:is(#face) {}` / `:not(#cafe)` | green (5th exemption) | green ✓ |
| `linear-gradient(#f00, #00f)` | red | red ✓ |
| `color-mix(in srgb, red, #fff)` | red (final-token position) | red ✓ |

**Why this is genuine, not synthetic:** GLM's H9 certification explicitly treated "the comma-position second id" as corpus-real for `el.matches('li:is(#face, #beef)')`. The identical selector text in a CSS block (a styled-components ``css`` fragment, a diff under review in coder rows) flags. Same string, same meaning, different verdict — that's an inconsistency *inside* the H9 fix pair, not a new enumeration demand. Harm: a legitimate coder-design row gets a `hardcoded_hex_outside_var` hygiene alarm and is falsely rejected.

**Fix sketch (bounded, mirrors the H9 convention):** widen the 5th lookbehind to span the argument list, hard-bounded at the closing paren:

```
(?<!:(?:not|is|where|has)\(\s*)  →  (?<!:(?:not|is|where|has)\([^)]{0,120})
```

Safety analysis:
- **Gradients unaffected:** `linear-gradient(` never matches `:(?:not|is|where|has)\(` — `linear-gradient(#f00, …)` stays red.
- **No leakage past the list:** `[^)]` hard-stops at the first `)`. `:is(#face) { border: 1px solid #ccc; }` still flags `#ccc` (the span from `:is(` ends at the paren). `x ? ':is(#face)' : '#beef'` still flags — the `)` inside the first string bounds the span before `#beef`.
- Restores symmetry: same selector text, same verdict, quoted call or bare CSS.

**Rider, not counted separately:** `:host(#cafe)` / `:slotted(#cafe)` are bare pseudo-class id selectors outside the alternation and flag today. Mechanically true; corpus confidence low (shadow-DOM styling in these rows is speculative). Same one-line locus if the corpus ever shows it — flagging for the ledger, not as a second finding.

## Considered and declined (pre-empting H11)

- **Mid-list function colors escape** (`linear-gradient(to right, #f00, #00f)` — only `#00f` flags): the terminator whitelist exists precisely to protect bare selector lists (`a, #beef, c {}` stays safe only because `,` is *not* a terminator). Closing this opens an H4-6 regression. Deliberate H5-M4 trade-off, not an H9 defect.
- **`rgb(0 0 0 / #fff)` slash form escapes both branches:** adding `/` to branch 1's class makes `/* #fff */` comments flag. Corpus-weak, fix risky. Declined.
- **The `{0,120}` bound itself:** blessed in H9 as the accepted bounded-lookbehind convention. Not re-litigating.
- **`querySelector(("#cafe"))` double-paren, bracket-access call forms:** contrived. Declined.
