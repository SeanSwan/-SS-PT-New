# Classroom planning

1. Classify the request before using any tool or remote model.
   - Continue only when every input is public, synthetic, or a controlled term.
   - If child/family-specific content appears, stop and route to the approved
     local H0 or school-record workflow without repeating the content.
2. Read `references/contracts.md` when creating a daily card, Radar query/card,
   SwanGuard opportunity, allergy flag, or 5090/external request.
3. Use one repeated core with a small variation. Put care routines and movement
   inside the plan. Keep group participation voluntary and brief.
4. Prefer on-hand, borrow/free, and reusable materials. Hold anything lacking
   age grading, recall, condition, cleanability, or provenance evidence.
5. Accept only deterministic allergy pass/hold flags. Never request the roster.
6. Produce a print-first card readable in at most 90 seconds. Include one core
   invitation, movement, transition, care-routine focus, safety flags, and
   `used / adapted / skipped` feedback.
7. Exclude deals, voice, per-child observations, behavior plans, assessment,
   incident narratives, autonomous messages, seller contact, and purchasing.
8. Mark generated material as generated. Preserve source URLs for verified
   public material. Never pass raw merchant HTML or email into model context.
9. When offline or uncertain, simplify to a template/paper plan and say which
   verification is missing.
