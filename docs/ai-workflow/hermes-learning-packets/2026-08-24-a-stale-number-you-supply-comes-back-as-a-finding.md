## What was decided/built (Fable-tier lesson)

A blueprint for upgrading the Content Studio into a multi-project asset studio on a two-plane ComfyUI-MCP architecture, reviewed by a three-seat panel at $0.00. The architectural output matters less than the process finding: **three of the panel's blockers rested on facts I supplied rather than facts they found**, and two of those facts were wrong.

## Why (the rationale Hermes should carry forward)

A review packet is not a summary — it is the reviewer's entire sensory apparatus. Reviewers cannot open the repository. Every number in the packet is, to them, a measurement. When I wrote "`comfyuiLocal.mjs` (296 ln)" — copied from an August handoff written before a refactor — two independent senior seats built a "split it before you touch the 300-line cap" blocker on it. The file is 227 lines. Neither seat was careless; both were reasoning correctly from a corrupted input.

The inverse also held. Because my packet never named `contentStudioRoutes.mjs`, no seat could see that it stands at **659 lines** — a 2.2x violation of the same cap, and the file the first slice would have extended. **The packet's omissions shape the review as forcefully as its contents.**

And the largest single correction came from a section I never wrote at all: I described the queue in prose ("FK-coupled to SwanStudios") instead of pasting the schema. Qwen concluded multi-project was "architecturally impossible without a complete rewrite"; Ox called it "a blank cheque." Both were reasonable readings of my prose. The schema says `project_id` already exists on both the job and the asset as a nullable, unconstrained UUID, and the only hard tenancy FK is `user_id`. **The migration those two seats priced as a quarter is additive.**

## Reusable pattern / rule Hermes should apply next time

1. **Measure in-session or don't state it.** Any line count, row count, test count, latency or file size entering a packet is generated by a command run in that session. A number lifted from a handoff doc is a `[HYPOTHESIS]` wearing a `[VERIFIED]` costume.
2. **Paste the schema, don't describe it.** For any question about data model or coupling, include the actual column list. Prose about a schema produces reviews about the prose.
3. **Verify every blocker before accepting it.** Rule 30 says a reviewer's finding is a hypothesis. Five premise checks here cost about four minutes and demoted or killed four blockers while confirming the one that mattered.
4. **Read the seat's own hedges.** GLM explicitly labelled two blockers conditional and named the file that would settle each. It was right to hedge and right about which file. A reviewer that tells you what it could not check is doing higher-quality work than one that asserts uniformly — and its confidence section is a to-do list.
5. **When two independent seats converge against your ordering, they are probably right.** GLM and Ox separately argued the first slice must be the creation surface, not the diagnostic tool, both citing the project's own recorded failure pattern. I had put the diagnostic first. Reordered.

## Skills created or changed

Nothing was created. One gap identified: **Rule 56** governs broad claims about baseline cleanliness ("tsc clean", "tests pass") but is silent on *file metrics quoted into a document*. The identical failure — an unmeasured number presented as measured — walked through a door the rule does not watch. Proposing an extension rather than a new rule, because the underlying discipline is the same one.

## Mistakes I made

- **Quoted `comfyuiLocal.mjs` at 296 lines from an August handoff instead of measuring it.** It is 227. Caught only because I ran `wc -l` while checking the seats' claims — had I accepted the blocker, a pointless refactor would have led slice one. **MECHANISM:** every numeric claim entering a review packet is produced by a command visible in that session's transcript; a figure whose only source is another document is written as `[from <doc>, unverified]` or not written.
- **Described the schema in prose instead of pasting it.** This produced the single largest misdirection in the panel — one REJECT and one "blank cheque" verdict, both about a migration that is additive. **MECHANISM:** any packet question touching data model, coupling or tenancy ships the actual column list from the model file; prose about a schema is not admissible as the schema.
- **Listed `videoJobQueue.mjs` under the render-agent execution layer.** It is the BullMQ YouTube-library queue; the render path is `VideoRenderJob` + `renderAgentRoutes` + `videoRenderJobService`. Caught by opening the file. **MECHANISM:** read the docblock of every file cited in an inventory table before the table ships — filename inference is how a queue for one subsystem gets attributed to another.
- **Put the diagnostic slice first.** Two seats independently argued the creation surface must lead, citing the project's own recorded failure pattern, and they were right. Caught by the panel, not by me. **MECHANISM:** when a slice plan answers "this isn't what I pictured," slice one is the pictured thing; a plan whose first slice is a tool for the builder fails that check by construction.
- **Attempted the commit into another agent's git lock, then had to stop.** The lock was a zero-byte orphan from a crashed process with no commit behind it, but clearing another agent's lock is exactly the unilateral move Rule 67 exists to prevent. Left the work uncommitted and disclosed it. **MECHANISM:** before staging, compare `.git/index.lock` mtime against the last commit timestamp; a lock with no commit behind it is reported to Sean, never removed by the agent that did not create it.

**The entry worth reading twice:** the stale-metric error is a repeat of a documented lesson, and the write-up did not prevent it because the write-up was aimed at the wrong direction. STALE-CHECK was recorded as "re-verify a blocker *before repeating it*" — a rule about other people's claims. It did not fire on my own packet inputs, which are the same failure class. **A procedural rule that names only one direction will silently exempt the other.**

## Risks / guardrails

- The MCP/render-agent lifecycle collision is **real and unfixed**. Until write ops acquire the render lease, any diagnostic session that restarts ComfyUI can kill a live render and trigger a retry — a second charge on a hosted route.
- `contentStudioRoutes.mjs` at 659 lines is a standing violation that the next slice would have doubled down on.
- The partner-node licence gate does not exist yet. Registering hosted providers before the per-provider grant switch ships would route paid generations around the written-grant requirement.
