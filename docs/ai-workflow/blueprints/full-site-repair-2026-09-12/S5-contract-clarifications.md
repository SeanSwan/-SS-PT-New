# Realtime contract clarification — source verified 2026-09-12

S5 remains the governing contract; these details refine its implementation before that slice starts. The earlier phrase “actual ProductionTokenManager subscription” assumed an existing observer API. Source inspection shows that `services/productionTokenManager.ts` currently has only private one-shot refresh waiters, and `api.service.ts` re-exports that same class. Add a small persistent token observer API to the canonical manager, with unsubscribe, notification on successful set/clear and cross-tab storage changes where needed. Do not subscribe a socket to private HTTP-refresh promise waiters. Tests cover logout while refresh is pending: a late old-session refresh must not resurrect authentication or the socket. Preserve HTTP refresh single-flight behavior and settle waiters on every outcome. AuthContext changes handle sign-in/out; token refresh may originate in an Axios interceptor, so context token alone is insufficient.

The mounted composer is `Social/Messaging/MessageThread.tsx`; it currently clears its draft immediately and types `onSend` as void. Both hook and composer must share a confirmed result contract. Await the durable REST receipt, retain draft on failure/uncertainty, disable duplicate submits while pending, and clear only the exact submitted text in the same account/conversation. A changed draft or conversation must not be erased by a late response. Realtime echo and REST response reconcile by persisted message ID. The hook must guard all touched completion paths against account changes, not just unmount. No automatic resend on an unknown result; reconciliation/read is allowed.

Keep API timeout handling finite and explicit. Tests use synthetic messages and a local socket server, never the real production transport. Typecheck and existing safe-error tests must remain valid; no raw provider/database errors reach chat UI. This is an architecture correction based on source, not approval or completed evidence.
