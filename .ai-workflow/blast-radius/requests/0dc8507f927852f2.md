# Change request — add a 10-second timeout to the Fable gate hook

**File:** `.claude/settings.json`
**Requested by:** Opus 5, round 14 of the spend-guard hostile review
**Size of change:** one line

---

## What is wrong, in plain English

Your `.claude/settings.json` lists the little programs ("hooks") that run before
every Bash command. Three of them guard money and safety:

| Hook | Timeout |
|---|---|
| `spend-guard-gate.mjs` | 10 seconds |
| **`fable-remit-gate.mjs`** | **none set** |
| `irreversible-git-gate.mjs` | 30 seconds |

The Fable gate is the only one of the three with no time limit. That is almost
certainly an oversight when it was added — its two neighbours both set one.

## Why it matters

A timeout is what stops a stuck program from hanging your terminal. If the Fable
gate ever hangs — a slow disk, a locked file, a bug — every Bash command you run
waits for it instead of stopping after 10 seconds.

It matters slightly more for this one than for the others, because the Fable gate
is written to **fail closed**: when it errors, it blocks the command on purpose,
to protect your Fable credits. A gate that is willing to block is a gate you want
to finish quickly.

**This is not urgent and nothing is currently broken.** No hang has been observed.
It is an inconsistency I found while auditing, and I would rather ask than leave it.

## Option A — my recommendation: add `"timeout": 10`

Matches the spend-guard hook sitting directly above it.

- **Cost:** one line. If the gate ever needs longer than 10 seconds it would be
  cut off — but it only reads a small file and matches some text, so 10 seconds is
  already a hundred times more than it needs.

## Option B — leave it as is

- **Cost:** nothing today. Claude Code applies its own default (60 seconds), so
  the worst case is a 60-second stall instead of a 10-second one, in a situation
  that has never happened. The inconsistency stays for the next person to
  re-discover.

## What I will verify after the change

1. `.claude/settings.json` still parses as valid JSON (a broken settings file
   would disable *every* hook — the real risk in touching this file at all).
2. The Fable gate still refuses a first Fable call and still allows an ordinary
   command — its 37 tests, re-run.
3. No other line in the file changed, confirmed by reading the diff.
